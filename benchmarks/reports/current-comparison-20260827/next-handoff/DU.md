## Finding: allocation is not exposed
**No bundled VFS provider exposes measured allocated blocks/bytes through the current public `FileStat`/`FileSystem` contract.** `size` is present; allocation fields/methods are absent (`src/contracts/filesystem.ts:6`, `src/contracts/filesystem.ts:77`). Capabilities have extensible boolean keys, but no defined allocation semantics or quantity (`src/contracts/filesystem.ts:27`).
This proves absence of an exposed observation, not absence of backing allocation or provider knowledge. Missing allocation is **unknown, never zero**. Extra host objects/transport metadata or arbitrary custom-provider extensions do not establish a portable contract.

## Proposed first profile: explicit apparent bytes only
These are handoff choices, **not implemented flags/APIs or approved requirements**; integration/command owners must accept them before implementation.
- Require explicit apparent-size selection; reject bare/default allocated mode with a clear unsupported-mode explanation, rather than silently replacing GNU `du` semantics. Label emitted totals/help as **VFS apparent bytes**, never disk blocks, physical usage or GNU parity. Default units within this explicit profile: bytes, no per-entry rounding.
- Count regular files by validated `FileStat.size`. Recommended directory own contribution: **zero by declared profile policy** on every backend, including Real; recurse into visible children. This is not a claim that directory storage is zero. Alternative owner choice: sum reported directory sizes, explicitly backend-dependent and not directly comparable across Memory/remote/Real.
- Recommended final-symlink contribution: its reported `lstat.size`, without traversing its target. Real stored target text can differ from virtual `readlink` text (`src/fs/real/index.ts:77`); do not recompute a supposedly uniform size from the latter. An alternative zero-symlink policy must receive a different explicit profile label.
- Start with operand summaries (default operand `.`), independent accounting per operand; overlapping operands may repeat counts across summaries. Prefer deterministic child order and escaped path output. No combined unique-storage total is implied.
- Deduplicate regular files within each operand only with complete, valid `(identityScope, dev, ino)` equality; compare scope by reference, not serialization. Count unknown identities per encountered path and disclose `unknown identities counted by path`; do not claim complete hardlink dedup. Never infer identity from size, ETag, path, client object, bare inode or `nlink`/capability flags (`src/contracts/filesystem.md:100`, `src/fs/mount/identity.ts:3`).
- A later bounded comparison fallback may use existing public `compareEntry`, preserving errors/unknown/conflicts; it compares **followed** entries, so cannot deduplicate no-follow symlink objects (`src/contracts/filesystem.md:160`). Avoid unbounded pairwise remote queries. Do not add private authority imports or serialized identity tokens.
- Use VFS `lstat`/`readdir`; intermediate links and trailing-directory syntax still obey the adapter's resolver. Initially reject follow-all/follow-operand options rather than promising unsupported traversal semantics. If later enabled, explicitly choose target-only versus link-plus-target contribution and ancestor-cycle handling.
- Maintain bounded active traversal state; check canonical-path/known-identity ancestor repetitions, report suspected cycles, and retain depth/node limits when identity is unknown. Per-resolution 40-link limits are **not** recursive-walk cycle protection (`src/fs/memory/index.ts:194`, `src/fs/real/index.ts:194`, `src/fs/mount/index.ts:251`, `src/fs/overlay/index.ts:261`). Never globally prune directory subtrees merely because backing directory identities match: mount injection/overlay composition can change children.
- Traverse the supplied visible mount namespace by default, including configured remote mounts. Do not inspect private backing layers or escape configured roots. Reject one-filesystem/mount-exclusion options initially: no public mount-boundary enumeration exists, and bare `dev`/missing identity cannot implement them truthfully (`src/contracts/filesystem.ts:77`). Mount link resolution also enforces backend boundaries, not unrestricted cross-mount following (`src/fs/mount/index.ts:225`, `src/fs/mount/index.ts:250`).
- Remote traversal uses only existing explicitly configured transports/authorization; metadata calls may incur requests/costs. Do not enable networking, read contents, download bodies to measure size, or invent snapshot consistency. Listings/stats and identity are observation-time values subject to concurrent change (`src/contracts/filesystem.md:154`).
- Preserve typed filesystem error meaning and virtual path diagnostics; missing/unreadable/unsupported entries must not become zero successes. Recommended first policy: fail the affected operand, mark/suppress its incomplete total, continue independent operands, final nonzero status. Abort stops all operands, including errno-shaped abort reasons; never claim completion for a canceled walk.
- Pass the invocation signal into every VFS/comparison operation; check it between traversal steps and before awaited byte-sink writes (`src/contracts/filesystem.ts:40`, `src/contracts/command.ts:22`). Bound command-owned depth, entries, operations, identity memory, concurrency and output; reject invalid/unsafe sizes and avoid numeric-sum overflow. Exhaustion is explicit failure, not silent truncation.
- `readdir` returns a materialized array, not a bounded iterator (`src/contracts/filesystem.ts:85`): post-return command limits cannot guarantee provider allocation/request limits. S3 has separate listing limits (`src/fs/s3/filesystem.ts:283`). No command-layer promise of forcibly canceling uncooperative host work.
- Read-only command intent is not blanket zero backend effects: Overlay `readdir` enters `run` with garbage cleanup enabled, which can remove prior staging garbage without the invocation signal (`src/fs/overlay/index.ts:145`, `src/fs/overlay/index.ts:360`, `src/fs/overlay/index.ts:534`). Owner decision needed for a strict metadata-only/no-write profile; do not patch or bypass it here.

## Future allocated mode: optional semantic design only
- **Not requested now:** a minimal future optional per-entry allocation observation (allocated bytes, or count plus explicit byte unit), bound to the same stat/path/backing entry and observation. Absence/unsupported/unknown is distinct from measured zero; invalid or denied observations remain errors. A boolean capability alone is insufficient; choose exact types/precision with the contract owner later.
- Define storage/accounting policy: provider-reported charged allocation versus exclusive/reclaimable physical bytes, treatment of directory/link metadata and shared extents, observation freshness and authority. Do not mix unlike policies in one unqualified aggregate. Define whether unknown entries fail allocated mode or yield labeled partial totals; no logical-size fallback.
- Real may expose genuine host-reported allocation only within its configured root, under host authorization and documented units/platform semantics. Sparse, compressed, reflink/shared, snapshot and deduplicated storage make logical rounding invalid and exclusive physical consumption uncertain; a reported per-inode allocation does not prove bytes reclaimable on deletion. Do not infer physical allocation from size or preferred I/O block size.
- S3/WebDAV remain unknown unless an explicitly trusted provider extension supplies authorized, correctly bound allocation semantics; content length, ETag, quota, billing classes, replica assumptions and mock buffer length are not substitutes. Do not add credentials or provider lookups implicitly.
- Mount/read-only/overlay snapshot allowlists would need owner-approved propagation; preserve selected backing provenance and per-path support, not wrapper-created authority. Synthetic directories remain unknown unless an explicit policy says otherwise; overlays must not sum invisible layers or retain stale allocation after copy-up. Remapped/cache views omit or replace changed assertions. Existing wrappers currently drop such undeclared fields.
