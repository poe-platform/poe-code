# GitHub workflow generator follows a symlinked output file and overwrites outside the repository

## Summary

The GitHub workflow generator writes committed output files beneath `.github/workflows` without rejecting symlinks at those paths. A repository containing a symlinked generated workflow can make normal workflow generation overwrite an arbitrary external file.

## Reproduction

1. From the repository root, run this disposable replica probe:

   ```sh
   probe=$(mktemp -d /tmp/poe-gh-workflow-probe.XXXXXX)
   mkdir -p "$probe/repo/packages/github-workflows" "$probe/repo/.github/workflows"
   cp -R packages/github-workflows/scripts packages/github-workflows/src \
     "$probe/repo/packages/github-workflows/"
   ln -s "$PWD/node_modules" "$probe/repo/node_modules"
   printf 'EXTERNAL ORIGINAL\n' > "$probe/outside.yml"
   ln -s "$probe/outside.yml" \
     "$probe/repo/.github/workflows/gh-fix-vulnerabilities.yml"

   "$PWD/node_modules/.bin/tsx" \
     "$probe/repo/packages/github-workflows/scripts/generate-gh-workflows.ts"

   realpath "$probe/repo/.github/workflows/gh-fix-vulnerabilities.yml"
   sed -n '1,6p' "$probe/outside.yml"
   ```

## Observed Behavior

The generated workflow path resolves to the external `outside.yml` target, which is overwritten with content beginning with `# Generated by: packages/github-workflows/scripts/generate-gh-workflows.ts` and the generated `Fix Vulnerabilities` workflow document.

`packages/github-workflows/scripts/generate-gh-workflows.ts:20` derives each fixed output path beneath `.github/workflows`, then writes it with `writeFileSync(outputPath, content)` at line 60 without verifying canonical containment or rejecting symlinked output files.

## Expected Behavior

Workflow generation should write only canonical generated workflow files inside the selected repository. It should reject a generated output file that resolves outside `.github/workflows` through a symbolic link.

## Impact

A crafted checkout can turn the normal workflow-generation or workflow-lint preparation step into an external file overwrite with developer or CI privileges. The apparent output remains a legitimate generated GitHub workflow path, obscuring the actual modified location.
