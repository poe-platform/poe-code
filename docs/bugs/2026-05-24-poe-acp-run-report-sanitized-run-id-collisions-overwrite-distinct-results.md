# Poe ACP run report sanitized run-id collisions overwrite distinct results

## Summary

`@poe-code/poe-acp-client` creates persisted report filenames from a millisecond timestamp plus a lossy sanitized `runId`. Distinct run identifiers that differ only in punctuation, such as `run/a` and `run?a`, normalize to the same basename; if they are saved within the same millisecond, the second report silently overwrites both files produced for the first run.

## Reproduction

Add the following temporary probe as `packages/poe-acp-client/src/__probe__.test.ts`:

```ts
import { createFsFromVolume, Volume } from "memfs";
import { describe, expect, it } from "vitest";
import { saveRunReport, type RunReport } from "./run-report.js";

describe("run report filename normalization", () => {
  it("lets distinct run ids overwrite the same timestamped report files", async () => {
    const volume = new Volume();
    const fs = createFsFromVolume(volume).promises;
    const now = () => new Date("2026-05-24T12:34:56.789Z");
    const createReport = (runId: string, exitStatus: RunReport["exitStatus"]): RunReport => ({
      runId,
      startTime: now().toISOString(),
      endTime: now().toISOString(),
      exitStatus,
      toolCalls: [],
      usage: { used: 0, size: 0, updates: 0 },
      errors: []
    });

    const first = await saveRunReport(createReport("run/a", "success"), { fs, homeDir: "/home", now });
    const second = await saveRunReport(createReport("run?a", "failed"), { fs, homeDir: "/home", now });
    const saved = JSON.parse(await fs.readFile(first.jsonPath, "utf8"));
    console.log(JSON.stringify({ first, second, savedRunId: saved.runId, savedStatus: saved.exitStatus }));
    expect(second.jsonPath).toBe(first.jsonPath);
    expect(saved).toMatchObject({ runId: "run?a", exitStatus: "failed" });
  });
});
```

Run the probe and then remove it:

```sh
./node_modules/.bin/vitest run packages/poe-acp-client/src/__probe__.test.ts --reporter verbose
rm -f packages/poe-acp-client/src/__probe__.test.ts
```

The reproduction passes and shows both reports resolving to the same files, which contain only the later result:

```text

✓ packages/poe-acp-client/src/__probe__.test.ts > run report filename normalization > lets distinct run ids overwrite the same timestamped report files
```

## Observed Behavior

`saveRunReport()` computes one basename from `toTimestampForFileName(now())` and `toSafeFileSegment(report.runId)`, then writes JSON and text files without collision handling. `toSafeFileSegment()` replaces every unsupported character with `-`, so `run/a` and `run?a` both become `run-a`. At the supplied identical timestamp, the second save targets exactly the first report's paths and replaces its successful result with the failed run's data.

## Expected Behavior

Persisting two distinct run reports must not silently overwrite either report, including when their identifiers contain characters unsafe for filenames or they finish during the same millisecond. The stored filename should include a collision-resistant representation or use exclusive creation with disambiguation.

## Impact

Concurrent or rapidly completed ACP runs can erase audit evidence, diagnostics, usage details, and success/failure outcomes for earlier runs. Identifiers generated by external agents or services need only collide after filename sanitization for this loss to occur, making report retention unreliable under normal parallel execution.
