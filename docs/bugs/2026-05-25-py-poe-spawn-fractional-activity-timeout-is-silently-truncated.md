# Python Poe spawn fractional activity timeout is silently truncated

## Summary

The public `py-poe-spawn` wrapper accepts a fractional `activity_timeout_ms` value even though its API documents an integer timeout and its validation error says the value must be a positive integer. Instead of rejecting `1.9`, it silently applies `int(...)` and launches `poe-code` with `--activity-timeout-ms 1`, changing the caller's requested inactivity limit without a diagnostic.

## Reproduction

Run this disposable Python probe from the repository root. It patches process startup only to observe the command arguments generated by the public `spawn.pretty(...)` API:

```sh
cat > /tmp/py_poe_spawn_fractional_timeout_probe.py <<'PY'
from unittest.mock import patch
from poe_spawn._spawn import spawn

class FakeProcess:
    def __init__(self):
        self.stdout = None

    def wait(self):
        return 0

calls = []

def fake_popen(command, **kwargs):
    calls.append(command)
    return FakeProcess()

with patch("poe_spawn._spawn._resolve_cli_command", return_value=["poe-code"]), patch(
    "poe_spawn._spawn.subprocess.Popen", side_effect=fake_popen
):
    result = spawn.pretty("codex", "probe", activity_timeout_ms=1.9)

print({"exit_code": result.exit_code, "command": calls[0]})
assert calls[0][calls[0].index("--activity-timeout-ms") + 1] == "1"
PY
PYTHONPATH=packages/py-poe-spawn/src python3 /tmp/py_poe_spawn_fractional_timeout_probe.py
rm -f /tmp/py_poe_spawn_fractional_timeout_probe.py
```

The probe succeeds and prints:

```text
{'exit_code': 0, 'command': ['poe-code', '--yes', 'spawn', '--activity-timeout-ms', '1', 'codex', 'probe']}
```

## Observed Behavior

`spawn(...)` and `spawn.pretty(...)` expose `activity_timeout_ms: Optional[int]` and the README documents `activity_timeout_ms: int | None`. In `_build_spawn_command()`, the wrapper executes `timeout = int(activity_timeout_ms)` before checking only `timeout <= 0`. Python therefore changes `1.9` into `1`, passes validation, and forwards a materially shorter timeout to the CLI. The invoked CLI itself validates `--activity-timeout-ms` as a positive integer, but it never sees the invalid original SDK input because the Python wrapper has already coerced it.

## Expected Behavior

The Python wrapper should reject values that are not positive integers before building the child command, matching its documented API and the CLI's integer validation contract. It should not silently round or truncate invalid timeout input into a different operational setting.

## Impact

Python consumers calculating timeouts dynamically can accidentally launch agents with shorter inactivity limits than requested, causing premature cancellation and retries that are difficult to diagnose. Because execution begins successfully with a sanitized argument, callers receive no indication that their configuration was malformed or altered at the SDK boundary.
