# SDK runRalph drops per-plan run log routing

## Summary

`@poe-code/ralph` computes a dedicated run-log directory and filename for each plan iteration and passes them through its `runAgent` contract. The public SDK's default Ralph bridge drops `logDir` and `logFileName` before invoking `spawn.autonomous()`, so normal SDK/CLI-backed Ralph runs do not write their agent output to Ralph's intended per-plan log location.

## Reproduction

## Observed Behavior

`runRalph()` computes `runLogDir` with `resolveRunLogDir()` at `packages/ralph/src/run/ralph.ts:41` through `packages/ralph/src/run/ralph.ts:47`, then supplies both `logDir` and a generated `logFileName` to its agent executor at `packages/ralph/src/run/ralph.ts:87` through `packages/ralph/src/run/ralph.ts:107`. The public SDK bridge receives that `AgentRunInput`, whose type exposes the log fields at `packages/ralph/src/types.ts:24` through `packages/ralph/src/types.ts:43`, but its `sdkSpawn.autonomous()` call at `src/sdk/ralph.ts:38` through `src/sdk/ralph.ts:56` omits them. Agent-spawn supports those fields as log routing controls at `packages/agent-spawn/src/types.ts:83` through `packages/agent-spawn/src/types.ts:93`, so the omission prevents Ralph's selected destination from reaching the logger.

## Expected Behavior

The public Ralph SDK bridge should forward the `logDir` and `logFileName` supplied by Ralph so each plan's agent output is persisted under its configured Ralph run-log directory.

## Impact

Normal Ralph runs invoked through the public SDK or CLI can lose the plan-scoped run-log organization generated by Ralph, placing output in generic/default logging locations or omitting expected files. This makes plan-specific debugging, auditing, replay, and iteration history harder to locate or incomplete.
