# csvsql implementation validation

Reference source archive SHA-256: `147318a8dbaec07c0bbb9291c14b78de5fa32ed3d4a5c2396e52a83c0a30df6b`. Its CSVSQL source was compared byte-for-byte with the oracle installation before captures. Reference cases and runtime versions are retained in `csvsql-reference.json`, using the existing frozen CPython 3.14.2 / Agate 1.14.2 / Agate-SQL 0.7.3 / SQLAlchemy 2.0.54 / C locale / UTC profile. Original reference artifacts were preserved.

The native captures are research evidence only. Canonical tests never launch Python or csvkit. Schema/validation comparisons use in-memory inputs and memfs. SQLite comparisons inject a fast Node builtin in-memory database: no host database file, subprocess, network or service. The test-only adapter preserves integer versus float cells and explicitly supplies the frozen SQLAlchemy exception-reporting profile. This measures the engine's output and transactional effects, not native DBAPI/SQLAlchemy driver interchangeability.

Failing original cases reproduced status-78 database execution before implementation. Further failing regressions reproduced missing inferred dialect DDL, literal containers, input-budget separation, query-file probing, Unicode identifiers, oversized integer arithmetic, source text-length ordering and empty identifiers, zero-batch lazy compilation and constraint-error precedence. A separate agent reproduced cancellation races during pending begin/commit/reflection and fixed them through registered admitted-work cleanup. Independent failing cases also reproduced and fixed separate DROP/CREATE reflection, skipped-DDL compilation and unique-column validation when CREATE is skipped. See `docs/plans/csvsql-qa.md` and `docs/plans/csvsql-stress-qa.md` for procedures.

Qualification remains bounded: no non-SQLite INSERT driver profile or deployed external database has been measured; binary result cells, remaining literal syntax/diagnostic cases, batch failure reporting without a qualified executemany binding and verbose tracebacks without frozen frames are explicit blockers. Passing injected SQLite cases does not promote these cases to passes. No README additions, commits, pushes or releases were authorized or performed.

Focused verification on 2026-09-18: the maintained csvkit unit route passed 3,499 tests across 65 files; its one existing skip and six existing todos remain unqualified. The final csvsql-focused route passed 49 cases, including all 33 native reference observations. Safe Bash command plus independent stress tests passed 91 cases; the maintained integration-inventory script passed 109 cases. Narrow workspace builds, csvkit lint, Safe Bash source/test/consumer typechecking and repository-wide lint passed. An ad hoc screenshot of registered query CSV and SQLite DDL was inspected for readable, complete output; temporary rendering artifacts are not canonical tests. 

The broad unit gate did not pass: it reproduced a 5,000ms timeout in docx text-command.test.ts. A complete docx workspace attempt also failed four timeout cases (comment extensions, package-view resources, section model and workflow behavior). Subsequent one-worker and 512 MiB heap attempts still timed out in different cases, including image replacement and table behavior. Isolated successes do not qualify the broad gate. A synchronous-hashing test experiment did not eliminate these failures and was removed; docx tests and the shared worker configuration remain unchanged. These failures remain an explicit delivery blocker, with no increased timeout, removed assertion or claimed full npm test pass.
