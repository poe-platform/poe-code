# Independent DBF scalar and memo user validation

Ten frozen native observations are stored in in2csv-dbf-user-stress-reference.json with exact stdout/stderr/status, base64 DBF and DBT fixtures, argv, profile, versions and unchanged-file effects. Reference tooling used hash-required CPython 3.14.2, csvkit 2.2.0, Agate 1.14.2, agate-dbf 0.2.4, dbfread 2.0.7 and SQLAlchemy 2.0.54 with LC_ALL/LANG=C and TZ=UTC.

The first actual-Shell regression run reproduced three failures (seven passing controls): textual memo indexes incorrectly accepted bytes 0xa0 and 0x85 as Unicode whitespace and read memo `hello`; a date component incorrectly accepted byte 0xa0 and emitted `0200-10-01`. Native returns exact ValueError diagnostics, empty stdout and status 1 in all three. The field codec now requires ASCII bytes for each date component and textual memo integer conversion, preserving four-byte binary memo pointers.

Canonical tests in packages/safe-bash/tests/commands/in2csv-dbf-user-stress.test.ts use MemoryFileSystem and in-memory bytes, with no disk creation, native programs, network, databases or LLMs. They compare exact output/status and unchanged DBF/DBT bytes and directory entries. Final run: ten passes, zero failures/skips/TODOs. The selected maintained uncached csvkit build closure passed; focused ESLint for the codec and test passed. Root records broader maintained build/test/lint and screenshot results separately.

This cohort additionally validates file-separator bytes are rejected in numeric/float/memo conversions, star padding preserves integer-versus-float inference, underscores remain legal numeric integer syntax, and negative memo indexes become null. It does not qualify all codepages, corrupt overlapping/backward layouts, exotic floats/timestamps, huge memo seek offsets, compressed sources, service-backed filesystems or concurrent mutation. No commits, pushes, publishing or README edits were performed. Root owns cleanup of the reference environment and out/dbf-user-scalar.
