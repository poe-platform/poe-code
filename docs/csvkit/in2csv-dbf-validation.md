# DBF milestone validation

The domain implementation preserves the original executables and uses the existing safe-bash family adapter. The frozen source audit and 100 original differential cases are in in2csv-dbf-reference.json; additional native scalar observations and independent Shell stress are in in2csv-dbf-stress-reference.json and in2csv-dbf-stress-validation.md. The active profile is CPython 3.14.2 with the exact dependency lock, C locale, UTC and UTF-8 reference environment. The corpus's PYTHONIOENCODING environment is explicitly injected into canonical tests rather than silently changing the product default.

Original regressions failed before fixes: illegal logical values became null, deleted invalid records were skipped, record count zero hid a real active row, and DBT memo fields returned an unsupported diagnostic. Independent stress reproduced early-year date and native Decimal inference failures. Broader domain tests reproduced a lowercase scientific exponent where Agate emits uppercase; native Number casting now preserves Decimal formatting. A resource-bound regression reproduced huge positive DB3 offsets silently becoming empty memos; the reader now returns status 78 for offsets outside the exact integer range. Decoded codepoint admission was also reproduced and fixed before CSV output.

Final filename reference observations used the same frozen environment and the first corpus fixture: `-f dbf missing.dbf` and `-e bogus -f dbf missing.dbf` both return status 1, empty stdout, and `FileNotFoundError: [Errno 2] No such file or directory: 'missing.dbf'\n`; `-e bogus input.dbf` returns status 1, empty stdout and `LookupError: unknown encoding: bogus\n`. These were reproduced in failing canonical memfs tests before implementing exact opening/encoding ordering. The text handle is never decoded, and stdin remains unsupported.

Domain tests cover the corpus, unchanged memfs input/companion bytes and absence of created files, SDK/argv parity, and admission bounds. Single-byte driver tests compare every byte of 21 injected codec mappings to frozen CPython, including undefined-byte Unicode errors. Independently authored actual-Shell tests cover native value identities, a corrupt FPT pointer, producer reuse, awaited output and delayed cooperative cancellation cleanup.

The scoped safe-bash integration membership test explicitly registers tests/commands/in2csv-dbf-stress.test.ts. Selected maintained builds include the complete declared safe-bash dependency closure, without cache shortcuts. The domain maintained test/lint and focused safe-bash tests/lint are run; existing skipped/TODO domain cases are excluded from compatibility claims. Root's repository-wide test/lint routes were not run for this focused milestone.

Final results: maintained `npm test --workspace=@poe-code/csvkit` passed 3,079 tests across 56 files, with one skipped and six TODO cases remaining explicitly unqualified. The DBF file contributed 107 passing regressions and the codepage qualification added one all-byte test. Maintained domain lint (ESLint plus source/test TypeScript) passed. Selected maintained `npm run build:workspaces -- --workspace=@poe-platform/safe-bash` passed all ten declared dependency-closure build stages and the normal safe-bash postbuild. Focused canonical node:test invocation of csvkit.test.ts, in2csv-stress.test.ts, in2csv-output-ownership.test.ts and in2csv-dbf-stress.test.ts passed all 27 tests. Maintained integration-inputs.test.mjs passed all 109 assertions/tests; focused ESLint and Git whitespace checks passed. These are scoped results, not a repository-wide gate.

Ad hoc screenshot QA used the built safe-bash Shell and injected MemoryFileSystem/codecs through the maintained screenshot renderer. The inspected PNG displayed the exact CSV header `value`, then rows `third` and `first`, confirming physical order and deletion omission. Root poe-code's bash command does not expose csvkit's required host bindings, so this screenshot uses an explicit plugin host instead of inventing a root CLI flag. Temporary screenshot, oracle environment, native fixtures and logs are removed after evidence reduction.

Full-suite compatibility is not claimed. The exact unqualified cases and status-78 boundaries are listed in docs/specs/in2csv-dbf.md. No README additions, staging, commits, pushes or publication are authorized or performed.
