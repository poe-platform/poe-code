# JSON/NDJSON user edge validation

The user pass reproduced and fixed one product bug. A JSON string ending in a bare backslash incorrectly reported `Invalid \\escape` at the backslash. Released csvkit 2.2.0 reports `Unterminated string starting at` at the opening quote. Five original-executable cases failed before the fix; the decoder now distinguishes an absent escaped character from an invalid escaped character. The shared engine serves CLI and SDK; no product subprocess, ambient capability or fallback was added.

`in2csv-json-user-edge-reference.json` freezes 75 original executable observations. Cases 0–41 cover malformed structures, numbers, escapes, Unicode and astral-character diagnostic offsets; 42–69 cover native numeric Text spelling including signed/scaled zero, exponents, Decimal precision and non-finite constants; 70–74 reproduce the fixed bug. The artifact records the existing dependency hash lock, verified CPython executable hash, csvkit source hash and exact minimal capture environment. Reference programs run only during disposable capture; canonical tests use memory inputs and the saved observations.

A different agent independently checked actual registered safe-bash tools. Its 49 passing tests cover frozen roots/value shapes, literal keys, ignored flags, nulls, physical lines, six codec observations, repeated one-byte producer buffers, named virtual-file preservation and consumer cancellation. The five new malformed string observations are exercised through JSON and NDJSON and through both stdin and named memory files. Writes serialize and consumer closure preserves the reason, stops output and drains registered cleanup without aborting the caller.

Maintained uncached verification passed the selected csvkit workspace build and its office-package dependency closure, csvkit package unit route (51 files; 2,851 passed, one skipped, six TODOs), and csvkit package lint (ESLint, production and test TypeScript). The other focused safe-bash JSON review, user-edge, stress and output-ownership files passed 135 tests. The independent 49-test file also passed ESLint. Skipped/TODO cases are not compatibility passes.

The maintained safe-bash typecheck passed source/test checks and 26 current consumer groups, with expected negative-consumer rejection. Integration-input declaration checks passed all 109 tests. These checks establish neither runtime acceptance of every consumer nor full repository/release qualification.

The actual safe-bash output was captured with the repository screenshot utility and visually inspected: full integer precision, Boolean rendering, ordered union, missing cells, quoted commas, corrected string-start diagnostics and blank-line NDJSON failure were visible. Temporary capture scripts, venv, logs and screenshot are purged after verification; unrelated evidence is preserved.

Nested serialization remains unresolved: the request requires serialization without flattening while the released Agate source and frozen originals flatten. This user pass retains the existing measured behavior and does not claim that requirement is implemented. Missing warning deployment provenance, unpaired-surrogate output, unmeasured locales/encodings and other explicit unsupported profiles in `docs/specs/in2csv-json.md` remain blockers. No complete-suite or release qualification is claimed. No README, staging, commit, push or publication changes were made.
