# Independent workbook format-section validation

The separate stress worker reproduced all four existing frozen style regressions before changing code: a later `[h]` format section incorrectly changed a cached numeric date into an elapsed duration in argv, SDK and side-file output. The frozen openpyxl 3.1.5 `is_timedelta_format` implementation splits at the first semicolon before inspecting elapsed tokens. The JavaScript engine now follows that same first-section rule.

The additional `in2csv-workbook-section-reference.json` corpus contains ten workbook styles and two native invocations. Capture authenticated the CPython 3.14.2 executable hash and all nineteen runtime distribution versions against the existing frozen csvkit 2.2.0 profile, with C/UTC/UTF-8/80x24 capture settings. This rechecked executable/version identity rather than reinstalling or reauthenticating installed-file manifests. The corpus independently covers later `[h]`, `[hh]:mm`, `[m]` and `[s]` sections; elapsed first sections; uppercase elapsed formats; numeric first sections; and quoted/escaped elapsed tokens. Native openpyxl's elapsed classifier still recognizes quoted and escaped elapsed tokens within its first section, so the implementation preserves that measured behavior.

Restoring only the worker's elapsed-classifier line to the original implementation produced eight failing exact-output observations: four existing style cases and four new section argv/SDK cases, including emitted side-file bytes. No canonical test creates files or executes native programs; inputs and effects use memfs. After restoring the correction, focused green verification is reported to root for integration qualification.

The reader's declared `NumberFormat` type also permits numeric built-in IDs. The engine resolves those IDs through SheetJS's exported `SSF.get_table()` before classifying raw cache types, which fixes the concrete maintained TypeScript failure without casting. An independent JavaScript reader inspection of the section fixture with `cellNF: true` emitted only string formats. Numeric IDs are an unmeasured reader-API path and are not included in the native compatibility denominator. Arbitrary malformed format grammar, exhaustive calendar/rounding ranges and broader workbook gaps listed in `in2csv-workbook-validation.md` remain explicit blockers. Source review also identified an unvalidated malformed-unused-worksheet gap: the ISO metadata helper parses every worksheet before selection, whereas native read-only worksheet cell iteration is lazy.
