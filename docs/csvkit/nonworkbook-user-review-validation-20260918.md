# Independent non-workbook user review

The independent reviewer used the actual safe-bash Shell with the csvkit command registration, rather than calling a command implementation stub. Reference measurements authenticated the frozen CPython 3.14.2 executable SHA-256 `3d6400b63b150164e89a690d9813af8b0eb420af9f336ef1f6c5102c6da60eae` and all 19 locked runtime distribution versions. Native reference subprocesses used only `LC_ALL=C`, `LANG=C`, `TZ=UTC`, `PYTHONIOENCODING=utf-8`, `COLUMNS=80` and `LINES=24`, with non-TTY pipes.

The measured differential grid comprised 195 csvcut/csvgrep/csvformat/csvstack cases and 140 additional csvformat/csvcut/csvclean cases. **315 of 335 matched exact stdout/stderr/status. The remaining 20 are explicit compatibility blockers:** input quoting modes 4 and 5 return product status 78 rather than native results. These existing refusals were already covered by maintained canonical tests and were not silently converted into passes or fixed through lossy string coercion. For example, `csvcut -u 4` with unquoted header `a,b` reports native `ValueError: could not convert string to float: 'a'`, while mode 5 successfully parses cells that the product currently refuses. Supporting those modes requires the reader/command typed-cell contract, not merely enabling their parser flags.

The grid covered empty and blank input, missing/duplicate/singleton headers, short/surplus records, reordered/repeated selectors, no-header mode, physical line numbering of multiline fields, mixed CR/LF, empty quoted and falsey text, Unicode whitespace, astral delimiter/quote characters, NUL and Unicode separators, malformed/unclosed quoted fields, non-strict suffixes after quotes, output modes 4/5, escape and doublequote options, custom line terminators, ASV, and csvclean joining/filling/normalization. This focused grid does not establish complete csvkit parity; workbook, SQL/database, interactive and other existing service/profile blockers remain outside its scope.

The frozen reference reduces 48 representative observations into `nonworkbook-user-review-reference.json`. Every canonical case runs twice: with a reused three-byte input buffer and empty fragments, and with virtual input/output redirection. All **48 tests / 96 Shell invocations pass** exact byte/stdout/stderr/status assertions and virtual-file/namespace effect checks. UTF-8 and CRLF split boundaries preserve producer-owned input semantics. The first test execution failed only because the newly authored namespace assertion expected string names instead of the filesystem's typed directory entries; correcting that setup left every product observation unchanged.

No product source change was justified by a new failing observation. No README, Git staging/commit/push or release changes were made. The maintained `npm run lint:eslint` completed with status 0: 15,933 configured subjects linted, zero errors and two warnings in unrelated docx tests (`packages/docx/src/operation-types.test.ts:20` and `packages/safe-bash/tests/commands/docx/table-model.test.ts:22`). The new review test has no diagnostics. Root records the maintained runner/build/typecheck/export-consumer checks separately. The QA procedure is `docs/plans/csvkit-nonworkbook-user-review-qa.md`.
