## Original failures and fixes

- All 24 raw connected CREATE comparisons initially failed because the implementation stripped SQLAlchemy's leading newline and two trailing newlines. Connected effects now preserve these bytes, while schema-only stdout retains stripped CREATE text and `;\n`.
- Three independent original shell regressions exposed binary64 conversion in Agate MaxPrecision: `1e309`, `1e400` and `-1e400` must be skipped before Decimal normalization, retaining scale 2 from another value. Finite `1e308` and underflowing `1e-400` controls prevent an overly broad skip rule.
- Fifteen original cross-dialect corpus cases exposed MSSQL multipart schema grammar. A declarative provider flag now selects SQLAlchemy's bracket-aware scanner; other dialects retain whole-name schema quoting. The independent agent separately reproduced 12 MSSQL failures, including embedded newlines, odd brackets and empty schema elements.
- The empty schema model originally emitted an extra tab/blank line inside CREATE parentheses. Public compilation now matches SQLAlchemy's exact empty-column output. csvsql still skips empty input tables.
- A regression caught while separating derivation and compilation diagnosed unconstrained MySQL VARCHAR before an empty table identifier. Compilation now preserves the source's identifier-before-type-error order.
- A synthetic optional-profile regression reproduced an ignored `typedTypes.Text` override. Text now resolves the legacy `textType` override, the declarative typed map, then generic metadata consistently during derivation and compilation. This validates port behavior, not a third-party dialect's native compatibility.

SQLAlchemy's frozen Boolean defaults generate no CHECK constraints or generated constraint names. UNIQUE constraints are unnamed, deduplicated in first-occurrence order and emitted after columns. Minimum/multiplier behavior remains confined to connected creation; schema-only ignores the options exactly as the source does.

## Explicit blockers

The synthetic optional profile proves only injection/routing, not third-party interoperability. Real non-SQLite drivers/services, non-SQLite INSERT bindings, uninstalled ingres/crate/external dialect profiles, other CPython/SQLAlchemy profiles and exhaustive manually constructed SQLAlchemy schema combinations remain unqualified. Core schema-only CLI choices do not silently widen when a host supplies optional connected metadata.

The existing csvkit workspace suite also retains one skipped non-string-reader quoting observation and six TODO stdout-encoding profile divergences. Those are blockers, never passes; this SQL change does not claim complete csvkit parity.
