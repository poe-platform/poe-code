# Independent workbook reader qualification

The independent worker measured the released csvkit 2.2.0 engine with CPython 3.14.2, Agate 1.14.2, agate-excel 0.4.2, openpyxl 3.1.5, xlrd 2.0.2 and SQLAlchemy 2.0.54 from the existing frozen uv deployment. Native capture used locale C and timezone UTC. Workbook generation and native executions were research activities, excluded from canonical tests. The csvkit release/source identity remains the root frozen reference profile; this focused audit did not reinstall or reauthenticate every reference dependency.

`workbook-stress-reference.json` freezes 42 argv observations with binary workbook inputs, stdout, stderr and status. The canonical `in2csv-workbook-stress.test.ts` executes all 42 through the actual safe-bash Shell, injected memory filesystem and csvkit command registration. It additionally verifies original workbook bytes remain unchanged and no unexpected files appear. Canonical tests create no host files and invoke no Python, network or native programs. Warning source paths are explicit injected deployment metadata, never ambient path discovery.

The worker first reproduced eight failing XLSX header/calendar/time/duration cases before changing the adapter. Later differential expansions reproduced two mixed BIFF date/text failures, four ISO date/header failures, one BIFF5 encoding-override failure and two fractional-day rollover failures. The sparse-cell token `last` independently reproduced one shared temporal-inference failure; root authored its fix and source regression. These are 18 distinct argv observations with failing product evidence, not 18 distinct implementation defects. Earlier failed helper imports and a TypeScript NumberFormat typing error were implementation/verification errors, excluded from the compatibility failure denominator.

Measured coverage includes cached numeric/date/error formula values, absent formula caches without recalculation, serial zero in date/time styles, Excel's fictitious leap day, date1900/date1904, negative serials and fractional-day rollover, millisecond fractions, elapsed duration styles, XLS raw serial/boolean/numeric headings and numeric error codes, mixed XLS date/text columns, BIFF5 cp1252/latin1/cp437 overrides, ISO cells with General styles and ISO date-only headings, sparse/trailing styled cells, merged headers/cells, duplicate/missing headings and exact injected warnings, hidden sheets and active/default selection. Dedicated malformed-dimension fixtures separately cover reported A1 automatic reset, explicit A1 reset, truncated A1:B1 default interpretation and explicit reset.

The adapter uses the tested public `@e965/xlsx@0.20.3` raw/cache reader APIs and public ESM codepage-table export. Explicit BIFF encoding override rewrites only parsed CODEPAGE records in an owned raw workbook stream because the library otherwise lets the existing record supersede its codepage option. Native ISO lexical provenance comes from root's parsed namespace/relationship helper rather than reconstructed formatted display strings. Native ISO dates and datetimes remain distinguishable in headings. Neither a workbook host process nor recalculation is introduced.

Final independent checks: the maintained uncached csvkit build closure passed. All 42 actual Shell workbook cases passed, zero skipped/TODO. A csvkit lint run passed before the final codepage-import/rollover adjustments; root owns the refreshed final maintained lint/typecheck/full integration verification. This corpus is focused reader evidence, not qualification of the entire csvkit suite or every native workbook structure.

The earlier 36-case package rerun above remains historical evidence for its smaller corpus.

Additional ad hoc actual Shell stress replayed all 42 frozen reader observations through stdin as reused 127-byte views. The producer overwrote its backing buffer before every yield and filled it with `0xff` on finalization. Exact stdout/stderr/status matched every observation; every producer finalized once and the memory filesystem remained empty. This replay created no host files and invoked no native/network capability. It corroborates byte ownership and workbook stdin caching for this corpus, rather than qualifying arbitrary asynchronous host mutation or opaque reader allocations.

Root then captured a dedicated native millisecond-tie workbook in `in2csv-workbook-rounding-reference.json` using its hash-locked frozen deployment. The two failures are separate argv observations outside the 42-case original reader denominator. Root owns the domain regression and reader fix; the independent worker owns the Shell regression and its follow-up verification.

After root's reader fix and rebuilt package were available, the independent worker reran all three actual Shell workbook files with Node test concurrency one and the maintained concise reporter: all 74 cases passed, zero failures/cancellations/skips/TODO. The two new rounding observations now match exact stdout/stderr/status and complete side-file bytes; both preserve source workbook bytes. The focused runner completed in 18.28 seconds while other workspace work was active; this timing is not a performance qualification. The package's maintained `scripts/test.mjs` discovers the whole active suite and has no focused file filter, so this check used its underlying Node/tsx runner against the three explicit workbook paths. Root owns the broad maintained workspace runner, integration-input inventory registration and lint/typecheck qualification.

The root-supplied `in2csv-workbook-style-reference.json` then independently reproduced two more actual Shell failures. Styles `b1`, `b2` and `0;mm` wrongly converted raw `45200.5` caches into `2023-10-01 12:00:00`; native openpyxl leaves these numeric. Ordinary stdout and `--write-sheets` stdout/side-file bytes both differed. The existing rounding regression file now loops both frozen corpora and derives the source filename from each argv. Its first expanded run passed the two rounding observations and failed the two style observations, with no skips/TODO. These new observations are outside the original 42-case denominator. Root owns the date-style parser fix.

Remaining explicit blockers include unmeasured/encrypted BIFF versions and OLE stream structures; BIFF8 legacy-byte metadata with encoding overrides; encoding aliases outside the declared small mapping; all unsupported/unmeasured native reader diagnostics; unusual style grammar where SheetJS SSF date detection differs from openpyxl; every calendar range/millisecond tie and arbitrary ISO duration/timezone/malformed lexical form; native ZIP/XML encodings outside root's UTF-8 XML helper profile; and broader raw XLS column-type combinations not represented here. Unsupported or unmeasured cases are not passes. The byte/ZIP/work/cache bounds constrain admitted input and retained host-owned data, while the synchronous opaque reader provides no internal per-object allocation accounting or preemption guarantee. Registered cooperative cleanup/backpressure tests elsewhere remain required; this corpus does not independently establish those guarantees.
