# DOCX whole API resumption evidence

Acceptance remains blocked. The [current register](whole-api-resumption.json)
reconciles all 1,337 public rows to observed exports and typed operation schemas.
It preserves 920 source records, 262 enum values, 2,259 source cases, twelve guides
and eleven workflow rows. Structural presence is not a passing behavior claim.
No complete public row or full guide-heading coverage is newly accepted.

All 33 exports missing at the earlier audit are now present. The earlier
[snapshot](whole-api-acceptance.json) remains historical evidence. Current
observations include inherited members, returned views, helpers, enums and public
underscore types; an unobserved descriptor is not automatically private or
unsupported. Type protocols and returned fields require further exact evidence.

The original `guide-whole-api-workflows.test.ts` executes thirteen paired small
workflows through public model exports, SDK typed batches and the actual CLI
engine, with independent semantic assertions after save/reload. Eleven correspond
to the registered guide workflows; omitted table cells and bounded XML removal
are supplemental. CLI checks compare JSON dry-run results/effects and reload
binary publication, check unchanged input and empty stderr. Five original raster
cases cover PNG, GIF, BMP, JPEG and TIFF through model insertion. All package bytes
live in memfs; time and author are explicit. These finite tests do not adapt all
source cases or qualify every guide heading, language variant or security edge.

Three corrections were reproduced with original failing tests before code:
typed enum transport assignments rejected valid orientation/start_type values;
selected XML-root removal deleted a paragraph then threw stale-handle errors;
empty and nested-table-only cells passed semantic validation. Further original
red tests established required-body/final-cell-paragraph rollback and admitted
wrapped terminal paragraphs. Minimal package-domain corrections use existing
schemas, model transactions and compatibility projection validation.

`NumberingPart.new()` remains unsupported: the pinned source raises
`NotImplementedError`, and JS throws `UnsupportedEditError` with `unsupported-edit`.
The map's earlier creation promise was documentation drift. This public member
remains in the denominator and blocks full acceptance.

Additional gaps remain explicit: direct paragraph alignment resets accept null,
but the typed setter schema does not; the public Paragraph.element getter has no
matching typed getter schema. The equivalent bounded XML removal workflow does
not close that getter gap. The later [async capability record](async-capabilities.md) qualifies save
with staged ByteSink, compatible ArchiveSink and explicit VfsPath output forms.
It supersedes the earlier sink-only observation without promoting whole-API
acceptance. Actual VFS admission uses matching
string capability tokens and an explicit binaryResolver; the proposed capability
object and fonts/template context forms have not been fully reconciled. Explicit
VFS output authority is now qualified by the scoped async record.
Save is asynchronous publication; the old map's “No publication” statement was
incorrect. Required contracts are retained alongside actual observations.

The shared CLI/SDK contracts continue to require plural resources, preserving
text replace, common selectors/flags/JSON/exit statuses and schema/capabilities.
Typed bounded batch routes supply the workflow CLI evidence. Neutral model
spellings, synchronous admitted access, always-async I/O, owned bytes, canonical
enum values and bounded XML views replace source-language/runtime mechanics.
No ambient host I/O, native runtime, callbacks or implicit network are admitted.

Verification receipts are recorded in the JSON register and owned
[QA plan](../plans/docx-whole-api-resumption.md). Independent code review passed
29 focused cases. Later packaging, renderer and other task gates stay pending.
