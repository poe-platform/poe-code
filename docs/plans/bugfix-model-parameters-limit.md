# Parameter-view limits

## Scope and contract

Change only `src/cli/commands/models.ts`,
`src/cli/commands/models-command.test.ts`, and this plan. Parameterless models
must not consume the parameters view's explicit or default model limit or its
truncation count. Preserve the global filter banner's meaning (for example,
`3/4 models` means three models match global filters, before parameter
eligibility), generic empty and since-empty messages, and all other views.

## Sequence

1. Add memfs-backed public-command regressions with mocked HTTP: newer
   parameterless models, older eligible models, explicit/default limits,
   footer counts, global filters, empty states, and other-view controls.
2. Run the new cases against unchanged production code and record failures.
3. Move parameter eligibility and its empty message after the global banner
   and generic empty checks, before sorting, counting, and slicing. Assign
   eligibility back to `filtered` and render that array directly.
4. Run focused models and full related tests, type checking, scoped lint,
   and diff checks; record results.

No new dependencies, helpers, inline comments, README edits, commits, or
pushes. Tests use memfs and injected HTTP mocks, not real network or LLMs.

and generic empty checks, before sorting, match counting, and limiting.

renders 50 eligible models with an eligible-only total. Other views retain
parameterless models, and global/empty messages retain their original meaning.
