## Validated defect and scope

The existing unrelated, untracked `packages/safe-js/src/interp/globals/iso-month-name-completeness.test.ts` was neither edited nor adopted into the commit. Its SHA-256 is `71bfb95fec05d6f26985504621bb04ec516caf021cbb3984606d1c8a63093ada`. Reproduction: `npx vitest run packages/safe-js/src/interp/globals/iso-month-name-completeness.test.ts` returned 6 failures / 12 passes: long standalone months and month ranges in en-US, pl-PL and ru-RU. Native Intl returned empty strings/parts too, despite resolving `calendar: iso8601, month: long`. Native Gregorian formatting supplied February/luty/февраль and correctly sourced range parts. This is a host Intl data/pattern defect, not a missing host authority grant.

The published target remains ECMA-262 edition 16 and ECMA-402 edition 12 (June 2025), with existing separately pinned Temporal extensions. [ECMA-402 FormatDateTimePattern](https://402.ecma-international.org/12.0/#sec-formatdatetimepattern) emits a part for each month placeholder; month names are implementation/locale/calendar dependent, with numeric fallback when no localized representation exists. It does not standardize the literal spellings asserted by the exploratory test. [CLDR calendar metadata](https://github.com/unicode-org/cldr/blob/main/common/bcp47/calendar.xml) identifies ISO as Gregorian with ISO calendar week rules. Thus using this same host's Gregorian standalone month data is a valid bounded recovery; blanket substitution of ISO calendar behavior is not justified.

The new adapter first executes the original formatter, preserving its input validation and errors. It changes only an empty string/empty parts array whose resolved ISO formatter contains `month: long` as its sole component. It preserves native locale, numbering system, timezone, strings, literals and range source labels. It does not change the original formatter state or `resolvedOptions().calendar`. Complete host output and unqualified empty patterns pass through unchanged. Temporal plain inputs retain their ISO reference date without timezone shifting; Instant inputs retain their actual epoch including negative submillisecond values. No guest capability, budget, timeout, assertion, global intrinsic or runtime support setting changes.
