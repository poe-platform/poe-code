# Independent csvsql SQL schema stress QA

This procedure covers the safe-bash command binding and injected database effects of the SQL schema work. It does not certify all csvkit executables, external drivers, third-party entry-point dialects or real databases.

1. Read root/scoped instructions and preserve unrelated edits and staging. Assign SQL implementation/integration ownership to root and independent shell regression ownership to another agent.
2. Verify available reference against `docs/csvkit/reference-profile.json`: CPython 3.14.2, csvkit 2.2.0, agate-sql 0.7.3 and SQLAlchemy 2.0.54. Capture argv/input/output using fresh `TextIOWrapper(BytesIO(...))` stdin so the csvkit input closure/reconfiguration contract remains meaningful. Do not use Python as a product fallback.
3. Exercise MSSQL multipart schema parsing with dots, multiple database components, odd brackets, empty bracket components and interior LF, including exact IndexError for `a..`. Confirm other dialects quote dotted schemas as one identifier. Exercise schema qualification and reserved, Unicode and numeric identifiers for generic plus the captured shipped order mssql/mysql/oracle/postgresql/sqlite. Compare complete stdout/stderr/status, including commas, tabs and final newline.
4. Exercise number precision, temporal representations, DateTime nullable exceptions, nullable text, duplicate UNIQUE columns, missing constraints, no-constraints mysql compilation failure and mysql 21844/21845 Unicode code-point text threshold.
5. Reproduce the MaxPrecision binary64 overflow defect with `n\n1e309\n2.34\n`, `1e400` and `-1e400`; require the original failing shell assertions before fixing schema derivation. Reference scale is 2, because Agate checks math.isnan/math.isinf before normalizing each Decimal.
6. Use an explicitly injected recording mysql database session. Confirm schema-only ignores minimum length/multiplier while connected creation uses them. Compare exact untrimmed SQLAlchemy CREATE TABLE string and begin/result-close/commit/session-close effects. No native program/database/network runs in canonical tests.
7. Verify actual Shell/registry optional compiler admission: absent metadata produces status 78/rollback/close; explicitly supplied synthetic CUSTOM_TEXT metadata produces exact raw DDL/commit/close. Confirm injected metadata cannot extend frozen schema-only `-i` choices. Run `TSX_DISABLE_CACHE=1 node --import tsx --test packages/safe-bash/tests/commands/csvsql-schema-stress.test.ts` after the maintained csvkit workspace build. Root registers this test's exact literal path in safe-bash integration discovery and owns build/typecheck/lint checks. Expand checks only as required by integration scope.
8. Inspect the CLI screenshot using the maintained screenshot command when root validates changed CLI output/help. Screenshots are ad hoc evidence, not new screenshot tests.
9. Record measured results in `docs/csvkit/sql-schema-stress-validation.md`; keep logs/screenshots/capture scripts in `out` and purge only evidence created for this task after use. Unavailable capabilities and unmeasured cases remain explicit blockers. Do not commit/push/publish.
