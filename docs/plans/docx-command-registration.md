## Contract boundary

The current SDK exposes bounded package, ZIP/XML, validation, publication and
location primitives. It does not yet expose the document model or command parser.
Registration therefore requires an explicit trusted engine; this milestone does
not supply a built-in operation interpreter. The adapter forwards literal owned
argument bytes and explicit shell I/O/cancellation capabilities. The engine uses
the SDK and owns the future common Office grammar and result semantics.

The public API research inventory remains at 920 records, including inherited
and returned types and documented underscore-prefixed types, with 23 recorded
documentation resolutions. Registration promotes none of those model rows.
The existing exact language/security decisions remain authoritative: async
admission/publication; owned Uint8Array bytes; supplied VFS/time/metrics;
zero-based sequence access versus keyed lookup; null as documented inheritance;
neutral snake_case model names; camelCase operation options; no host evaluation.
In particular comment_id/timestamp, table_direction, typed errors, and bounded
XML/package views retain their reconciled meanings. No model alias or exclusion
is introduced here.

## Verification procedure

1. Run new original tests before implementation and record the observed failures.
2. Dispatch through actual Shell/registry instances. Verify absence from both
   default aggregates, opt-in registration, refused collisions, deliberate
   replacement, literal arguments, stream bytes and cleanup/cancellation.
3. Exercise existing package SDK behavior through an injected engine using
   original in-memory data. Mutating unit fixtures use memfs.
4. Inspect actual ZIP/XML exports, build with maintained workspace routes and
   verify the npm package's runtime, declarations, legal notices and closure.
   Test browser/worker conditions before declaring those conditions available.
5. Run maintained checks for the changed scope, review the exact owned diff,
   then commit only explicit owned paths on main. Do not push or release.

Packed/browser QA uses an invocation-owned temporary directory. Pack the built
root tarball, extract it, and inspect the actual DOCX runtime/declarations/legal
files and absence of QA fixture directories. Run original archive create/write/
read plus opt-in Shell dispatch, collision and replacement through public imports.
Typecheck a strict NodeNext consumer with `skipLibCheck:false`, no path aliases
and no private workspace dependencies. Bundle the packed public imports with the
browser condition and reject every external import. Execute the result in Chrome
and a module Worker, then inspect a screenshot of the observed dispatch results.
The workerd runtime is unavailable and no explicit workerd condition is added.
