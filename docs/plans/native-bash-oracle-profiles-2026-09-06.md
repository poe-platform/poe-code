# Native Bash oracle profiles: brace expansion and printf assignment

## Validated failure

The maintained root gate exposed 13 failures in
`packages/safe-bash/tests/shell/brace-expansion-differential.test.ts` and nine in
`packages/safe-bash/tests/shell/printf-variable.test.ts`. Independent focused
replays reproduced 48/61 and 73/82 passes respectively, without skips.
Both files hardcoded `/bin/bash`, which is GNU Bash 3.2.57(1)-release on this Mac.

The brace failures require stepped ranges or zero padding: this oracle prints
`{1..5..2}` literally and expands `{01..03}` as `1 2 3`. The printf failures
cover empty-format publication, readonly refusal status and indexed lvalues:
Bash 3 retains old values for empty formats, reports scalar readonly refusal
with status zero, and rejects indexed printf targets.

These are not grounds to remove product functionality. The authoritative
`bugfix-637-brace-expansion.md` and `bugfix-636-printf-variable.md` plans explicitly
require the current semantics and record successful original comparisons against
GNU Bash 5.0.17. Historical results remain historical; no fresh Bash 5 comparison
was obtained in this local repair.

## Narrow test repair and expectation provenance

Keep every original source string and all existing portable assertions. Add
independent fixed product assertions for the 13 brace and nine printf cases.
Their modern native comparisons become separate subtests, explicitly unavailable
when `/bin/bash` reports a major version below 5. The remaining live native
comparisons continue on the installed oracle. Version-probe errors, signals,
malformed versions, and supported-oracle failures remain test failures.

Brace number/alphabet expectations follow the original plan's signed-step,
zero-step, decimal-padding and ASCII ordering requirements; the existing
`brace-expansion.test.ts` independently asserts stepped and padded outputs.
For `{Y..c..3}`, stepping ASCII values 89 through 99 by three selects Y,
backslash, underscore and b. The plan's lexical replay contract removes the
generated backslash while quoting its next character. Dollar becomes literal;
an escaped opening quote becomes literal and the unmatched closing quote is
removed; a doubled backslash leaves one backslash. Consequently the quoted
`$value` variant exposes unquoted x/y fields after its literal opening quote.
ANSI-C translation precedes replay, retaining byte FF after a literal quote.
These six suffix expectations are explicitly contract-derived, not copied native
captures. A Bash 3 primitive control confirmed generated-backslash removal in
bare `{Z..a}`; suffixed unstepped controls also generate a backtick and fail, so
they do not provide independent full suffix-output qualification.

Printf expectations follow the original plan's empty/partial publication,
readonly status 1, index-zero replacement, local restoration and supported
0..2147483647 index rules. BOM/UTF-8 expected bytes also match the existing
independent browser-decoder test. No expected value is generated by the product
implementation under test.
