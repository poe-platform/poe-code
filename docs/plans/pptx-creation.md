Implement only the requested creation increment from `docs/specs/pptx.md`, with
the shared office CLI/SDK contracts. Do not execute the full pipeline. Preserve
unrelated work, including the preexisting pipeline-plan edit and untracked
research. No README edits, product host I/O/network/native runtime, push or release.

## Ownership

- Creation worker: creation domain, original tests and public exports in
  `packages/pptx`.
- Adapter worker: command engine/schema and safe-bash adapter with original
  paired SDK/CLI tests; substantive adapter work is delegated under its scoped rules.
- Independent reviewer: read-only format and behavior review, concrete findings
  and independent reopening evidence.
- Root: coverage reconciliation, draft usage, integration verification and local
  commits of explicitly named owned files.

## Acceptance and agent QA procedure

1. Reproduce absent creation through failing original tests before implementation.
2. Author a deterministic Transitional presentation graph with one blank layout,
   master and theme. Default to zero slides, 12192000 by 6858000 EMUs and pptx.
   Verify potx and ppsx main content types separately and a structured one-slide
   case with original text. No copied default templates or assets.
3. Independently unpack generated bytes into memfs, parse XML with an independent
   parser and assert required content types, relationship targets, IDs, ordering,
   sizes, text, metadata and macro absence. Test explicit dates and omission of
   time/author; never read the clock to generate authored metadata.
4. Exercise the same behavior through the SDK engine and actual virtual CLI,
   including schema, capabilities, JSON, dry-run, output protection and errors.
   Inspect help/error screenshots; keep screenshots disposable.
5. Consult the manifest before corpus QA. Creation from original inputs needs
   no publisher assets; any template experiment must verify listed cache hashes,
   preserve input bytes and reduce meaningful findings into original regressions.
6. Run maintained focused package tests/lint and selected workspace build closure.
   Run adapter checks appropriate to changed scope. Inspect all failures and
   independently review authored XML validity before the local commit.
7. Reconcile relevant parameter variants, BDD examples and public API obligations
   in a research supplement. Keep model functionality outside this increment as
   visible gaps; never infer API coverage from archive inspection alone.
8. Commit coherent improvements on main with Conventional Commit messages,
   named owned paths and this receipt. Report local hashes separately; do not push.
