## Agent QA procedure

1. Parse both inventories and the new JSON register. Compare IDs as sets, check
   uniqueness and counts, verify aliases and all collection contracts. Verify
   source/document hashes against the explicitly named pinned research checkout
   without importing or executing its code.
2. Inspect signatures and argument defaults, including chart builders, media/OLE,
   dates, units, RGB, nullable setters, placeholder replacement, creating getters,
   and the D01–D15 drift decisions. Check bounded XML/package view destinations.
3. Check every callable/property route has closed typed arguments and an explicit
   operation ID; common actions retain plural resources and `text replace`.
   Confirm enum/type discovery routes and original test obligations remain visible.
4. Use the maintained formatting route, scoped to owned Markdown/JSON files.
   Parse TypeScript signature fragments in memory; inspect syntax diagnostics.
   Check local links, JSON references, staged paths and whitespace. This task
   changes no runtime or CLI visuals, so product tests and screenshots do not
   establish useful evidence here.
5. Preserve the input audit/inventory bytes. Do not delete downloaded publisher
   documents, clone binaries or fixtures. Future QA must reduce meaningful cases
   to small original in-memory tests before cleanup; neither collection nor this
   register is a passing product test.
6. Stage only the new map, its companion evidence and this plan. Commit the atomic
   documentation improvement with a Conventional Commit. Report the local hash;
   do not push or release.
