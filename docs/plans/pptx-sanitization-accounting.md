# PPTX sanitization accounting and disposable QA

## Ownership and scope

The accounting worker owns only this plan, `docs/pptx/sanitization-evidence.md`
and `docs/pptx/sanitization-case-map.json`. Domain and command workers own their
assigned implementation/tests. The coordinator owns integration, maintained
checks, local commits and the final receipt. No push, release, whole pipeline,
README change, native runtime or product network access is authorized here.

## Accounting procedure and result

Read root instructions, F47–F56 in the format contract, the shared office CLI/SDK
contracts, both pinned audits and both inventories. Reconcile existing notes,
legacy/modern comments, properties/tags, links, opaque objects and relationship
receipts. Preserve original source row identities and expanded variants only in
research. Resolve each receipt back to an exact inventory row; reject ambiguous
or missing identities during ledger construction.

The resulting union has 341 unit variants, 117 expanded BDD examples and 179
public API records. Each row points to the existing detailed original-case or API
receipt; none is promoted to full parity by the sanitization operation. API
inherited members, underscore-prefixed public types, enums and live collections
remain obligations. No source implementation or fixture is copied.

## Disposable QA procedure

1. Use only paths recorded in `docs/pptx/corpus-manifest.json`; all 14 paths were
   present when inspected. Verify SHA-256 before the selected product operation.
2. Use `WWL-template-1slide.pptx` for one notes part and visible slide numbering;
   `CERN-job-opp-250925.pptx` for six external relationships and seven click links;
   `20120418_Jedlovec_SuomiNPP.pptx` for two opaque embeddings and eight notes parts.
   `data-visualization-course.pptx` offers eight embeddings plus 24 chart parts to
   distinguish embedded-object cleanup from chart-workbook destruction.
3. Admit bytes explicitly, sanitize a single selected category in memory, inspect
   returned removals and retained-content report, and independently compare ZIP
   member names, relationship edges and unchanged member bytes. Do not activate,
   recurse into, render with a native application or download embedded targets.
4. Verify unrelated slide formatting and chart workbook bytes remain unchanged.
   A no-match input is an empty-selection case unless explicitly allowed.
5. Reduce any meaningful finding to a small original in-memory regression before
   changing code. Modern comments/shared relationships/signatures require original
   fixtures because this corpus census does not establish their presence.
6. Keep downloaded fixtures and outputs ignored and disposable. Do not commit or
   delete unrelated files. Record executed QA independently from these candidates.

## Verification responsibilities

The coordinator runs selected maintained workspace build/test/lint routes and
focused public safe-bash tests after implementation. Commands and executable
schema must expose the same explicit policy and common publication contract.
Review a disposable CLI screenshot if output/help changes. Validate all local
research JSON references and test-file paths. Commit explicitly owned files with
relevant plans only after those checks pass; report local hashes independently.
