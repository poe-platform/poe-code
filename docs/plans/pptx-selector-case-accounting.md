## JavaScript and security mappings

- J01: model spellings `slide_id`, `shape_id`, `name`, `get`, `get_by_name`, and `index` remain neutral documented spellings. Operation JSON uses camelCase; CLI uses kebab-case.
- J02: model handles are live and owner-bound. Replacing an object invalidates its prior handle with `InvalidHandleError`; cross-document assignment requires explicit import. CLI reads cannot invoke creating getters.
- J03: model sequences are checked zero-based collections with length and iteration. CLI positions are one-based; JSON positions must declare their coordinate system. Model `Slides.get` can return its explicit fallback/null on a miss, whereas command selection fails `missing-selection`; these are separate contracts. `.at()` on slides, shapes, layouts and masters retains documented negative from-end lookup; command ordinals reject negatives. Model shape/group iteration follows immediate owner membership, while named command selection traverses nested children in depth-first XML order. No blanket slide/shape slicing is promised. Sparse slide-placeholder `idx` is a key, not ordinal position.
- J06/J08: explicit admitted bytes and capabilities only; no ambient host, network, native runtime, clock or implicit coercion. Package fingerprint is SHA-256 of admitted bytes, independent of filename or image compatibility metadata.
- Token payload is canonical `{fingerprint,scope,owner,objectId,coordinateSystem:"identity"}` with canonical part URI owner. Input-snapshot token validation differs from later-batch positional resolution against the evolving model. Token and simple selection cannot mix; all-cardinality cannot widen owner scope.
- Duplicate names produce bounded ambiguity candidates unless all is explicit. Duplicate shape IDs on different slides are legal and must remain owner-scoped; duplicate slide IDs or duplicate IDs within one drawing owner must not select the first match. Numeric strings are shape names when supplied as names.
