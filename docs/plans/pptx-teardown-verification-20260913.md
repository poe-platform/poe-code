# PPTX teardown verification

Scope: audit the current PPTX work and retained evidence. Do not execute the
implementation pipeline, alter unrelated work, push or publish.

## Procedure

1. Record local HEAD, index and existing worktree changes. Read the pipeline,
   register, checkpoint, corpus and public acceptance receipts.
2. Parse every upstream case pointer; compare identity, file, line and revision.
   Verify unique destinations, API identity coverage and feature/command joins.
3. Inspect known reference identities in package source, comments, test names,
   authored fixtures, built outputs and adapter files. Retain standalone notices;
   absence of branding is not evidence of original authorship.
4. Run maintained package tests, lint/type checks and selected workspace build
   closure. Exercise the command-family tests and a built public SDK consumer.
   Separate dirty-tree execution from committed-source inspection.
5. Rehash retained manifest downloads. Review paired CLI, regression reduction,
   independent rendering/playback and cleanup evidence without promoting designs.
6. Record failed or unverified acceptance gates. Leave preexisting task-state
   edits untouched and do not advance Implemented Through. Stage only this plan
   and the two new teardown receipt files; inspect the index and commit locally
   with normal hooks and no co-author trailer.
