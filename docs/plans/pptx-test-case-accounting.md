# Presentation case accounting and verification

Scope: documentation/evidence on main. Preserve existing edits and untracked
research. No product implementation, whole-pipeline execution, README changes,
reference runtime, network, binary cleanup, push or release.

## Work and agent QA procedure

1. Read root/scoped instructions, the presentation spec, shared CLI/SDK contracts,
   both presentation inventories/audits, the counterpart package/XML/image audit,
   the current API/command maps and corpus manifest. Keep source identities only
   in research and standalone notices.
2. Compare the complete collected unit and BDD identities with the API map's
   candidate groups. Retain every variant, including those with no candidates.
   Assign a neutral stable original-case obligation and implementation task;
   never represent a reserved ID as a specified or passing test.
3. Verify the explicit temporary checkouts against their recorded commits and
   tracked source trees. Compare all recorded API source/document hashes and
   all retained execution/failure artifact hashes before reusing the baseline.
   Only reproduce the documented isolated environment if those checks require it;
   retain failed attempts and dependency resolution without patching source.
4. Recover actual BDD scenario headings, example fields and expanded steps from
   the pinned feature files. Check each expanded row against its inventory
   location and step count. Keep source text in research under the MIT notice.
5. Specify reviewed original regressions with concrete inputs and outcomes.
   Retain parameter boundaries and observable behavior, replacing source assets,
   wording and mock/class identities. Leave unreviewed semantics explicit; public
   behavior cannot become architecture-only because it is difficult.
6. Retain counterpart OPC/image/shared XML obligations separately and keep every
   target API record linked to its original acceptance IDs, including APIs without
   source tests. Do not count mixed API record kinds as a coverage percentage.
7. Parse the ledger, check exact identity sets and unique IDs, resolve inventory
   and API pointers, verify source/example lines and task IDs, check input hashes,
   and confirm all execution/implementation flags remain false. Validate concrete
   regression designs against the pinned source bodies/fixtures.
8. Run the maintained installed Prettier formatter on the explicitly owned JSON
   and Markdown paths, followed by its scoped check and `git diff --check`.
   Review local links and legal-notice bytes. Product unit tests and CLI screenshot
   runs do not apply because no runtime or visual behavior changes.
9. Stage only the ledger, companion research notes, standalone notice and this
   plan. Inspect staged paths and commit the atomic documentation improvement.
   Report the local hash separately; do not push or release. Preserve the existing
   modification to the larger pipeline plan without staging it.

## Results

- Full presentation source accounting: 2,700 unit variants and 973 BDD examples.
  Prior candidate groups omit 875 unit variants and 307 BDD examples.
- Seventy reviewed original designs: 12 image-format metadata cases, five density
  cases, four sizing cases and 49 expanded navigation examples. All require
  original TypeScript implementation and passing evidence.
- The remaining 3,603 presentation semantics remain explicitly unreviewed.
  `map-every-upstream-case` stays open; no implementation task was started.
- Retained 391 counterpart package/image/shared XML obligations without assuming
  cross-format equivalence. Both full inventories were read as JSON.
- Retained all 2,424 API targets and their planned original acceptance IDs;
  1,072 rows have no prior class/workflow candidate. No public type is excluded
  for underscore spelling, and no numerical API-conformance claim is made.
- Both pinned checkout identities and clean tracked research trees verified.
  All 155 API source/document hashes and all 12 retained execution artifacts match.
  Initial collection and subsequent setup failures remain recorded; no suite rerun.
- No corpus bytes, downloaded fixtures, product source, README or unrelated work
  changed. Corpus QA and regression reduction remain unrun implementation work.
