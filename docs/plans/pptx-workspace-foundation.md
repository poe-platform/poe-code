## Decisions and evidence

The existing ZIP reader imports shell contracts, scheduler, archive diagnostics
and the compression codec; that codec imports `pako` and shell diagnostics. XML
parsing is owned by safe-fs. Their extraction and preservation work belongs to the
separate codec milestone in the architecture review. No runtime import of these
modules is introduced. Existing safe-bash byte sources are async-iterable, whereas
the SDK's declared source is pull-based; no cast or proxy layer substitutes for
that transport difference. Original byte admission does not duplicate a codec.

The package is exactly `pptx`, private, ESM and dependency-free. Source emits strict
NodeNext declarations with unchecked-index and exact-optional checks; no Node
ambient types are needed by runtime source. Root's wildcard workspace/test
discovery requires no implementation change. A narrow npm lock update records
the package and workspace link. The project MIT license is standalone; no source
code or assets from the reference implementation were derived in this milestone.
Required existing research notices remain untouched.

Read APIs snapshot direct input before yielding, copy producer chunks before the
next read, bound empty reads and probe exact byte ceilings. Explicit VFS opening
is delegated to an injected trusted root-scoped capability. Output snapshots the
input, awaits isolated chunk writes and captures close intent before host work.
The caller owns source cleanup; callbacks cooperate with signals. There is no
implicit I/O or ambient discovery. Raw sink transfer is not validated publication;
partial bytes cannot be rolled back. No graph, archive, time, font, CLI or document
factory behavior is claimed.

The original tests first failed because runtime exports did not exist. Subsequent
red/green regressions caught null limit fallback, completion intent changing
during a host callback, and a read-only option being accepted on output. Expected
byte arrays, error codes, write ordering and memfs contents are independent of
production serializers. No unit test creates host files or downloads fixtures.

`OperationRequest` and `OfficeResult` are type-only common contract blocks, with
literal operation IDs supplied by future closed operation definitions. They do
not form a dynamic dispatcher. Failed prepublication results require null data,
zero affected and nonempty errors. Advanced partial publication and the exact
operation registries remain unimplemented. Neutral method names, inherited API,
enums and underscore-prefixed returned interfaces remain future obligations.

The J06 byte mapping now has a concrete pull transport with an optional signal
argument, unchanged null EOF semantics and always-async return types. VFS has an
explicit read capability only. There is no `OfficeContext`, model `Presentation`
or save implementation yet; `ByteContext` deliberately describes only transport.
This resolves the foundational protocol without overwriting the exact model map.
Existing documentation corrections (return types, collection protocols, enum
spelling and creating getters) are retained as research obligations.
