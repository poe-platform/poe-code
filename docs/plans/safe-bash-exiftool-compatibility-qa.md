# Independent ExifTool compatibility QA

This is an opt-in Markdown execution plan, not a product script or unit-test oracle. Use [the pinned contract](safe-bash-exiftool-research.md). Native research tools do not become product dependencies. No universal compatibility claim follows from the fresh PNG cells.

1. Download only the pinned archive into repository `out`; verify its exact SHA256 before extraction/execution. Confirm 13.59. Disable ambient code loading using `-config ''` as the first option and clear Perl module-loading environment overrides. Record exact argv, source hash, fixture hash, stdout/stderr bytes and status; never normalize whitespace, exponent spelling, JSON escapes or warnings.
2. Reconstruct fresh PNG fixture from the documented chunk payloads/CRC rules; separately create the post-IDAT warning variant. Execute every fresh table row and compare exact streams/status. Rebuild the 20 scalar CRC-correct fixtures; run ordinary JSON, JSONQ and s3. Keep s3 sanitization distinct from stored-value evidence. Preserve lexical numeric output instead of parsing through JS Number.
3. Reconstruct XMP Alt/Bag/Seq/structured fixtures with explicit namespaces, x-default and language alternatives; cross `-j`, `-struct`, `-sep`, requested groups, `-n`/`#`, singleton/multi-item/missing values. Capture independent expected bytes before using these as implementation acceptance controls.
4. Execute the format/tag matrix per format, reader and writer independently. Include both TIFF endians, JPEG EXIF/XMP/IPTC collisions, PNG text compression/encoding, WebP payload preservation and HTML charset/entity duplicates. Test OOXML extraction on DOCX, PPTX and XLSX separately; capture exact native write refusal on all three, with unchanged input and no new backup/output. Office editing is not an admitted native-parity extension.
5. On fresh PNG copies, capture every supplied assignment/deletion/shift/subtraction control. Check unknown chunks and IHDR/IDAT/IEND byte identity, backup bytes, existing sentinel and output collision. On an explicitly configured native research filesystem, compare inode/hardlink effects for default, overwrite and in-place; record platform/filesystem limitations. Repeat against an explicit memory VFS for product acceptance; missing faithful identity capabilities must produce an explicit refusal.
6. Build a valid minimal PDF in memory with catalog/pages/page and Info Title/Author. Calculate xref offsets from actual bytes, then hash it. Do not claim the supplied 421-byte hash unless all original bytes match. Independently capture successive edits, delete, restore, repeated restore and corrupt suffix. Check original prefix, retained secret bytes, no reported deleted tags and exact restoration. Capture full warning/error streams. PDF deletion must never be presented as redaction.
7. Capture date/charset controls with explicit policies: EXIF/XMP/PDF dates, subsecond/offset/no-offset/invalid values, UTF-8/Latin-1/UTF-16 and malformed byte sequences. No host timezone/stat/account data may silently enter product results. Stage unsupported directives explicitly.
8. Capture multi-file success/error/condition statuses, CSV union-header retention, JSON SourceFile-specific/default imports, empty JSON versus CSV fields, duplicate group/member collisions and execute/stay-open ready identifiers. Bound native research batches externally; product batches are invocation-local without file polling. Verify explicit rejection of native expression/config features.
9. Separately run TDD implementation tests with memory VFS and mocked capabilities. Cover cancellation at acquisition/read/write/publication, awaited cleanup/backpressure, owned byte copies, shared budgets, realm/brand/replay invariants and malformed resource inputs. These tests are not independent native compatibility controls.
10. Before integration claims, use maintained workspace builds/lint/tests and isolated packed consumers of the root/contracts/command subpaths. Verify no bare private runtime/declaration imports, one canonical brand/error owner, Shell byte argv and identical CLI/SDK results. Verify each advertised runtime profile independently. Do not publish the private command package. Any authorized push must be verified on remote main and its release monitored separately.

Record each cell as fresh-pass, supplied-reference, pending, intentionally-excluded or product-not-implemented. Unsupported format/tag/write cells stay visible. Keep independent controls outside implementation test generation; do not weaken assertions, hide failures or increase timeouts. Purge temporary captures under `out` after recording reviewable findings in the research document.
