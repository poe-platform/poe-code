The input filename is an option, not a second positional operand. Omitted selector means html. Omitted input/output means -. Long options are --filename, --output, --base, --detect-base, --text, --ignore-whitespace, --pretty, --remove-nodes and --attributes. -a and -r collect multiple occurrences. -B is case-sensitive. Output selection precedence is attributes, text, pretty, ordinary HTML. Other enabled modes do not combine their output.

The complete document is parsed before selection. HTML5 implicit wrappers therefore appear for fragment inputs. Selection yields elements in document order; selector-list deduplication and mutation interactions belong to the pinned selector/DOM contract, not arbitrary array sorting. Empty selection succeeds and emits nothing.

Removal does not mean remove all matches. For each selected node, the source uses select_first on the joined removal selector and detaches that one inclusive match. An invalid removal selector or no match is ignored at this stage. The selected node is then optionally rewritten and projected. A selected parent and child can both produce overlapping output; detaching an upcoming selected descendant can affect the lazy iteration and must be reproduced with an executable control.

## Proposed engine interfaces and implementation sequence

The command consumes an admitted HTML byte source and produces a bounded DOM with parent/child/sibling links, namespaces, ordered attributes and raw text nodes. Query compilation returns a selector program; evaluation visits bounded nodes and charges matcher work, including ancestor/sibling traversal. Serialization accepts a node, mode and awaited byte sink. URL rewriting mutates a selected element through the same DOM ownership API. Limit overrides lower host ceilings and cover input bytes, decoder state, DOM nodes/attributes/depth, selector tokens/nesting, matcher work, mutations, serialized bytes and retained state.

Build tokenizer/tree/serializer first, then the supported selector grammar, then projections and mutation order. This parser can also serve HTML-to-PDF later, but CSS cascade/layout remains separate. Do not promise every modern selector before verifying what upstream actually accepts.

Manual compatibility QA is a Markdown procedure: build or obtain the pinned native htmlq under an explicit temporary tool root; run H01–H30 with original saved inputs; capture raw stdout/stderr/status and file effects; inspect differences before codifying tests. Upstream parser libraries are oracle inputs only. The later native controls qualify enumerated cases; full grammar, mutation and recovery coverage remain open.
