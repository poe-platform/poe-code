## Root repair and semantics

Only `packages/safejs/src/interp/host-bridge.ts` changes in production, by two formatted lines in `wrapSandboxClosureForHost`. When the genuine `SandboxClosure.length` metadata exists, the existing async wrapper receives that value through `Object.defineProperty` before it is stored in the existing identity cache and callback registries. The same wrapper, invocation body, callback IDs, tracing, proof conversion, and cancellation behavior remain intact. No helper, dynamic function signature, generic converter, or acceptance rule is added.

Source arity is already computed by the parser/interpreter, bound arity by existing bind logic, and restored source arity by snapshot reconstruction. `createSandboxClosure` stores the number as non-writable data; a restored closure can inherit that internal data from its genuine base closure. Reading this typed internal metadata therefore also covers restored closures, unlike an own-descriptor-only lookup. The adapter does not inspect an arbitrary user-supplied native function or evaluate a getter to infer arity. Missing internal metadata leaves existing behavior unchanged; that is not a waiver of the confirmed supported guest-source case.

The wrapper's existing native length descriptor remains non-writable, non-enumerable, and configurable, matching the native source-function descriptor in the regression. Annotation does not invoke callbacks or parameter defaults, mutate the guest closure, replace cached identities, or alter argument/call semantics.
