## Design

Package-local intrinsic helpers inspect actual Float32Array slots without invoking input methods or accessors. Fixed buffer bytes are copied once per graph; views retain offsets and lengths. Native storage supplies binary32 rounding, signed zero and non-finite values. Constructor and copying-method allocation is checked against arrayLength and dataSize before allocating. Backing bytes are accounted once in the retained graph.

Typed replay and both snapshot serializers receive an additive Float32Array tagged view representation. The first view of a backing buffer carries its exact bytes; subsequent views refer to that view's backing storage. Named properties stay in the existing reference graph. Existing execution/version markers and historical captures are not rewritten. Old snapshots do not acquire retroactive successful Float32 execution merely because this feature exists; compatibility and original unsupported-global controls must be measured and qualified before handoff.

Expected shared integration paths are the interpreter, run global registration, values/host conversion, known-global lint registry, and snapshot codecs/validation. New implementation logic is isolated in Float32-specific files. Exact preimages and an early overlap receipt are captured before production edits.
