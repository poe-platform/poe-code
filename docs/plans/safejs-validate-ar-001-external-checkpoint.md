## Independent procedure and coverage

1. Execute all five scenarios natively first in a separate bounded Node child: reduction 10, callback 05, retry 06/re-issue, retry 06/external reconciliation, and generator 07.
2. Run current TypeScript through the public package source entry. Hold an ordinary declared native host operation at the original boundary. Request the actual public replay dump, then invoke the actual signal handler without overriding its dump implementation. Both snapshots arrive before releasing the native gate.
3. Release the original run and compare the complete result, boundary calls and final ordered host effects with native. Restore public-pending, signal-pending and completed snapshots in process.
4. Send the serialized snapshots, unchanged source and genuine completed host receipts into a new Node process. Repeat all 15 restores with fresh capabilities; no parent interpreter state or private wrapper is transferred.
5. Run dedicated independent tests against exact base production preimages via a read-only Vite loader and against the frozen candidate. The loader records the four actual preimage hashes; no working-tree swap occurs.
6. Validate documented defaults, callback restrictions, source aliases, missing-provider refusal, real OS helper signaling, existing CLI SIGINT recovery, declarations, full tests and meaningful screenshots.

All five original outputs, original call order, 10 requested pending captures, 15 in-process restores and 15 restores in one fresh host process match. Completed replay invokes zero native operations and zero reconciliation requests in every scenario.

Fourteen independent tests cover five original workflows, seven API/alias/host-boundary controls and two CLI compatibility controls. Original callback results prove six source callbacks, total 410, correct closure-derived batch values and full trace without duplicated source effects. - Public source exports and generated declarations expose `DumpOptions.mode?: "capture" | "replay"`; root typecheck passes. Positive captures use public `index.ts` run/dump/restore/declareHostOperation, never internal prewrapped closures.

- Same-run host callback requests remain rejected across await. A host callback belonging to another run can independently checkpoint the target run. Completed success/failure and onFailure checkpoint behavior remain intact.
- All captured envelopes genuinely use version 1 / jobs-v6. dump-format.ts, both CLI implementations, package manifests and lockfile remain identical to base. Existing restore/migration validation is retained; no arbitrary historical snapshot compatibility is certified.
- The changed SIGUSR1 helper has no production CLI caller and is not newly exported by the package index. That is an existing surface limitation, not evidence that supported CLI SIGINT is broken. CLI help explicitly documents best-effort SIGINT snapshots. Independent public runCli SIGINT testing returns exit 130 while the raw host gate is still held, writes a recoverable checkpoint, and resumes the unchanged source to 13 with one pending re-issue.
- Root harness CLI help and its existing SIGINT cancellation path were inspected. No new CLI signal or flag was promised by the frozen contract. Claiming completed/automatic snapshots alone as AR-001 resolution would be wrong; the independent public replay and helper evidence establishes the actual requested pending behavior.
