# Independent analysis tool protocol QA procedure

Execute this procedure with an agent other than the protocol implementation owner. Root retains shared-engine, safe-bash integration, export, and Git ownership. Native Gnumeric is an isolated QA oracle and is never used by product or unit code. Acquire source and capture temporary evidence only under `out`.

1. Authenticate Gnumeric 1.12.61 archive SHA-256 `2ac135d856572713c1a408b76b50a59f2a9769ed21f1213446b5af255df20a12` through the implementation owner's source receipt. Read `src/ssconvert.c` functions `run_tool_test`, `parse_property_based_options`, and native analysis setters. Use the captured C-locale dependency/plugin profile; do not generalize observations to unmeasured profiles.
2. Inspect writable property inventory and property order. Stress duplicate values, malformed arguments, first-colon splitting, canonical property spelling, exact Boolean tokens, enum nick/numeric admission, C numeric prefix conversion, signed overflow/narrowing, unsigned coercion, and rejected-property default retention.
3. Reproduce every suspected defect with a failing in-memory unit case before repair. Fixtures must be original and small; file integration fixtures use memfs. Unit tests must not spawn native programs or write host files.
4. Measure native malformed/missing ranges, selected sheets, collisions, exact output names, formula default and overrides, ordering, cancellation, and destination preservation. Record native crashes separately rather than implementing a host crash or fallback.
5. Execute the independent stress suite and root-owned maintained uncached workspace build/test/lint closure. Scope coverage accurately; unsupported tools and unmeasured numerical output are not passes.

## Verified observations on the working candidate

The independent agent inspected authenticated-source-location `out/ssconvert-lifecycle/gnumeric-1.12.61/src/ssconvert.c`, tool setters, and the implementation owner's native writable-property inventory `out/analysis-tool-protocol/inventory.tsv`. Native cases and environment profile are captured separately under that output directory. This document is a QA procedure and coverage report, not a replacement source-authentication receipt.

`protocol-independent-stress.test.ts`: 12 cases passed with a fresh Vitest process. Two validated defects were reproduced first: fill-series step/stop setters failed to set their implicit flags; rejected int/enum property messages used JavaScript-facing types and omitted the native property type. Repairs retain canonical GObject property iteration order, allow later explicit flags to override implicit flags, preserve defaults for rejected setter values, and render measured stable int/enum diagnostic bodies. The native enum type names come from the captured inventory. Four output sheet labels were corrected against source as directed by root.

Additional covered cases: exact lowercase truth tokens; LP64 `atoi` saturation followed by 32-bit narrowing; unsigned conversion; decimal/hexadecimal/nonfinite `atof` prefixes; negative zero; enum signed/whitespace rejection; duplicate replacement; colon-containing string values; warning ordering; ignored noncanonical/unknown options; case-insensitive sheet selection; output-sheet collision avoidance; source nonmutation; malformed/whitespace/reversed data references; dynamic ANOVA/chi-squared output names; exact cancellation-reason propagation.

Root's native range capture measured empty data, `bogus`, `=A1:A4`, and ` A1:A4 ` as status 0 producing an empty analysis sheet; preparation discards those references without warning. Native reversed `A4:A1` normalizes to `A1:A4`, matching preparation. Root owns checking these observations through actual command output.

After the moving-average runner was implemented, the independent agent executed `runner-independent-stress.test.ts`: nine cases passed in a fresh process. These cover original two-column labeled values with formulas disabled, horizontal row-window formulas, measured area/bin grouping, empty output for absent/malformed data, exact total-cell admission at 20 cells and rejection at 19, sheet-limit rejection, explicit unsupported graph/numerical variants and sheet spans, exact cancellation reason, unchanged original source/active sheet, independent sheet-ID/name collisions, and repeated analysis output naming. These are direct shared-runner tests, separate from root's CLI/SDK and safe-bash tests.

The protocol stress suite subsequently grew to 15 cases after root measured native double-property behavior. Failing regressions reproduced incorrectly admitted NaN, incorrectly formatted nonfinite/finite diagnostics, lost negative-NaN sign, lost signed-zero fallback for malformed negative hexadecimal prefixes, and cancellation hidden by unknown-tool failure after an awaited malformed-argument diagnostic. Measured cases include `2`, `-.1`, `-.0078125` (renders `-0.007812`), and `1e100`; the latter's full native binary64 integer expansion matches. `-0xg`, `-0x`, and `-0x.p2` retain negative zero; `-.` returns positive zero. Captured LP64 integer overflow/prefix values match existing stress expectations. Cancellation now propagates its exact reason at initial admission and after awaited diagnostics.

Runner stress finally grew to 11 cases. The previous assertion that the result retained the input active sheet was corrected against this concrete native evidence. The corrected regression failed before repairing the runner to activate its generated output ID. The original input workbook, including its active sheet, remains unchanged. Both independent suites subsequently passed again (26 total cases). Root owns verification of the resulting selected-sheet CSV export. The final GenericB range case distinguishes source-defined omitted `x`/`y` defaults (`value_new_error_REF(NULL)`) from explicit malformed `RANGE_ARG` results (`NULL`). Both independent suites then passed with 27 total cases (16 protocol, 11 runner). This is source-based preparation coverage, not a GenericB numerical-output pass.

## Remaining mismatches and unmeasured coverage

- Native rejected-property diagnostics include a GLib prefix containing process ID and timestamp and are GLib critical log records. Product currently emits the stable body through its injected diagnostic channel with warning severity; prefix bytes and critical classification are not matched.
- Arbitrary double-property diagnostic rendering beyond the measured values, alternate libc/locale behavior, and complete enum-warning rendering across every class have not been differentially measured. Source inventory does not establish their runtime parity.
- Root measured a nonexistent selected sheet as native status 139 with GLib assertions. Product safely rejects that invalid request with status 1. Crash status and assertion output are a measured mismatch; no native crash emulation is implemented.
- Preparation covers 31 native tool names and their inventoried properties. Numerical tool execution is a separate responsibility; root's default runner currently covers moving-average only. Remaining numerical analysis outputs are unsupported by that runner; injection/preparation unit passes are not numerical compatibility passes.
- Sheet dimensions, workbook name expressions, multidimensional/sheet-spanning data, resource exhaustion, every property/default/constraint transition, alternate function/plugin inventories, and actual safe-bash replay/realm budgets were not qualified by these 12 cases. Existing limits and host isolation must remain intact.
- Native moving-average header italic styles and chart styling/namespace effects are not covered by the runner stress assertions; cell values and formula bytes alone do not establish style parity. Label-only data and area/bin grouping were measured separately by root and their reported output behavior is covered by the independent runner suite.
- Root owns final maintained build/test/lint, CLI/SDK integration, safe-bash stress, and final coverage reporting. A fresh focused Vitest pass here does not certify those gates or a release. No push or publication is authorized.
