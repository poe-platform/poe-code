# Independent database interoperability stress review

Scope: a different agent reviewed the new TypeScript codecs and exercised the
shared SDK and safe-bash virtual command. This review does not certify every DBF
version, Paradox version, optional plugin profile, codepage or corrupted file.

## Concrete failures and repairs

- An in-memory SDK round trip of table `Café` and specification `Crème,A,8`
  failed with `CafÃ©`. pxlib 0.6.8 `src/px_head.c` copies metadata bytes unchanged;
  Gnumeric's plugin consumes UTF-8 names. Decode metadata as UTF-8 and clip
  specifications to the native 29-byte payload bound.
- A corrupted BCD decimal nibble `0xA` produced `1.105` instead of `1.:5`.
  `PX_get_data_bcd` converts each nibble with `+48`. Preserve that character
  conversion instead of formatting the nibble as an integer string.
- A negative 32-decimal-place BCD value failed by shifting the fraction one
  digit. An integral capacity of zero now contributes zero integral digits,
  matching the native BCD loop bounds.

All three failures were observed before the corresponding runtime edits.
Source was inspected only from the existing primary-source and pxlib trees in
`out`. Unit tests use original generated bytes and memfs, without native process
execution, LLM calls or disk writes.

## Remaining limits and manual optional-profile procedure

- Native optional-pxlib differential qualification belongs to the root's captured
  Gnumeric 1.12.61 profile. This agent did not run or alter that oracle.
- Invalid UTF-8 metadata, clipping through a multibyte sequence, greater-than-256
  columns and greater-than-65536 rows remain unmeasured native cases here.
- Missing external memo files, corrupted block chains and unsupported DBF
  codepages are not covered by this independent cohort.
- The pxlib BCD no-decimal-point branch computes a pointer using the precision,
  potentially beyond a short C string. Precision-32 coverage deliberately uses
  a decimal point; native undefined-memory behavior is not certified.
- Full host isolation, realm ownership, replay infrastructure and all budgets
  are broader contracts; these tests verify only the named command/SDK replay,
  injected I/O, destination preservation and cancellation cases.

For the dedicated optional-profile QA, record the actual native dependency,
plugin, locale and source-hash profile, run matching original binary fixtures
through both implementations, compare exit statuses, stdout/stderr bytes and
file effects, and retain every unsupported/unmeasured case as a gap. Store
temporary fixtures and captures in `out`, purge them after the maintained
evidence is recorded, and never turn the native tool into a product fallback.

## Final candidate recheck

After the root's native-profile repairs, this agent reread the DBF binary
NUL-padding behavior, exotic-codepage handling, added CP737/CP874 facts, Paradox
version 13–15 header layout, and output field/block/header bounds. The same six
SDK tests and one command test were rerun fresh and passed. No additional runtime
edits were made in this recheck. Old-version primary-index target-encoding
warnings remain owned by the root's measured diagnostic repair.

The root reports that the captured optional native profile uses pxlib 0.6.9,
with two explicitly recorded QA-only mechanical repairs for GSF reader pointer
truncation and an undeclared iconv result variable. Earlier source comparisons
in this document used the separately acquired pxlib 0.6.8 source tree; they do
not identify the captured native build as 0.6.8. Native short-specification
exporter use-after-free and nonterminated inline-memo output garbage are reported
oracle mismatches, not independent passes or authorization to reproduce unsafe
memory behavior in the product.

After the final header and record-count diagnostic repairs, this agent checked
that the record-count scan is bounded by the declared 16-bit block count and
calls the cancellation/yield helper on every step. The data scan separately
detects visited blocks, preserves readable records and refuses reads beyond
either the input bytes or the block boundary. Two additional original in-memory
regressions verify bounded cyclic-link partial output with the exact warning and
cancellation during the block-count scan. All eight independent SDK tests pass;
the root's 23 database tests and the one virtual-command test also passed fresh
before these two additional tests. No production source was changed by this
final review.

Native missing/truncated data can yield nondeterministic `-2147483648` from unsafe
reads, and a cyclic file can time out. The product's bounded partial output and
warning behavior intentionally cannot emulate arbitrary native memory values
or a native hang. Those corrupted-input mismatches remain explicit limitations,
even though the product liveness/cancellation regressions pass.
