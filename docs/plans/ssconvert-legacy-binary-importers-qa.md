# Legacy binary importers: implementation and QA record

## Status and authority

This candidate implements four separate declarative providers with JavaScript byte readers in the TypeScript ESM `@poe-code/ssconvert` package, consumed by the existing SDK engine and Safe Bash virtual command. It is **incomplete** against the requested all-record Gnumeric 1.12.61 contract. Passing subsets below are not complete format qualification. No native utility, psiconv library, process invocation or ambient file access is used by the product. No legacy writer was added. No README edits, commits, pushes or publication were performed.

Primary Gnumeric source was authenticated against archive SHA-256 `2ac135d856572713c1a408b76b50a59f2a9769ed21f1213446b5af255df20a12`, retained only beneath `out/ssconvert-lifecycle`. Psiconv 0.9.9 primary archive was acquired only into task-owned `out`, SHA-256 `6d51fe79b502a1e277bea275a574ae2db5b1b9d7daef703a8fa3635ae02a8bb0`. Derived tables retain upstream attribution. Native reference evidence is reduced into [legacy-binary-reference-profile.json](../ssconvert/legacy-binary-reference-profile.json); historical baseline profile remains unchanged.

Lotus old dispatch in pinned `lotus.c:1570..1680` actively handles only BOF, EOF, INTEGER, NUMBER, LABEL and FORMULA (with STRING lookahead); its other records intentionally pass through. Modern dispatch in `lotus.c:2000..2575` additionally handles selection, widths, FORMAT, values/formulas, STYLE, sheet names, RLDB and comments. Those active structures now have implementations and original fixtures. NAMED_SHEET and border database effects are source no-ops; CA_DB/DEFAULTS_DB/NAMED_STYLE_DB and many object/document/view records are source-ignored. LARGE_DATA and unknown records warn. Works V3 dispatch is separately implemented. The reference JSON includes 18 authenticated source-file hashes, source-order case-label inventories, 112 Lotus numeric definitions and 334 Quattro numeric definitions. Nested/disabled labels and formula constants occur in these inventories; they are audit inputs, not pass counts or proof of exhaustive semantic tests.

Lotus formula operand opcodes 0..6, modern errors 9..11, arithmetic/logical/unary/concat operators and the source function table are translated. Named range opcodes 7/8 emit the native unimplemented warning. Modern 0x7a special named functions are decoded. Tables in `lotus-functions.ts`, `qpro-functions.ts` and `pln-functions.ts` preserve source names/arities, but table inclusion does not verify every translated expression or evaluator function. Comprehensive token differentials remain required.

PlanPerfect formula decoder recognizes literal/string/function/comparison/whitespace/reference/range and source placeholder opcodes 1..46, with the pinned two function-name tables. Placeholder text and parse failure behavior need native comparison; recognizing an opcode is not equivalent to implementing its spreadsheet meaning. The source itself has incomplete formulas. Quattro formula dispatch and its function table similarly need exhaustive operand/arity/ref tests.

Psiconv behaviors deliberately followed from primary source include boolean cells using the nonzero type marker (thus true), error values becoming blank in Gnumeric, implicit leading-one float decoding even for exponent zero, and the released frozen-grid stride bug. Mandatory no-content page headers retain the source extra-byte advance. These are source-derived behaviors; absent-plugin native QA does not qualify their successful imports.

Psion structural formula parsing recognizes the source constants, references, ranges, unary/binary operators and fixed/variable argument functions. Translation deliberately follows Gnumeric's smaller supported subset; functions, power/logical/concat/not remain cache-only where native Gnumeric drops their expressions. Vararg separator/end bytes are 42/43. The captured little-endian Gnumeric Sheet font setter casts UCS2 to char*, truncating ASCII names to their first character (Times New Roman → T); structurally ignored page/bullet fonts use decoded Unicode instead. Font-related unsupported tests and embedded-object tests verify explicit failure behavior, not successful format qualification.

## Concrete regression evidence

Original small in-memory fixtures and memfs integration precede implementations. Initial missing readers produced failing provider import cases. Independent agent stress added failing tests before fixes for PLN zero-sheet admission, Quattro/Lotus cumulative formula budgets, Lotus final-diagnostic cancellation, modern sheet-name opcode and silent unsupported metadata/unknown-record handling. Follow-up root tests reproduced acceptance of truncated Psion mandatory page layouts, wrong Psion date/time literals and excessive decimals, and missing Lotus widths. Independent follow-up reproduced Psion omitted grid trailer and Lotus default-width work admission. Exact virtual-command corrupt Quattro stderr exposed double newlines; provider now supplies native diagnostic bytes instead of relying on generic CLI line termination.

[Independent stress procedure and results](ssconvert-legacy-binary-stress-qa.md) identify separate agent ownership and earlier failures. No assertion was weakened to make these bugs pass; unsupported-record cases were replaced with concrete width semantics as those records gained implementation.

## Native QA procedure and results

1. Authenticate the pinned archive before reading/extracting source; keep source and original generated binary fixtures under `out` only.
2. Use the captured separate Docker native binary/environment in the profile, with `LC_ALL=C`, `TZ=UTC`, schema path and memory settings backend. Capture binary hash/version, plugin listing, `ldd` and Debian dependency versions. Never patch the oracle or substitute another version for an unavailable plugin.
3. Generate original tiny fixtures from the memory test record layouts. Invoke native `ssconvert -T Gnumeric_stf:stf_csv INPUT OUTPUT` (explicit `-I Gnumeric_QPro:qpro` for corruption); capture status, stdout, stderr and output bytes. Compare the public JS engine with injected byte source/sink and the same locale/options. Record every result; missing output/errors are not passes.
4. Compare cached formulas both with and without explicit recalculation, styles through workbook output, each supported variant/container, every opcode, boundary/truncation and warning ordering; current measurements cover only the sample below.
5. For optional missing Psion, invoke `-I Gnumeric_psiconv:psiconv` and verify status 1, no output artifact, and exact absent-importer diagnostic. Successful Psion imports remain source-derived until an unchanged released-plugin profile can run them.

The reduced profile contains 36 cases: 27 exact native/SDK CSV status/output/diagnostic comparisons; three selected XML-fact comparisons; two additional native XML structure captures without full export qualification; three explicit diagnostic-envelope mismatches; and one absent-plugin profile. CSV samples include WB1 unsigned/text `65535,é\n`, WK1 signed/text `-1,hi\n`, PLN `1\n`, arithmetic cache `99\n`, recalculation, modern Lotus LMBCS12 `中\n`, all four Quattro signatures, all four stable modern Lotus signatures, Works `42,é\n`, and corrupt Quattro followed by valid cell `7\n`. Corrupt Quattro's exact stderr is `File is most likely corrupted.\nInvalid 'QPRO_INTEGER_CELL' record of length 1 instead of 8\n`; actual virtual-command memfs replays compare these bytes. Other native cases were measured through the SDK. These are sample comparisons, not fully qualified formats.

Explicit unknown Lotus version 0x1006 natively imports `1\n` with status 0 and warns `Unexpected version 1006`; JS now follows that routing while the auto probe rejects unknown versions. Unknown records and Works STYLE warnings likewise contain native dynamic GLib PID/time envelopes; JS injected diagnostics emit plain source messages. Exact diagnostic byte parity is therefore false. Selected native XML facts for Works font/alignment/wrapping/format, default width 82.69 and comment/cursor/viewport now match public SDK output. Full XML ordering, style partitioning/compression, default structures and all bytes are not qualified.

Absent Psion yielded status 1 and exact stderr `Unknown importer 'Gnumeric_psiconv:psiconv'.\nTry --list-importers to see a list of possibilities.\n`. Plugin absence is an optional-profile result; no successful Psion native comparison is claimed. Released plugin fails unchanged against psiconv 0.9.9 on undeclared `p_cellref_init`, as the baseline reference profile already records.

An initial native invocation omitted schema configuration and emitted unrelated GLib criticals. Corrected reruns used the complete profile above; earlier runs are not counted as clean comparisons.
