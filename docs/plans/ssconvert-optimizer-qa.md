## Source and numerical findings

The first LP regression failed with `Unsupported ssconvert feature: solver algorithm for linear model`. JavaScript now uses a bounded two-phase simplex and integer branch-and-bound, an invocation-owned Rosenbrock direction search and continuous active-basis sensitivity. The actual workbook evaluator supplies all objective/constraint values and applies/recalculates results. There is no native, subprocess, WASM or optimizer-dependency product path.

The captured source exposes exactly GLPK and LPSolve linear/MIP factories and Nlsolve nonlinear. There is no quadratic factory in these audited manifests; quadratic metadata therefore prints `Solver: Failed to create solver` and continues, as native does. A quadratic objective with nonlinear metadata is numerically exercised. This distinction does not claim a missing quadratic factory is implemented.

The original native LP has objective `3*A1+2*A2`, constraints `A1+A2<=4`, `A1<=2`, `A2<=3` with cell-valued RHSs, nonnegative variables. Both GLPK and LPSolve produce (2,2), objective 10. GLPK 5.0 reports Feasible for a completed continuous optimum; LPSolve reports Optimal. Both program reports contain static values, bold Target/Variables/Constraints headers and the measured rows/slacks. Native names are `Solver (1)` and `Solver (2)` and the last report receives focus. Sensitivity scalar-constraint iteration resets its index for each source constraint; the measured repeated shadow 2 and limits 2/5 are deliberately preserved. GLPK omits reduced costs and some infinite-breakpoint ranges because of its released human-report parser. LPSolve retains reduced cost 0 and A1 lower coefficient limit 2. The minimization control returns (1,3), repeated shadow -1 and RHS limits 2/4.

Native bounds derivation replaces a numeric RHS with zero when no RHS cell exists. A direct input constraint can consequently produce zero secant columns and constant LP rows. GLPK fails on a constant row or an empty ordinary row set, prints `Solver: Solver ran, but failed`, exits 0 and preserves cells. JS covers those distinctions. Infeasible and unbounded valid-row GLPK cases apply #N/A to inputs and exit 0. Requesting sensitivity ranges for an infeasible model instead fails, preserves cells and exits 0. A program-only infeasible report displays raw solver zeros after input cells receive #N/A. Native numeric-RHS report formatting can additionally emit pid/time-bearing GLib critical diagnostics; those bytes are a remaining mismatch.

Native Nlsolve equality/discrete startup errors and infeasible initial values continue conversion. Iteration-limit warnings also continue and retain feasible incumbents. LP plugins do not impose the Nlsolve iteration option; MaxIter=0 on the native LP still produces (2,2). Native MaxTime is checked only by the GUI timeout callback; ssconvert and these plugin execution paths do not impose it. JavaScript command solving likewise ignores GUI-only MaxTime metadata and always has a shared finite work budget. The numerical routine budget separately supports explicitly injected elapsed-time limits. An initial unsigned-time inference was rejected during independent source review and removed; the final command regression uses MaxTime=0 and an injected clock.

Independent stress reproduced and repaired integer-infeasible/unbounded-relaxation classification, minimization report signs and admission of constructor/coefficient/nonlinear matrices before allocation/evaluation. A command regression reproduced asymptotic boundary convergence exhausting the existing work budget; bounded near-box polishing now reaches zero while retaining strict objective improvement and full feasibility checks. Independent boundary stress verifies rejection of worse or infeasible snaps and cancellation. See `ssconvert-optimizer-independent-qa.md` for original exhaustive-integer, classical-cycle, free-negative, Rosenbrock, cancellation and report controls.
