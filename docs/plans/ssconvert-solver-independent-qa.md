# Independent solver stress QA

## Procedure and scope

A separate agent reviewed `src/solver/model.ts` against the extracted released Gnumeric 1.12.61 source in `out/ssconvert-lifecycle/gnumeric-1.12.61`. Root retains command/export/integration/Git ownership. Use original in-memory workbook fixtures, run `npx vitest run packages/ssconvert/src/solver/model.test.ts`, then the maintained workspace lint route. Tests do not create files, spawn utilities, or access external capabilities.

Inspect `src/xml-sax-read.c` solver and named-expression handlers, `src/value.c:value_new_cellrange_parsepos_str`, and `src/tools/gnm-solver.c` target lookup, validation and legacy constraint conversion. Search Excel and OpenOffice plugin sources for solver import hooks; absence of a hook is a source-audit result, not an Excel/ODF differential pass.

## Validated repairs

Five original regressions failed before repairs: absent target incorrectly treated as created input cell; invalid legacy target coordinates threw rather than retaining modern target; final-workbook names could be resolved despite deferred native XML name definitions; unknown native constraint types bypassed less-than-or-equal RHS validation; legacy rectangular domain coordinates were ignored. Initial named-objective test was corrected after deeper source inspection: `xml_sax_named_expr_end` creates empty placeholders, while `handle_delayed_names` installs definitions after file parsing. Native retained Solver records therefore reject named targets, inputs and constraint sides, including local/global names.

Legacy targets now override modern targets only with valid complete coordinates. Native constraint relations are typed `1 | 2 | 4 | 8 | 16`; unrecognized XML types default to `1`. Legacy constraints use default origins and dimensions and overwrite modern sides. Missing targets fail before input-cell consideration. Parenthesized references are accepted as in `gnm_expr_get_range`. Domain-membership scans consume the workbook work budget and check cancellation. Two subsequent failing regressions verified cross-sheet diagnostic quoting via shared quoteNativeSheet and rejection of imported-record getters without execution via snapshotWorkbook at the loader boundary.

Additional failing cases reproduced incorrect `50%` RHS handling and absent native constructor options. Constraint RHS now uses existing `matchNumber` before range parsing, reproducing percent scaling, C-locale currency/grouping, accounting parentheses and signed decimals. Formula-prefixed numeric values and arithmetic expressions are rejected because `gnm_expr_get_range` cannot turn numeric formula ASTs into cell ranges. Native constructor-only `gradientOrder: 10`, `scenarioName: "Optimal"` and `addScenario: false` are exposed without interpreting invented XML attributes; native Solver XML only serializes the existing iteration/time/boolean model options.

Parser inventory: `formulas/functions/text.ts:matchNumber` supplies captured-locale numeric/grouping/currency/accounting/date/time matching and calls `formulas/values.ts:numericText` for numeric/scientific/percent text. `formulas/parser.ts:parseExpression` and `formulas/local-references.ts:localReferenceRange` supply bounded reference geometry. No new locale parser or product dependency was added. Fraction syntax, alternate currency symbols, full native whitespace/grouping acceptance, localized dates and uncaptured locales remain unmeasured matcher parity gaps; they are not certified by these C-locale cases.

Native `xml-sax-read.c` recognizes only native-namespace `Constr` children beneath Solver. Existing `gnumeric.ts:record/accepted` already filters that grammar and normalizes accepted native namespaces to `http://www.gnumeric.org/v10.dtd`; imported extension children never reach the solver loader. The synthetic legacy fixture was corrected to `Constr` in that namespace. A raw-SDK fabricated extension-child stress probe showed the loader itself does not filter children; no runtime change was made because importer admission already owns that invariant. This is not an imported-file parity failure or a claimed SDK extension-input pass.

## Verified coverage and limits

The focused model suite has 24 in-memory cases covering native defaults/options, domains/model classification, validation order, formula inputs, shape mismatch, explicit unavailable algorithms, missing targets, invalid legacy coordinates, native local/global name rejection, unknown constraint type, legacy domain rectangles, parenthesized objectives, active-sheet selection, cross-sheet domain rejection, cancellation and domain-work exhaustion. Focused vitest and maintained workspace lint completed successfully after repairs. The final failing budget regression used 40 variables and 50 ordinary LE constraints with workbookWork=2500: both domain scans now count every predicate visit before checking relation, preserving cancellation and bounding ordinary-constraint scans. Late failing regressions verified all native Boolean options: case-insensitive false or exact zero disable, every other present string enables. Valid signed-32 iteration values preserve unsigned storage bits while time values remain signed. Another failing case verifies constraint LHS numeric-first precedence: 1:2 matches a time number and cannot become a whole-row constraint range; objective and input references still use range-only parsing. A grouped-formula regression verifies that native array members carry expressions: numeric array-element objectives validate, and grouped variable cells receive the formula-input diagnostic through existing calculation normalization. No evaluator changes were made. A selector case additionally confirms functional saved choices are retained despite mismatched model type, and unavailable saved choices fall back to the first functional model-matching registry entry. Root owns final maintained uncached workspace build/test and cross-workspace checks; these focused tests alone do not certify them.

No released spreadsheet solver import hook was found by searching `plugins/excel` and `plugins/openoffice` for solver references. Native Excel Solver add-in metadata and ODF solver extension inputs remain unmeasured; this audit must not be reported as passing differential coverage. Native GLPK/LPSolve/Nlsolve numerical execution and iteration/time-limit results remain parity blockers until JS algorithms exist. No native fallback was introduced.

Remaining unmeasured details include localized numeric constraint syntax, malformed/out-of-range XML integer coercion, arbitrary formula recalculation side effects, native input-cell allocation namespace effects, archived Excel/ODF extension variations, and numerical optimization results. The stress suite verifies geometry and validation only, not solver execution or complete native parity.
