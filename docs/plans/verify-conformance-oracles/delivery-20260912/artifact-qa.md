# Published artifact verification

Execute this manual procedure after the authorized main push. This is packaging QA, not a repeat of the complete ECMAScript corpus, and does not infer oracle coverage from installed packages: the conformance runner is a repository test tool, excluded from the npm runtime artifacts.

1. Read registry metadata independently for `poe-code`, `@poe-platform/safe-fs`, `@poe-platform/safe-js`, and `@poe-platform/safe-bash`. Save exact versions, tarball URLs, integrity and attestation URLs. Compare to `registry-before.json`; no old version is a new publication receipt.
2. For each newly published package, fetch its npm attestation bundle. Decode the SLSA statement, require the source `gitCommit` to contain implementation commit `d5baada123a54174cfa6a31f65427d160d1c4ccb` (check Git ancestry if different), and require the invocation URL to identify the successful publishing workflow. Compare the statement's subject SHA-512 to npm's declared integrity and the bytes downloaded from the exact tarball URL. Save each package separately, including any unavailable/error result; partial publication does not establish family success.
3. In a new temporary consumer directory, install all exact versions with `npm install --ignore-scripts --no-audit --no-fund`; save the argument vector and terminal output. Installation must not refer to workspace symlinks or local dist. Run `npm audit signatures` there to verify registry signatures/provenance with npm, recording its result separately from the digest/ancestry checks.
4. Run four independent commands in that consumer, retaining each exit code and output: SafeJS executes `return 6 * 7` and exposes no ambient `process`; SafeFS writes and reads bytes using its explicitly supplied in-memory filesystem; Safe Bash first rejects an unregistered `printf`, then executes `printf oracle-artifact` after explicitly registering only that command, using an explicitly supplied memory filesystem, and disposes the shell; `poe-code --version` renders the exact installed version in its design-system frame, and `poe-code/safe-js` executes arithmetic without ambient process authority. Each check imports the installed published package, not workspace source. These narrow controls do not qualify all runtime APIs.
5. Record required workflow URL, head SHA and terminal conclusion separately from registry versions and smoke results. Cancelled or superseded workflows require verifying a successor's ancestry before reuse. If a publish fails, retain every already-published package's independent receipt and diagnose the failing job. Never unpublish, roll back, or publish locally. A repair requires a validated failing control, an atomic commit, normal push and verified successor publication.

The implementation release must finish before the final evidence-only commit. Monitor that docs successor too; a green no-release root workflow does not claim another package version. Keep the successor's final observation separately because a commit cannot contain its own SHA or subsequent workflow result.
