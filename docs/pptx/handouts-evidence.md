This bounded F49 receipt supplements the historical audits; it does not replace
or reclassify their unimplemented public APIs. [Case accounting](handouts-accounting.json)
links the complete adjacent notes, master and presentation-dimension receipts,
with explicit association criteria. Their parameter variants, expanded BDD
scenarios, inherited members, constructors, enum values and underscore-prefixed
public interfaces retain their existing statuses; unrelated text/shape cases are
not reclassified as direct F49 obligations.

No direct handout, notes-page-size, or print/view public API/test is present in the
pinned inventories. The OPC view-properties content-type case remains relevant.
Core `last_printed`, last-slide-viewed actions and chart top-view enums are separate
behaviors. F49 therefore needs new original assertions, not invented upstream

## JavaScript and security mappings

- J01/J10: neutral model spellings remain unchanged. Operation inventory records
  and camelCase schema fields do not implement a live `Presentation` object graph.
  CLI uses plural resources and `text replace`, shared selectors and envelopes.
- J02/J07: missing notes dimensions/resources remain null/absent on inspection.
  Reads must not invoke creating notes/master getters, synthesize templates or
  timestamps, or mutate the document. Unknown placeholders/layout values retain
  their original XML and bytes when unrelated parts are edited.
- J03: CLI ordinals are one-based; SDK resource records identify canonical owning
  parts. Placeholder IDs are keys, not collection positions. Shared text mutation
  requires explicit `handout-master` scope; ordinary slide scope excludes it.
- J05: notes dimensions use safe integer EMUs; zero and false remain explicit
  values. Missing values are not guessed. The existing settings operation supports
  notesWidth/notesHeight and notesOrientation; it does not establish layout output.
- J06/J09: asynchronous admitted `Uint8Array` inputs and explicit VFS capabilities
  are the only I/O authority. Relationship targets and public XML views remain
  owner-bounded. Inspection never follows external links, invokes a printer or
  renderer, or grants native/host access. No unrestricted XML-library interface is
  promised by preserving `.element` or `.part` obligations in the API register.
- J08: shared usage/schema errors have exit 2, document/selection/unsupported errors
  1, I/O 3, limits 4 and cancellation 130. Retained attributes are inventory data;
  they are not executable commands or accepted editing profiles.

## Documentation reconciliation

The baseline test audit's “adaptation not started” describes its historical
checkpoint. Later notes/master/settings receipts establish bounded operations,
while live-model members remain pending. In particular notes dimensions already
have settings support, but print/view XML retention does not mean complete
semantic editing, and handout resource inventory does not mean rendered handout
pages. F49 is additive to the public API baseline. Do not claim full SDK parity,
printer layout, pagination or visual fidelity from this receipt.

source identities appear only in the research ledgers. The bounded QA procedure
