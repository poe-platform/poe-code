It preserves outgoing relationship closure without interpreting embedded content. It does not create OLE objects or implement the live format model.

## Language and security mappings

`readObjects(input, context)` and `extractObject(input, { part }, context)` are always asynchronous. Inputs are admitted bytes, explicit streams or capability-scoped VFS paths, with caller-supplied limits and cancellation. The SDK never discovers a host path. Extraction returns owned `Uint8Array` bytes; result arrays describe a snapshot, not live model ownership or collection equality. Read-only inventory does not instantiate a creating getter.

Classification uses declared content types, relationship kinds and conservative executable/compound-container prefix signatures. `activeContent` means a potentially active carrier or recognized header, not proof of maliciousness, a complete scanner or permission to execute. External relationship targets remain inert strings. Font bytes are not installed or decoded. 3D and web extension payloads are not rendered. No nested package/compound payload is recursively parsed.

Outgoing internal dependency closure is cycle-bounded by the package part set. Exact relationship-part bytes accompany extraction. Missing dependencies remain visible in inventory and block extraction. Generated extraction basenames derive from package-part SHA-256 with an `opaque-` prefix and `.bin` extension; embedded names cannot supply traversal paths or collision-prone basenames. The manifest maps safe filenames back to original part identities. This is an extraction bundle, not a rebuilt embedded package.

Neutral model spellings `blob`, `prog_id`, `show_as_icon`, `add_ole_object` and inherited members retain their shared SDK obligations. Operation records are not camelCase aliases claiming to implement them. `PROG_ID.icon_filename` must eventually identify original inert packaged artwork metadata; it must never authorize ambient file reads or reuse reference artwork without the required rights.
