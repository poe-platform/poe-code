# Selected sanitization: bounded accounting

This receipt supplements the historical upstream audits for F56 and its notes,
review, metadata, external-link and embedded-object dependencies. It does not
claim whole-public-API parity or that a file is free of hidden data. The
[ledger](sanitization-case-map.json) reconciles 341 expanded unit variants,
117 expanded BDD examples and 179 public API records to their existing detailed
original TypeScript receipts. Each identity resolves to the pinned inventory;
parameter variants are never collapsed into a source test-function count.

The dependency ledger retains each earlier receipt's status without promoting
it. Notes live-model members remain incomplete; opaque extraction/inventory does
not implement OLE creation or the complete returned object graph. Existing links
owner views have documented full-graph wiring limits. Scalar metadata has bounded
live accessors. Shared inherited shape/text/package interfaces outside the union
remain in the complete public register. Types beginning with an underscore are
public obligations where the API inventory records them.

Legacy and modern annotations, bulk sanitization and signature cleanup are not
established by the pinned test baseline. Comment-named core metadata cases test
description strings, not review threads. Original removal, retention, graph and
security regressions therefore supplement the baseline rather than masquerading
as adapted upstream passes. Detailed source equivalence and original test names
remain linked by JSON pointers in the ledger.

## Language, security and documentation reconciliation

Byte operations consume `Uint8Array` or explicit admitted input capabilities and
return asynchronous results; no host filename authority, clock, identity,
network, native runtime or embedded-content activation follows from package XML.
Operation records are detached data, not replacement live NotesSlide, _OleFormat
or relationship collection objects. Neutral documented model spellings remain
unchanged. Creating model getters remain distinct from noncreating inspection.
CLI one-based positions must not be used as JS model collection indexes.

The historical test audit's “adaptation not started” statement describes its
pinned checkpoint. This supplemental receipt describes later bounded work and
does not rewrite that history. The stale documented CoreProperties module path
continues to resolve to the recorded implementation type while preserving both
source identities and neutral member spellings. Public `comments` metadata
means description; it does not become a modern or legacy annotation collection.
The exact existing property/date, link/action enum, collection and package-view
mappings remain authoritative in the linked API receipts.

A category removal policy is explicit intent, not a request to erase every
unknown extension or package member. External relationships are inert references;
URL strings confer no network authority. Ordinary external hyperlinks and active
macro/program/OLE actions are different security cases. The complete signature
graph requires its separate explicit removal contract before mutation; sanitizing
another category must not silently discard signatures or bypass protection.
Known-retained and unknown/opaque content must remain visible in the report.
Absence of recognized selected data does not prove absence of hidden data.

Whole-text replacement and formatting-preserving text edits remain separate
operations. Sanitization must remove the selected node/edge or known scalar only;
it must not flatten runs, reconstruct unrelated styles, strip unknown XML, delete
unselected shared resources or erase chart workbooks as ordinary OLE payloads.
Shared graph cleanup must retain any resource still referenced by another owner.
