safe-bash + FFmpeg + ImageMagick

safe-bash has an FFmpeg shim.
The shim calls the Sandbox API.

You run an ordinary ffmpeg command. A JavaScript shim sends it to an API that runs the real FFmpeg. ImageMagick works the same way.

ffmpeg -i input.mp4 output.mp4
Cloudflare Worker

safe-bash → FFmpeg shim

The shim receives the arguments, uploads the needed files and calls the API.

It returns streams, file changes and the exit code to safe-bash.

→API call + files
←results
Cloudflare Sandbox

API → real FFmpeg

The server puts files in the right folders and runs the native tool.

The Worker does not run these binaries itself.

1. Send what it needs

Upload input files and their dependencies, keeping the right folders.

2. Run the tool

The Sandbox runs FFmpeg or ImageMagick. Pipes stream data as it runs.

3. Bring results back

Output files, messages and the exit code return to safe-bash.

To the caller, it’s a normal safe-bash command.
Behind the scenes, the media processing is remote.

Where do the two packages fit?

media-cli understands FFmpeg and ImageMagick commands.
remote-execution handles file transfer and remote jobs.
safe-bash connects to them through mediaCommands({ engine }).
