# Frozen csvkit SQL schema compilation

The target is csvkit 2.2.0, source archive SHA-256 `147318a8dbaec07c0bbb9291c14b78de5fa32ed3d4a5c2396e52a83c0a30df6b`, under the existing `darwin-cpython-3.14.2-csvkit-2.2.0` reference profile. SQLAlchemy 2.0.54 supplies the captured core dialect order `mssql, mysql, oracle, postgresql, sqlite`; generic compilation is additional. The profile has no third-party dialect entry points. The independent corpus and complete identifier-preparer metadata are in docs/csvkit/sql-schema-reference.json.

## Derivation and compilation

`packages/csvkit/src/sql/schema.ts` derives an immutable column/unique-constraint model and compiles it with declarative database descriptors. Build-time provider discovery remains in scripts/generate-inventories.mjs; there are no dialect-name branches in derivation, compilation or csvsql. `deriveSchema`, `compileCreateTable`, `sqlIdentifier`, `sqlSchemaIdentifier` and their model/work types are exported through the public csvkit package. Work ports preserve invocation cancellation and budgets; these synchronous functions acquire no I/O resources.

Agate SQL_TYPE_MAP uses DATE and VARCHAR directly. Boolean defaults to BOOLEAN, overridden by MSSQL BIT; the MySQL compiler emits BOOL. Number defaults to DECIMAL, overridden by SQLite FLOAT. DateTime defaults to TIMESTAMP, overridden by MSSQL DATETIME; PostgreSQL emits TIMESTAMP WITHOUT TIME ZONE. TimeDelta defaults to emulated DATETIME, overridden by PostgreSQL INTERVAL and Oracle INTERVAL DAY TO SECOND. The upstream crate FLOAT and ingres length/precision entries belong to uninstalled optional dialect profiles, not the supported core list.

With constraints enabled, all non-DateTime columns use HasNulls for nullability. DateTime remains nullable even when all input values are present. MSSQL explicitly emits NULL for nullable fields; MySQL explicitly emits NULL for nullable TIMESTAMP. No-constraints removes null checks and numeric/text length constraints. MySQL unconstrained VARCHAR fails with the reference CompileError rather than silently becoming TEXT.

Only the core MySQL profile derives VARCHAR length, measured in Unicode code points over non-null values. It multiplies observed length by Decimal(multiplier) under the frozen precision-28 half-even context before testing the 21844-code-point TEXT threshold, then applies the Python-sized integer minimum. Large negative products can therefore round, even though the argv multiplier is an integer. Schema-only uses fixed defaults of one because csvkit does not forward these options to to_sql_create_statement; connected creation uses the supplied settings.

MSSQL/MySQL/Oracle derive DECIMAL precision 38 and scale from Agate MaxPrecision under Decimal precision 28. This uses normalized significant decimal places, starts whole places at one, and reduces scale when total places exceed 28; negative scales are preserved. Agate's math.isnan/math.isinf conversion to binary64 first skips overflowing finite Decimals as well as infinities/NaNs. Finite binary64 maxima and underflowing Decimals still participate. Generic/PostgreSQL DECIMAL and SQLite FLOAT do not receive derived precision/scale.

Identifiers use the captured reserved sets, quote characters, illegal initial characters and percent escaping. SQLAlchemy's CPython case-insensitive legal-character profile includes dotless i and long s and accepts a final LF anchor. Names with Unicode outside that class, upper case, reserved words, numeric initials or dialect-specific illegal initials are quoted, and closing quotes are doubled. Schema and table are quoted separately. The MSSQL descriptor enables SQLAlchemy's bracket-aware database/owner grammar: `db.owner` becomes two names; earlier dotted components are joined into a database name, bracket groups preserve embedded dots, and internal bracket groups can force raw quoted database text. Empty schema elements, unusual brackets, newlines and schema-placeholder sentinels preserve the frozen source behavior. Other dialects quote dotted schemas as one name. `sqlSchemaIdentifier` exposes this profile-selected grammar; there are no provider-name branches or regular expressions. Empty identifiers retain the reference IndexError. A UNIQUE constraint preserves first occurrence order, deduplicates repeated columns, follows all columns and has no generated name. Missing columns raise the exact ConstraintColumnNotFoundError.

SQLAlchemy Boolean defaults to create_constraint=False in this frozen version. Consequently there are no Boolean CHECK constraints, generated CHECK names or CHECK-order nondeterminism to simulate. Other SQLAlchemy versions/options remain unqualified.

`compileCreateTable` returns SQLAlchemy's raw leading newline and two trailing newlines, without a semicolon. Connected sessions receive those exact bytes. csvsql's schema-only path strips surrounding whitespace and adds `;\n`. Fields join with comma, space, newline and tab exactly as the compiler does. argv and SDK use the same operation; the fourteen executable names and original syntax are unchanged.

## Optional profiles and limits

`CsvkitContext.sqlDialects` and safe-bash `CsvkitCommandsOptions.sqlDialects` accept explicitly injected compiler descriptors for connected sessions whose reported dialect is outside the core inventory. Descriptors supply qualified type overrides, quoting and length/precision behavior; built-in profiles retain precedence. Admission copies their mutable metadata without freezing caller objects. Missing metadata remains status 78 with transaction rollback/close. The synthetic port test proves capability routing, not compatibility with an actual third-party dialect. Schema-only core CLI choices stay frozen; hosts can directly derive/compile through the public SQL functions with an independently qualified descriptor.

No database driver is loaded implicitly. Non-SQLite INSERT bindings, real services, third-party dialect interoperability, other SQLAlchemy/CPython profiles and exhaustive SQLAlchemy schema combinations remain explicit blockers. The existing injected session lifecycle, cooperative cleanup, cancellation, stream ownership and awaited backpressure are unchanged. No product subprocess or Python fallback is used.
