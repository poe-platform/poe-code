# Explicit SQLite binding

`createSqliteDatabaseProvider` in `packages/csvkit` binds real SQLite to the existing shared CLI/SDK engine and safe-bash command family. The executable names remain `csvsql` and `sql2csv`. Nothing loads this provider implicitly. Hosts pass it through `databases` when constructing the command family or SDK context.

The selected infrastructure is `@sqlite.org/sqlite-wasm@3.50.4-build1`, integrity `sha512-Qig2Wso7gPkU1PtXwFzndh+CTRzrIFxVGqv6eCetjU7YqxlHItj+GvQYwYTppCRgAPawtRN/4AJcEgB9xDHGug==`. Its WASM SHA-256 is `3c924f7de0fd0979da11615be99ec826a066f8fc804a91c3ec9c45b7d8f1655f`. This is compiled SQLite infrastructure, not compiled csvkit/Agate/Python and not a product subprocess or Python fallback. SQLite itself parses, plans and executes statements. The binding verifies version 3.50.4 and the source ID from the frozen primary reference. It does not claim compatibility with the secondary SQLite 3.43.2 reference.

## Host configuration

`SQLiteOptions.sqlite` is an already initialized SQLite module. Runtime initialization, WASM compilation/instantiation, module bytes and any worker hosting must be explicitly authorized by the caller. The product factory imports only its TypeScript type; it never calls the package's loader. Hosts must provide `wasmBinary` or their authorized instantiator to the infrastructure loader rather than allowing its default filesystem/network resolution. This boundary needs WebAssembly, BigInt and the upstream WASM callback table. It is unavailable in runtimes that disallow those infrastructure capabilities.

The public `sqlite` type is opaque; the adapter keeps the upstream API type internal, so ordinary SDK consumers do not need its complete declarations. `cwd` is the fallback for direct driver calls. The shared command engine passes invocation `cwd` as optional fourth `connect` argument, so relative database URLs follow actual shell/SDK invocation cwd. `clock.now()` supplies milliseconds since the Unix epoch to this VFS. `random(bytes)` fills the requested VFS randomness buffer. SQLite's process-wide PRNG and upstream initialization are infrastructure state: this is not a claim that its complete entropy lifecycle is isolated per provider. `vfs` optionally supplies synchronous trusted random-access files. No environment variables, host credentials or ambient paths are consulted by the factory.

`limits` exposes positive safe-integer `maxWork` (default 10,000,000 VM operations), `maxSqlBytes` (1,000,000), `maxValueBytes` (16,000,000 SQLite length limit), and `maxResultRows` (100,000). A progress callback checks cancellation and work every 100 VM operations, including prepare/step. Work accumulates across the session's queries. Rollback resets work and uses an independent signal so canceled guest work can release transactions. SQL byte/SQLite value/result-row limits complement the existing command engine's byte/row/retained/output budgets. These are not a hard total WASM-memory limit or timer-preemption guarantee. Opaque host callbacks, non-VM engine allocation, busy waits and module initialization remain outside that accounting.

`dispose()` synchronously rejects new connection admission, then closes the provider's sessions/statements, unregisters its VFS and releases installed callback/struct resources. It is idempotent. Failed connection setup closes an acquired database before rejecting. Named capability failures from VFS read/lock callbacks and transaction-control I/O retain their domain refusal rather than becoming generic SQLite I/O errors. The caller owns provider lifetime; per-command registered cleanup owns acquired sessions, results and iterators. Sharing a provider does not transfer provider ownership to an individual command.

## SQL and results

`sqlite://`, `sqlite:///` and `sqlite:///:memory:` create independent in-memory databases. `sqlite:///relative.db` resolves under `cwd`; `sqlite:////absolute.db` uses an absolute virtual path. `sqlite+pysqlite` is an explicit scheme alias, including the empty-path memory spelling. Percent escapes remain literal filename characters, matching SQLAlchemy SQLite parsing. Query strings, fragments, NULs, `file:` filenames and unbound file URLs are refused. Shared descriptor validation reports the qualified native invalid-authority diagnostic before capability resolution; credential-bearing invalid URL rendering remains a named qualification blocker.

The first statement is prepared by SQLite. The returned SQL tail is checked using CPython's whitespace/comment rules before stepping; a second statement is rejected, while semicolons inside SQL strings are left to SQLite. Values are bound through C APIs. INTEGER results retain signed 64-bit BigInt identity; REAL results retain Python float representation through existing tagged CSV cells; NULL remains null. Text decoding preserves BOMs and embedded NULs. BLOB remains bytes in the database API and uses CPython bytes representation when written through either CSV command.

Query results step once before publication, then stream one row per awaited consumer request. Result close, iterator return and session/provider disposal finalize statements. DML beginning with INSERT/UPDATE/DELETE/REPLACE starts a legacy implicit transaction when needed; DDL/query-only operations and CTE-leading DML retain SQLite/CPython legacy behavior. Explicit transaction statements are handled by SQLite. `csvsql` owns its begin/commit/rollback boundary; `sql2csv` rolls back uncommitted DML on cleanup.

## VFS contract and actual adapter

`SQLiteFileSystem` exposes `open(path, SQLite flags)`, `exists` and `delete(path, syncDirectory)`. `SQLiteFile` exposes bounded offset `read`, complete `write`, `truncate`, `size`, `sync`, lock acquisition/unlock/reserved checks and close. Methods must be synchronous; there is no async filesystem bridge or snapshot substitution. The backend must enforce authorization for main, journal and temporary files, honor requested open modes, and implement SQLite lock levels correctly. The VFS advertises version 1, no mmap/WAL/shared-memory methods and no atomic-write device guarantees. Read/access capability granularity is limited: xAccess currently exposes existence only. Durable implementations require separate qualification, including access-mode reflection and fault recovery.

`createMemorySqliteFileSystem(volume, {authorize, maxBytes})` is the concrete adapter for an explicitly supplied synchronous memfs volume. It limits accounted database/journal bytes, requires existing parents, rejects canonical-path authorization failures and symlink traversal (including dangling links), and coordinates SHARED/RESERVED/PENDING/EXCLUSIVE locks among its descriptors. Use one adapter for all connections to the same volume; direct volume mutations or independent adapters bypass its accounting/locks and are outside its qualified contract. `sync()` makes no disk durability claim. Pages and committed transactions persist only for that volume's lifetime. No cross-process locks, crash durability, directory fsync, host atomicity or disk publication are supported by this adapter.

## Explicit parity blockers

The selected WASM build is not the frozen CPython build. `docs/csvkit/sqlite-wasm-profile.json` records actual source/compile options/function inventory; `sqlite-engine-reference.json` records freshly authenticated CPython/SQLAlchemy measurements and original executable channels/status. Known absence is never counted as a compatible result:

- OMIT_UTF16 removes reference `PRAGMA encoding` and UTF-16 database semantics. Encoding requests are named status-78 refusals; UTF-16 database-file qualification remains blocked.
- FTS3, FTS4 and Geopoly are absent. Known virtual-table requests are refused; their full functions, tokenizers, persistence and query profiles remain blockers.
- SQLAlchemy registers Python `regexp` and `floor` on reference connections. The injected provider overrides bare WASM floor to preserve INTEGER identity, signed 64-bit values, negative rounding and native callback errors for NULL, text, blobs, infinity and overflow. The bounded original-oracle cohort and rollback regression are recorded in `docs/csvkit/floor-user-edge-validation-20260919.md`; this does not qualify all SQL functions. REGEXP remains refused as an unqualified Python-function profile rather than substituting JavaScript regular expressions. Reference-only function names absent from this build include offsets, fts3_tokenizer, matchinfo, optimize and the recorded Geopoly function family; the full function inventories are retained for audit.
- OMIT_DEPRECATED, OMIT_SHARED_CACHE, MUTEX_OMIT/THREADSAFE=0 and lack of WAL/mmap/worker support differ from the reference. Deprecated/compile-profile/threads/mmap/busy-timeout pragmas and introspection functions are refused. Page-size and cache-size defaults are aligned through actual SQLite pragmas; complete PRAGMA/function/module/compile-default equivalence and exact file-byte parity remain unqualified.
- ATTACH/DETACH, VACUUM (including implicit attachment), VACUUM INTO, load_extension, readfile/writefile, URI features and filesystem-directory pragmas are named host divergences. Unnamed file acquisition is unsupported. No parser approximates these operations.
- Invalid UTF-8 TEXT is refused instead of silently replaced. The exact reference OperationalError decoding diagnostic remains blocked.
- Engine options and execution options beyond `no_parameters`/`stream_results` and first-statement `isolation_level=AUTOCOMMIT`, complete driver error taxonomy/parameter formatting, lock retry timing, hard aggregate WASM memory accounting, same-thread asynchronous cancellation during one synchronous step and arbitrary query coverage remain unqualified. Other isolation levels and isolation changes after a prior query are named refusals. The AUTOCOMMIT DML path is compared to frozen pysqlite effects in `sql2csv-reference.json` using the actual WASM/memfs binding; see `sql2csv.md`. A real SQLite engine is not proof of the remaining contracts.

The remaining suite-wide blockers (including Python interaction and optional format/codec/locale profiles) are not resolved by this binding. Package README publication still needs user permission. No commits, pushes or releases are part of this work.
