Reference: csvkit 2.2.0 archive SHA-256 `147318a8dbaec07c0bbb9291c14b78de5fa32ed3d4a5c2396e52a83c0a30df6b`, Agate 1.14.2 archive SHA-256 `7f29841c39d84b1de7fde762b8d792085371515324f3a01413b20f810398225b`, existing frozen reference profiles. The new native cohort binds CPython 3.14.2 executable SHA-256 `3d6400b63b150164e89a690d9813af8b0eb420af9f336ef1f6c5102c6da60eae`, SQLAlchemy 2.0.54 and Babel 2.18.0, with the exact minimal environment recorded in the reference JSON. The existing CPython 3.9.6 reference profile is preserved; this cohort does not qualify it.

## Census boundary

`docs/csvkit/csvpy-public-object-census.json` contains 270 immediate public namespace entries across nine modules, 61 Agate classes with 2,207 public/inherited/protocol member records, and definitions/signatures/hashes from all 100 Python source files in the authenticated Agate archive. It records defaults, representative preloaded and returned object types, and source locations. Native `csvkit.cli` is imported before the census, as in csvpy. It does not install the optional Excel/DBF/SQL monkey patches on Table in this source path; importing their libraries would require separate guest implementation and qualification. Installed plugin versions in the census are reference provenance, not a claim that their Table methods were injected.

The source csvpy `code.interact` locals contain only the actual reader or table. The console can import Agate and reach all its root exports, CSV/config/exception objects, computations, aggregations, types, warnings and utilities. Public imported modules and method return values expand this namespace beyond Agate into collections, decimal, datetime, Babel, leather, unittest, warnings and other standard-library APIs. Immediate-name/class census is finite; arbitrary transitive Python import closure is not. Those external APIs and dynamically imported plugin namespaces remain explicit blockers. Census signatures and native repr samples do not certify implementations. Address-bearing native representations are raw acquisition evidence, not stable guest expectations.

## Measured scoped reader support

Actual interpreter evaluation covers Reader iteration/next/exhaustion, physical multiline progress, raw-reader forwarding, dialect attributes/read-only assignment, mutable header/line-number behavior, dictionaries with duplicate/missing/extra cells, mutable fieldnames/restkey/restval, blank-record skipping, generator exhaustion, Python printing/imports and config mutation/isolation. Five selected frozen transcripts compare exact stdout, stderr and status. VFS/stdio and budgets are injected; retained guest containers and modules belong to the session. Guest code never receives arbitrary host JS table objects, streams, filesystem or database handles.

`FieldSizeLimitError` inherits Exception, not ValueError. Its constructor accepts `(limit, line_number)`. Numeric CSV conversion raises ValueError inside the guest. Both facts have original failing regressions. DictReader's fieldnames getter always updates line_num from its raw reader, so a returned row after blanks reflects that row's physical line. Blank-only exhaustion retains the initial skipped-row counter until later fieldnames access. Earlier regression assertions and documentation claiming that a successful row retains the first skipped line were incorrect; native evidence and corrected canonical regressions supersede that claim.

`agate.csv.reader` is a function returning a Reader, not a class suitable as isinstance's second argument. The guest retains this function/class distinction. `agate.csv` is also registered as a scoped import alias for existing bridge consumers; the source package's ordinary root attribute points to `agate.csv_py3`, and direct `import agate.csv` is not a native source promise. The earlier fabricated `agate.csv.Error` export has been removed following a failing native differential: native code accesses `agate.csv.csv.Error` or `csv.Error`. The scoped import alias does not certify the rest of the CSV API.

## Blocking library work

All census entries retain a conservative BLOCKED complete-API qualification. Selected reader/config expressions above do not clear a whole class or module.

- Agate Table, Row, Column, MappedSequence, TableSet and their constructors are absent as maintained guest libraries. Typed row/column indexing, names/types, immutability, bool-versus-int indexing, mapping iteration/items/dict/get, sequence equality/repr, row names and column value variants remain blocked. Table mode returns status 78 without an explicitly injected qualified object-library capability. A parser export or seeded table does not satisfy this boundary.
- All Table transformations and calculations remain blocked: aggregate, bins, compute, denormalize, distinct, exclude, find, group_by, homogenize, join, limit, merge, normalize, order_by, pivot, rename, select and where. TableSet's corresponding APIs, having/count/key properties and nested result types remain blocked.
- Table constructors/converters/printing/charts remain blocked: from_csv/from_fixed/from_json/from_object, to_csv/to_json, print_csv/print_json/print_table/print_structure/print_html/print_bars and chart/scatterplot methods. The native table transcript is reference-only. Output stream defaults bound at import time require explicit capture streams and cannot be silently counted as captured prints. VFS and network effects must use explicit capabilities; SQL/Excel/DBF plugin methods need separate admission.
- DataType/TypeTester, Boolean/Text/Number/Date/DateTime/TimeDelta public construction/casting/testing and formatting, Decimal contexts/arithmetic/signals/representations, temporal objects and locale behavior remain blocked as guest APIs. JavaScript CLI inference does not qualify any of these objects.
- Every aggregation/computation, warning helper, public utility and AgateTestCase API in the census remains blocked pending a complete implementation and semantic/error/effect qualification. Public foreign-module objects are not granted implicitly.
- Scoped CSV classes construct only preloaded capability-backed objects. Public arbitrary-file/iterable Reader/DictReader construction, raw CSV reader repr/type identity, Writer/DictWriter, Sniffer, csv dialect registration and field-size mutation APIs, and descriptor deletion/slots fidelity remain blocked. There is no general stdlib csv implementation. Session-local config is an isolation policy, not CPython process-global equivalence.
- After a parse/conversion/field-size exception, the underlying JavaScript generator closes. CPython's reader can consume later physical rows; recovery and exact post-error line_num/EOF progression remain blocked. Selected success/exhaustion tests do not clear this mismatch.

## Blocking console work

Exact CPython library traceback frames, exception chaining/diagnostic arbitration, imported code/codeop/traceback, future-feature compiler state, configurable sys.displayhook, arbitrary multiline interaction, nested asynchronous input and KeyboardInterrupt recovery remain blocked. The synchronous interpreter buffers guest output and drains it through awaited sinks between inputs; it cannot await sink backpressure within one Python call. File transport/decoding is buffered before console construction, so live CPython file timing and memory behavior are unmatched. Cancellation/registered cooperative cleanup remain implemented but cannot preempt opaque host services. Optional legacy IPython imports require a distinct injected library/profile and are not substituted with the scoped console.
