# csvsql 2.2.0 source contract

Target: the literal `csvkit.utilities.csvsql.CSVSQL` executable from the hash-pinned 2.2.0 source archive. The implementation lives in `packages/csvkit/src/commands/csvsql.ts`; its descriptor is consumed directly by the common argv/SDK engine and existing Safe Bash command family. All fourteen original executable names remain unchanged. There is no product subprocess, implicit database driver or Python fallback.

## Arguments and validation

The independently asserted argument inventory includes FILE (`*`), all source-declared local options and precisely the inherited flags surviving `override_flags = ['f']`. `-i` means SQL dialect, `-I` disables inference and `-y` controls sniffing. There is no `-f`, `--output`, column selector or `--execution-option`. Engine options append two arguments; queries and INSERT prefixes append one; before/after hooks and the other local settings store their last occurrence. SDK settings use the actual argparse destination names and the same operation.

Validation follows source order: terminal stdin without a file; dialect versus database/query; insert without database/query; no-create, checkfirst and overwrite without insert; overwrite with no-create; before/after hooks and truthy chunk-size without insert; no-create with checkfirst. Query without a database selects `sqlite:///:memory:` and enables insertion. Empty/zero values retain Python truthiness, rather than gaining unsolicited positive-size validations.

Engine-option conversion uses the shared work-bounded Python literal parser. Qualified scalars, nested lists, frozen tuples, sets and typed dictionaries are supported, including Python key equality and duplicate option/dictionary-key precedence. Qualified AST ValueError expressions retain their original raw string without evaluation, and measured SyntaxError diagnostics retain their native status/detail. Bytes, complex numbers, unhashable-key TypeError, named/unknown string escapes, unmeasured malformed syntax and other AST expressions remain explicit qualification blockers. See docs/specs/csvkit-database-providers.md and the frozen container/syntax observations.

## Tables, queries and output

Database connection and transaction begin precede CSV consumption. A table name comes from the corresponding comma-separated `--tables` entry, otherwise the POSIX basename with only its outer extension removed, or `stdin`. Tables without data rows are skipped, consuming their positional table name but running neither hooks nor DDL. Column inference, CSV reading and deployment-qualified warnings use the common Agate-profile engine.

Before hooks run once per nonempty table, before DDL; after hooks run once after table creation/insertion. Both split naively and execute even empty segments. Queries first resolve all existing filenames, decode them with the frozen UTF-8 locale profile and universal newlines, then split naively using `--sql-delimiter`. Blank query segments are skipped; other segments retain their original whitespace. Splitting deliberately occurs inside SQL strings and comments. An empty SQL delimiter raises the native ValueError.

Combined overwrite and create-if-not-exists reflect separately for DROP and CREATE. Skipped CREATE does not compile DDL, including dialect length restrictions; missing unique-column metadata still fails before reflection or schema compilation. Empty table identifiers retain the frozen IndexError when compiled. Zero INSERT batches compile no unused identifiers or driver bindings and still run after-insert hooks.

Only the final executed query determines output. If it returns no rows, earlier query results produce no CSV. A row-returning final query writes its header and every returned row, with common BOM and writer line-number behavior. A whitespace-only query list produces the source NoneType error. `-H` concerns input headers and does not suppress query output headers.

Schema-only execution emits CREATE TABLE text, never INSERT statements. It supports the five released dialects, inferred numeric precision/scale, dialect text and datetime types, nullability and unique constraints. Source schema-only execution ignores min-col-len and col-len-multiplier. Connected MySQL compilation applies its TEXT threshold to multiplied observed length before applying the minimum. Integer chunk/length controls retain Python-sized arithmetic. SQL identifier quoting follows the frozen SQLAlchemy/CPython profile, including Unicode quoting, re.I special letters and the final-LF anchor behavior.

## Explicit capabilities and cleanup

`CsvkitFileSystem.exists` optionally supplies native path-existence semantics without opening literal SQL. Safe Bash binds this through virtual filesystem stat, suppressing filesystem path errors while preserving cancellation. Without this optional method the SDK probes readFile and treats ENOENT/ENOTDIR as literal SQL; existence/read races require the explicit existence capability for native error fidelity. Query-file bytes share the CSV input budget and become owned bytes before asynchronous decoding.

A host explicitly supplies DatabaseProvider.connect. DatabaseSession optionally supplies dialect identity, hasTable for checkfirst/overwrite reflection, and executeMany for actual driver batches. Without executeMany, SQLite bound rows execute individually inside the same transaction; successful SQLite database effects are differentially checked, while batch failure diagnostics require a qualified driver binding. Declarative dialect descriptors supply DDL metadata, placeholders and their qualified bind processor, so adding a dialect does not add command branches keyed to a provider name.

SQLite binds cover text/null, Boolean integers, Number floats, dates, datetimes and epoch-based intervals within years 1–9999. DatabaseResult rows accept DatabaseCell values; tagged float cells preserve Python repr, including integral floats and signed zero. Hosts must preserve driver scalar types and supply qualified driver diagnostics. Binary-value output uses CPython bytes representation in both SQL CSV commands. The explicitly bound SQLite WASM engine, VFS and remaining SQL blockers are specified in `docs/specs/csvkit-sqlite.md`. Inherited CSV quoting modes 2/4/5 remain blocked by the common string-reader qualification boundary; missing compression/codecs, warning deployment identities and unsupported locale/temporal profiles retain their existing explicit blockers. Non-SQLite INSERT driver profiles and deployed non-SQLite databases remain explicit blockers. Unknown DDL metadata does not prevent query-only execution over empty input.

Resource enrollment precedes connect, query/result and iterator acquisition. Cleanup is idempotent, requests cooperative iterator return immediately and waits for both return and any pending next read before closing results or disposing the session. Iterator return can unblock a pending read; an immediately completed return does not establish that the read has settled. Begin, commit and reflection are tracked through the same resource scope. Transaction commit follows successful output; failure/cancellation rolls back unless an admitted commit actually succeeded. Backpressure is awaited. Original cancellation and falsey driver failures are preserved. Verbose Python traceback fidelity still requires qualified reference frames; it is not inferred from a JavaScript stack.
