# in2csv GeoJSON converter contract

Target: csvkit 2.2.0 source archive SHA-256 `147318a8dbaec07c0bbb9291c14b78de5fa32ed3d4a5c2396e52a83c0a30df6b`, `csvkit/convert/geojs.py:geojson2csv`. The runtime/dependency/locale reference is frozen in `docs/csvkit/reference-profile.json`. New measurements use its CPython 3.14.2 profile, not an assumed inverse of csvjson.

`in2csv -f geojson` requires an object root, a top-level type equal to FeatureCollection and a features key, in that validation order. It does not import arbitrary Feature/geometry roots, expand property paths or infer the format from a .geojson extension. Features are traversed in source order. Header columns are id, the union of first-seen property names, geojson, type, longitude, latitude. Reserved property names remain separate duplicate header columns. Missing IDs/properties and explicit null cell values remain blank; explicit null properties objects fail when their keys are accessed. Feature type is not independently validated.

Each geometry cell uses Python json.dumps defaults: insertion order, comma/colon spaces, ASCII Unicode escapes and JSON non-finite spelling. Geometry null produces the literal null cell; false/empty geometry retains its JSON representation and has absent type/coordinates. Point coordinates use their first two values, dropping altitude; missing coordinates and non-Point geometry yield absent longitude/latitude. Measured malformed features/geometry and coordinate slicing/unpacking failures preserve exact Python diagnostics.

Only an ordered object directly in a property cell is JSON-dumped. Lists use Python list representation, including nested OrderedDict representation, booleans and None. Objects in feature IDs, geometry type and coordinate cells also use OrderedDict representation. Raw floating scalar/list cells spell nan/inf/-inf, whereas JSON cells spell NaN/Infinity/-Infinity; overflowing JSON float tokens follow CPython float conversion. Integers retain their exact lexical value with negative integer zero normalized to zero.

This returns raw CSV, without Agate table inference or header normalization. Frozen evidence confirms ignored `-I`, `-k`, `-l`, `-H`, `-K`, `-y`, locale/date/datetime/leading-zero/null settings, delimiter/quote/escape/space flags and the tested workbook selection flags. These flags are still parsed and validated by the shared original argv grammar. Input encoding remains active; the shared outer writer applies `--add-bom`. `-n` and `--write-sheets` retain the separate executable dispatch behavior documented in in2csv.md.

Product code uses only injected input/output/filesystem capabilities, shares the CLI/SDK engine and awaits output backpressure. Registered cooperative cleanup precedes source acquisition; cancellation and producer ownership stay with the common runtime. Existing budgets may explicitly refuse oversized inputs. Unpaired surrogates, arbitrary deep JSON, exhaustive CPython floating shortest-digit ties, verbose traceback identity and the broader suite's network/database/interactive qualification remain explicit blockers, not passes.
