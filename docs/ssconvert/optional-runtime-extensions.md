# Trusted JavaScript optional providers

`EngineConfig.runtimeFunctions` registers invocation-owner-supplied JavaScript ports. The same config is accepted by safe-bash `ssconvertCommands`; command calculations and direct SDK conversions use the same engine and evaluator. No ambient plugin discovery, native module loading, source-language subprocess or native fallback is introduced.

Import `RuntimeFunction`, `RuntimeFunctions`, `snapshotRuntimeFunctions`, `perlSampleFunctions` and `pythonSampleFunctions` from the ssconvert public entry. Explicitly provide `runtimeFunctions: { ...perlSampleFunctions, ...pythonSampleFunctions }` to enable PERL_ADDER, PY_BITAND and the partial PY_CAPWORDS port. PY_CAPWORDS implements ASCII whole-word capitalization and Python ASCII whitespace splitting, including U+001C–U+001F. Punctuation does not start a new word; a digit at the start keeps subsequent letters lowercase. Non-ASCII input throws an explicit unsupported-feature execution error until Python-version-specific Unicode tables are qualified. These objects are partial sample ports; they do not enable or implement the remaining sample functions or the original loaders. Activated native sample comparisons remain unresolved.

A provider maps canonical uppercase function names to `{ signature, implementation(args, host) }`. Signatures accept `f`, `s`, `b`, `E`, `r`, `A`, `?` and one optional `|` separator in the shared typed argument convention. `snapshotRuntimeFunctions` validates and freezes a registration; the engine and virtual command also capture registrations at construction. The evaluator applies its existing argument evaluation, coercion, error propagation and array iteration before calling the implementation. Ports return a scalar CellValue; the engine validates, copies and bounds it using workbook admission. Built-in/intrinsic collisions are rejected rather than replaced. Registration is snapshotted; functions are not discovered from workbook input. Namespaces belong to the configured engine/invocation and are not process-global. Cancellation/work admission occurs before and after calls; providers must cooperate with `host.tick()` inside loops and explicitly respect `host.context.signal`.

The host object exposes the current workbook, evaluation position and explicit capabilities. Providers are **trusted host JavaScript**, not an untrusted-code sandbox: a supplied closure can access whatever its author captures, block without ticking or modify host-visible data. The owner must supply cooperative, deterministic, invocation/realm-owned implementations and explicit mocked or replay-compatible external capabilities. This contract does not make arbitrary third-party JS safe or replayable. No global registry, clock, filesystem, network, interpreter or configuration is granted implicitly.

Workbook format extensions use the existing explicit `EngineConfig.codecs` registry; these are distinct from formula functions. Stateful data sources, arrays, loader lifecycle, dependency watchers, diagnostic streams and environment effects require specific capability ports and qualification beyond this scalar function contract. GOffice rendering/plot/image/component extensions also require explicit JS ports through the appropriate rendering/service APIs. A native/Python/Perl/Guile plugin must be ported; its module name is not accepted as a provider. There is no finite predeclared feature list for arbitrary external plugins.

The pinned source census, finite profile definitions and unresolved capabilities are recorded in optional-runtime-extension-coverage.json and reference-profile.json. Profiles are specifications until exact optional activation, dependency identities and command differential observations are captured. Implemented unit behavior is not matching-profile native coverage or full parity. The Python glossary is a file saver, not GUI-only; Excel's shipped plugin manifest contains format services, while the commented excelplugins build entry has no shipped service manifest. GUI service declarations alone do not qualify module initialization as having no command effect. Guile's configure block is disabled in the release, while external Guile ports remain an open extension boundary.
