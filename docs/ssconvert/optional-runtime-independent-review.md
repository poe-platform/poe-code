# Independent optional runtime review

The independent reviewer inspected runtime registration, argument dispatch and evaluator admission. Thirteen provider/runtime tests and the author's separate absent-provider regression ran freshly with Vitest; all fourteen passed. The maintained package lint route passed, including source and test TypeScript checks. No native utilities, filesystem fixtures, LLM calls or host module loaders were used.

Two current defects were reproduced with failing assertions before repairs:

- `Object.entries` and direct definition reads executed provider accessors during snapshot. Registration now admits own data properties using property descriptors and rejects accessor or inherited definition members without invoking getters. Inherited provider entries remain absent from the namespace.
- SUM was accepted as an extension although the evaluator owns its intrinsic implementation and would ignore the extension. Registration now also reserves SUM, PRODUCT and GNUMERIC_VERSION, whose evaluator implementations do not appear in the descriptor table.

Passing stress cases verify immutable provider-definition capture, owned returned scalar records, rejection of undefined/Promise/matrix/wrong-type scalar results, post-provider cancellation preserving the original abort error, and cooperative workbook-work exhaustion. A shared SDK engine case verifies provider capture before injected byte I/O despite later caller mutation, with exact output bytes, zero exit status and empty diagnostics. Existing provider cases verify arithmetic, optional typed coercion, arity diagnostics and delegated BITAND behavior above 32 bits.

Additional independent stress of the author's absent-function repair verifies #NAME? for custom and prototype-like names, no optional namespace leakage between invocations, IF short-circuiting, IFERROR/IFNA error selection and SUM propagation. GNUMERIC_VERSION stays callable and RAND still requires its injected capability. Zero-work budget and pre-abort checks still fail execution. The parent's captured native absent-loader control is not activated-loader coverage; no Perl/Python activation is inferred from matching absent-profile cell errors.

Final provider stress covers the author's source-validated Perl boolean conversion repair, including TRUE/FALSE, blank references, negative/fractional addition, numeric-string coercion and overflow. Both sample functions preserve left/right division errors, bad-text errors and too-few/too-many argument errors. PY_BITAND additionally preserves typed boolean/blank/numeric-text conversion, fractional truncation and negative-input errors. These are source/JavaScript contract assertions; activated loader oracle comparisons remain unresolved.

This is JavaScript contract coverage, not native optional-module oracle coverage. The providers are trusted synchronous cooperative host JavaScript, not a sandbox or interpreter for arbitrary third-party code. A malicious provider can close over external capabilities or never return; registration cannot revoke those capabilities or forcibly preempt its execution. No realm isolation, native loader compatibility or replay certification is inferred. Other source-shipped optional services remain unresolved according to the reference profile; the two sample providers do not establish complete Perl/Python parity.
