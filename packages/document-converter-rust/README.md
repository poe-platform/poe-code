# Rust document conversion

This package maps the existing Pandoc document AST and semantic HTML into the shared Rust document AST, then delegates serialization to `docx-ast-rust` or `pdf-ast-rust`. It does not read files, fetch URLs, execute processes, or install fonts. The host supplies resolved image/font bytes. The JavaScript Pandoc Session retains ownership of parsing, filtering, resource resolution, cancellation, and publication.

Rust callers can use `html::from_html` or `map_pandoc` directly with the existing MCP JSON value and supplied resource map. Safe Bash uses this same HTML parser and adapter; its `document` exports remain available for compatibility. Native callers can disable the default `wasm-abi` feature to omit the converter's `document_*` C exports. The converter does not depend on the shell runtime.

`convert({mode: "pandoc", format: "docx", document, resources, options, limits})` uses the bundled WebAssembly module. `createConverter(loadWasm)` accepts a host-provided module loader and is also available as plain `src/runtime.js` for browser workers. HTML requests use `{mode: "html", format, html, title}`. Results contain `bytes`, structured `diagnostics`, and resource `usage`; failures carry the existing Pandoc error code.

Build with `npm run build --workspace=@poe-code/document-converter-rust`; run the converter, all four document engine crates, and JavaScript runtime tests with `npm run test:unit --workspace=@poe-code/document-converter-rust`. JavaScript integration tests live with the existing Pandoc command. The exported C ABI accepts a little-endian JSON length followed by JSON and binary resources. Resources carry checked offsets into that binary tail; no WASI imports are required. The `document_start` / `document_step` / `document_result` ABI polls a cooperative Rust future; cancellation drops that future and its allocations. `convert(request, {signal, cooperate})` accepts an optional host checkpoint and still advances the event loop so timer-driven cancellation can be observed.

Supplied resource and font copies honor their limits before allocation, including repeated or overlapping ranges in the binary tail.

HTML footnotes have a separate string admission ceiling: 64 MiB for converter entry points; the native HTML reader also applies its shell memory limit when lower. Before copying styles, the note index checks live inherited style strings, retained definition styles and temporary href replacements. Before expanding references, it checks indexed styles plus expanded text and each note-body text, image or checkbox's retained style strings. This conservatively counts text nodes before adjacent runs merge; removed definition backlinks do not count. These checks do not redefine `retainedBytes` or represent a total heap/RSS cap.

The Pandoc and native CLI layout profile uses 12 pt text with 1.2 line height. Direct HTML conversion, including editor exports, uses 12 pt with 1.65 line height.

Extensions should lower their custom Markdown nodes through the existing Pandoc filter/writer registry before this adapter, or target the public shared document AST in Rust. Word-specific constructs belong in `docx-ast-rust`; PDF geometry, fonts, layout and serialization belong in `pdf-ast-rust`.

Supported raw HTML inside Pandoc input is lowered by the same Rust HTML adapter as ordinary semantic HTML. Formatting and link scopes can contain typed Markdown inlines; block containers can contain typed lists, tables and notes. Complete HTML tables and preformatted blocks retain their structure, and raw images consume supplied resource bytes. GitHub-style `details` sections preserve their summary and full body in both formats, whether open or closed on screen. HTML character references decode once, including nonbreaking spaces. Unknown elements, malformed scopes and styles the model cannot represent fail explicitly. In particular, raw HTML cannot reset the document's bold heading/header typography or apply custom text styling to a code block. Static page layouts that need browser CSS should be supplied as embedded images by a host export plugin.

Pandoc PDF input supports alphabetic and Roman list numbering, merged cells, and nested tables with rich cell content. Leading table headers repeat; body-section headings and row-header cells retain emphasis without repeating. Row-header columns are counted geometrically across spans. Table spans are validated before layout: row spans must be integers from 1 to 10,000 and column spans from 1 to 1,000. Row-header counts must be integers within the declared columns, and cells cannot straddle the header/data column boundary. Malformed direct requests fail with `E_AST`; the PDF engine additionally limits tables to 64 columns and requires each vertically merged group to fit a printable page. Bidirectional text still requires capabilities beyond the current PDF model.

Pandoc title, subtitle, authors and date render before the body in both formats. Titles are centered and bold, subtitles centered and italic; authors retain their input order. These use ordinary document paragraphs, without adding PDF outline entries. Metadata selection follows Pandoc’s inline-compatible shapes; `visible_metadata` exposes the same selection to native hosts for resource discovery. Images, links and notes in visible metadata use the ordinary document pipeline. Custom or unsupported metadata shapes are not rendered and need no resource reads. HTML-mode `title` remains a descriptive filename/title, without an extra visible paragraph.

Drawing plugins can emit a shared `VectorScene` as a custom Pandoc block `{t: "Vector", c: scene}`. Coordinates use points with a top-left origin. Scenes contain identified groups, paths, positioned text and embedded raster resources; transforms, clipping and opacity remain explicit. Rust validates scene geometry, content limits and image bytes before DOCX/PDF serialization. Legacy JavaScript AST APIs preserve this JSON under their ordinary AST budgets and check its scene envelope; detailed geometry validation occurs at export. JSON preserves Vector blocks, while other legacy text writers reject them explicitly.

`convert({mode: "drawing", format: "mermaid" | "graphviz", source, theme?})` returns `{svg, scene}` from the existing native diagram parser/layout. Both outputs come from the same scene; SVG is output, not an accepted source format. Drawing requests allow up to 1 MiB of UTF-8 source and no resource tail; output is limited to 16 MiB of SVG and 64 MiB of combined JSON. The existing cancellation control and import-free WASM runtime apply to these requests as well.

Drawing `theme` accepts a Safe Bash theme mode or `{mode?, light?, dark?}` token overrides, including typography and colors. Rust validates and applies it before layout. Source configuration overrides host defaults; repeated requests never share mutable theme state.
