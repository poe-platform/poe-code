# @poe-code/mp4-ast

Decoded H.264 frames retain native pixels for `scaleVideoPicture(frame, width, height)`
to resize before RGB conversion. Treat frame buffers as immutable; replaced RGBA
buffers or dimensions make native scaling unavailable.

Portable multimedia container and bitstream AST engine for MP4 (`ISOBMFF`), QuickTime (`MOV`), Fragmented MP4 (`fMP4`), Matroska (`MKV`), WebM (`WebM`), MPEG-TS (`.ts`), AVI (`.avi`), FLV (`.flv`), YUV4MPEG2 (`.y4m`), ADTS AAC (`.aac`), WAV and Sony Wave64 (`wavAst("w64")`, `.w64`), CAF (signed PCM and floating-point audio), AIFF (signed 8/16/24/32-bit PCM), MP3, FLAC, OGG, GIF, SRT, WebVTT, ASS subtitles, and Image sequences. `assAst()` reads subtitle text and cue timing and writes ASS with a default style; custom ASS styles are not retained. Animated GIF parsing, probing, and encoding preserve frame counts and individual frame durations. MP4 probing reports `extradata_size` for H.264 and AAC decoder configurations and `nb_frames` only when the sample table declares a nonzero count; fragmented samples remain available through ffprobe’s `-count_frames` and `-count_packets`.

`scanMp4Boxes({ size, read }, { signal, checkpoint, budget })` lazily emits box ranges using reads of at most 16 bytes, skipping media payloads. It preserves the resident parser's clipping, extended-size, UUID and QuickTime/FullBox metadata rules. Each span includes payload offsets and, for known containers, a `children` range that can be passed as the next scan's options. It scans siblings without collecting a box tree; callers own source lifetime, input admission and any traversal/index backing. The returned UUID bytes are owned. This is a range parser primitive; explicit document APIs still build resident models. Use `probeMp4Source` for native source-backed probe records.

`scanMp4SampleTable(source, tables, options)` replays classic `stbl` sample spans from the box ranges, using at most seven 16 KiB table pages. It preserves timing runs, composition offsets, chunk mappings, clipped payload sizes and subtitle prefixes without collecting timing/chunk/size arrays. For nonempty `stss`, supply a fresh caller-owned `syncSamples` membership index with `add(sample)` and `has(sample)` methods; use external backing for large indexes. The caller owns its cleanup. `signal`, `checkpoint`, `budget` and `type` support cancellation, cooperative execution, existing resource policies and subtitle handling. The resident parser shares this traversal but still collects its explicit document's samples.

`scanMp4Fragment(source, trafChildrenRange, options)` streams fragmented sample spans using one 16 KiB run page. Pass `trackId`, `moofOffset`, `defaults` from the track's `trex`, and optional `{ dts, sampleCount }` state from the last retained classic sample or previous fragment. The generator returns updated state even when an empty fragment only changes its timestamp. It shares run parsing with the resident document API, including signed composition offsets, default fields, keyframe flags and clipped ranges. Headers can occur after runs; two sibling scans avoid retaining a box list. Source lifetime, track/default indexing and staged publication remain caller-owned. Both source sample APIs honor `signal`, `budget` and cooperative `checkpoint` hooks. `probeMp4Source` composes this traversal with native stream and format metadata.

`scanMp4Packets(source, options)` combines classic tables and fragmented runs across tracks without retaining a box tree, track array or sample list. Reads stay within 16 KiB; media payloads are skipped except for subtitle prefixes. Supply `syncSamples(trackIndex)` to create a fresh caller-backed membership index for each track, and retire those indexes yourself. The scanner replays samples to resolve duration limits and subtitle packing before emitting packets. It preserves track ordering, absolute file packet offsets (including interleaved and fragmented samples), edit-list duration checks and subtitle gaps. Spans may precede later validation failures; stage output before publication. Use `probeMp4Source` for stream/format metadata and `scanMp4Frames` below for frame descriptors.

`scanMp4CodecDescriptions(source, stsdRange, options)` yields scalar codec descriptions through bounded source reads, skipping opaque configuration payloads. H.264 interpretation retains only the first SPS (at most 65,535 bytes), read in chunks of at most 16 KiB; other codec headers and ES descriptors use bounded prefixes/pages. Codec interpretation is shared with resident MP4 parsing. The caller owns input admission, lifetime, and publication after validation.

`scanMp4Frames(source, options)` replays native frame descriptors with the same timing, subtitle normalization, dimensions, pixel/sample formats and channel fields as `probeMp4`. Video frames are emitted in presentation order using a memory-budgeted descriptor buffer; packets retain decode order. It shares normalized sample traversal with `scanMp4Packets`, accepts the same per-track caller-owned keyframe indexes and limits, and never decodes media samples. Both probe APIs omit `pict_type`: container sync flags identify keyframes but cannot establish I/P/B picture types. Frame-only and mixed packet/frame ffprobe requests use retained or caller-staged sources with all five writers. Stream/format metadata and counts are available through `probeMp4Source`.

`probeEsdsSource(source, { payloadOffset, payloadSize }, { signal, budget, checkpoint })` reads audio codec metadata from an MP4 `esds` payload with one 16 KiB cache page. It returns object type, sample rate, channel count, bitrates and decoder configuration size, skipping opaque descriptor and decoder payloads. The caller owns input admission and source lifetime. `parseEsds(bytes)` remains the explicit resident API when decoder bytes are needed. The full `probeMp4Source` reader uses this for audio codec properties.

`probeMp4Source(source, { filename, showPackets, showFrames, syncSamples, signal, budget, limits, checkpoint })` returns source-backed streams, format, chapters and optional packet/frame records. It scans track summaries without retaining track/sample arrays, then replays selected records; handler names and format tags stream from the source. Supply fresh caller-backed keyframe indexes through `syncSamples(trackIndex)` and retain their backing and the input until output admission finishes. Stream fields share the resident probe's schema, including duration, bitrate, frame rate, rotation, language and subtitle normalization. Native ffprobe explicit MP4/MOV requests and automatic requests using media-only options use this reader. Automatic strict-audio metadata and readFile-only backends still require separate source adapters.

`probeMp4MetadataSource(source, durationSeconds, { signal, budget, checkpoint })` reads native MP4 format tags as replayable `MediaProbeText` fields and chapters as an asynchronous iterable. Pass the final movie duration to determine the last chapter's end. Brand arrays, tag payloads and chapter lists stay in the caller source; reads and text chunks use at most 16 KiB, with one chapter of lookahead. Tag aliases, duplicate replacement, null suffix trimming, Unicode decoding, and QuickTime/FullBox metadata layouts match the resident probe. Keep the source alive until all selected fields and chapters finish, and stage output before publication. The full `probeMp4Source` reader supplies the final duration and combines these tags/chapters with track aggregates.

A media plugin can implement `probeRecords(source, options)` to return `MediaProbeSourceRecords` with one-shot synchronous or asynchronous stream, chapter, packet and frame iterables. The caller must keep the input alive during enumeration and call the optional `close()` afterward, including when output selection skips sections or enumeration fails. Use `close()` to retire plugin-owned caller-backed indexes; it does not own the input. `ffprobe` prefers this hook over metadata convenience hooks, stages sequential inputs in caller storage when seeking is needed, and finishes record enumeration and cleanup before publishing stdout. Stream, format and chapter tags accept strings or `MediaProbeText` values: `{ kind: "text", chunks() }`. Return bounded string chunks from a synchronous or asynchronous iterable; each invocation must replay identical text because CSV quoting can read twice. Keep field backing alive until result cleanup. Writers preserve split Unicode surrogate pairs and retire active field iterators on early return, cancellation or failure. Native format adapters must opt into these source fields; resident convenience APIs still accept ordinary strings.

For cooperative hosts, `muxMp4Steps` and `sliceMp4Steps` return generators that pause between track/sample batches. Yield to your host event loop and check cancellation before resuming; their final values match the synchronous APIs.

`serializeWav` decodes Ogg Vorbis with page granule timing and final padding. It decodes CBR/VBR MP3 packets with encoder delay and padding trimmed after decoding. It also decodes AAC access units with their decoder configuration and applies MP4 edit lists after decoding priming samples. Missing or corrupt audio and unsupported edit rates fail explicitly. MP3 and AAC inside WAV are decoded using their compressed payloads and WAV codec configuration. WAV probing skips decoded PCM channel arrays. Use `wavAst().parse(bytes, { decodeAudio: false })` or `parseWav(bytes, { decodeAudio: false })` to retain encoded samples without decoding audio; parsing decodes audio by default. Metadata-only probing also skips per-packet sample allocation. Byte-buffer APIs still retain the input. For caller-owned range reads, use `await probeWavSource({ size, read(offset, length) }, { filename, signal })`: it reads headers in requests of at most 16 bytes, skips sample payloads, and returns the same media metadata schema. The caller keeps ownership of the source and closes it. Pass `showPackets` or `showFrames` to either source API for lazy, replayable descriptor iterables; sample payloads are never retained. The byte-buffer probe API keeps its array results. The ffprobe command uses this path for explicit `-f wav` metadata requests on filesystems with retained reads. `probeWavStream(chunks, { filename, signal })` accepts an async iterable of borrowed byte chunks and consumes it once with only a small header buffer, skipping sample payloads. The ffprobe command uses this sequential path for explicit WAV metadata from stdin or streaming filesystems without retained reads.

## Features

- **Lossless MP4 / Multi-Container Merging (`concatMp4`)**: Concatenates multiple videos at the sample/packet level without pixel re-encoding, automatically handling multi-entry `stsd` codec tables (`sample_description_index = 1, 2, ...`) and aligning video/audio durations at segment boundaries. Decoded audio is concatenated at the first segment’s sample rate and channel count, using linear resampling, mono duplication, and averaging when downmixing to mono. `startTimesSeconds` sets segment packet/frame timestamps while retaining decoded PCM in input order. Alignment gaps contain silence; mixing encoded and decoded segments in one audio track requires decoding all segments first.
- **Keyframe & Edit-List Cutting (`sliceMp4`)**: Slices decoded audio at rounded PCM sample boundaries. Trims video and audio tracks by time range (`startSeconds`, `endSeconds`, `durationSeconds`) with `edts`/`elst` edit lists preserving keyframe preroll and the requested playback duration by default. Set `useEditList: false` for sample cutting without preroll (for example, at HLS keyframe boundaries).
- **Track Muxing & Remapping (`muxMp4`)**: Mixes tracks across files, strips audio (`stripAudio`) or video (`stripVideo`), updates display rotation (`0`, `90`, `180`, `270`), and relocates `moov` before `mdat` (`faststart`).
- **Sun AU Audio**: `auAst()` reads and writes AU headers and PCM, floating-point, mu-law, and A-law samples. Output defaults to big-endian PCM16; encoded packet copying is supported.
- **Headerless PCM Audio**: Select a raw format with `createMediaAstRegistry(allMediaAsts()).findByFormatName("s16be")` and call `parse(bytes, { sampleRate: 8000, channels: 1 })`. Signed/unsigned 8-bit, signed 16/24/32-bit, float 32/64-bit, mu-law, and A-law inputs are supported, including both byte orders for multibyte samples. Omitted stream parameters default to 44100 Hz mono.
- **Modular AST Registry (`createMediaAstRegistry`, `allMediaAsts`)**: Pluggable format descriptors consumed by `ffmpeg` and `ffprobe` to dynamically determine which container formats, extensions, demuxers, muxers, and codecs are enabled.
- **Consumer-Defined Resource Limits (`MediaResourceLimits`, `cloudflareWorkerLimits`)**: Imposes zero default restrictions while offering a ready-made Cloudflare Worker limit preset and `MediaBudgetTracker`.

`hlsAst()` and `dashAst()` parse local media playlists using a caller-provided
`resolveResource(uri)` option. The URI is relative to the manifest; return the
referenced file bytes. HLS supports MPEG-TS and fMP4 segments with `EXT-X-MAP`.
DASH supports a static single Period, `SegmentTemplate` (duration or timeline),
`SegmentList`, and `BaseURL`, selecting the first representation per adaptation
set. Missing resources fail rather than producing synthetic streams. Encrypted
HLS, master playlists, and byte-range segments are not supported.

For DASH output, `serializeDashDocument(doc, { segmentDuration: 1 })` splits at the requested duration
(in seconds, default 5), aligning video cuts to keyframes, and returns `{ manifest, resources }`.
Write the manifest and each `resources` entry beside it; the output contains one
initialization file and one complete media fragment per audio/video track.
`dashAst().serialize(doc)` returns only the manifest bytes.
H.264 decoding handles native CAVLC/CABAC streams, reference pictures, delayed B frames, SPS cropping, and color conversion. `decodeH264Samples` yields complete tracks in presentation order; standalone access units can pass their `avcC` configuration to `decodeH264FrameToRgba`.

`mp3Ast().probeMetadata(source)` scans MPEG Layer III frame boundaries using bounded reads. `probeMetadataStream(chunks)` accepts borrowed chunks without retaining audio payloads. Both retain frame descriptors for replay after source closure, with actual packet sizes, positions, counts, and timestamps on FFprobe's 14,112,000 Hz clock. ID3 and Xing/Info/VBRI headers are excluded from audio packets; decoded frame timing accounts for encoder delay and padding. MP3 probing omits undeclared `nb_frames`; scanned counts are available as `nb_read_packets` and `nb_read_frames`. Truncated or invalid MPEG frames fail explicitly.

`flacAst().probeMetadata(source)` scans bounded caller-owned ranges; `probeMetadataStream(chunks)` scans borrowed chunks through EOF. Both validate FLAC frame checksums and report actual packet sizes, timestamps, durations and counts without retaining encoded audio. FLAC probes omit `nb_frames`, which the container does not declare. The caller owns source lifetime and admission limits.

`probeOggFlacSource(source, { filename, signal, checkpoint, showPackets, showFrames })` validates the legacy FLAC-in-Ogg mapping through caller-owned ranges of at most 16 KiB. It retains a 51-byte identification packet and scalar sizes, returns the existing media probe schema, and returns `undefined` for other Ogg codecs. The caller owns source lifetime, limits and optional cooperative checkpoints. `probeOggStreamMetadata(stream, size, options)` formats a validated Opus/Vorbis stream using the existing general-media record schema without retaining sample bytes; callers remain responsible for validating the full container and all logical streams.

FLAC output encodes decoded PCM as lossless 16-bit verbatim frames. Ogg output defaults to Vorbis; `{ audioCodec: "opus" }` selects Opus and `{ audioCodec: "flac" }` selects Ogg FLAC. `.opus` format output defaults to Opus. All write complete audio packets with page checksums and accurate final durations. Encoding requires decoded PCM. The codecs run as static JavaScript in browsers and Workers, without native processes or runtime WebAssembly compilation.
