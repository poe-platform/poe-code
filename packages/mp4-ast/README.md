FFmetadata keys with whitespace before `#` or `;` remain metadata; only markers at the start of a record begin comments. FFmetadata accepts CR, CRLF, and LF record terminators. Uppercase `[CHAPTER]` and `[STREAM]` markers must start at the first byte of a record; trailing text is ignored. FFmetadata exposes each `[STREAM]` section as a data track, including empty sections, in input order. Unedited FFmetadata round trips retain global tag order, including mixed standard/custom tags and integer-like keys. Repeated global and chapter keys match FFmpeg dictionary order: the last tag fills the old slot, and the replacement is appended with its latest spelling and value. FFmetadata chapter parsing rejects zero and negative `TIMEBASE` denominators instead of substituting positive timings. `scanMp4Boxes({ size, read }, { signal, checkpoint, budget })` lazily emits box ranges using reads of at most 16 bytes, skipping media payloads. It preserves the resident parser's clipping, extended-size, UUID and QuickTime/FullBox metadata rules. Each span includes payload offsets and, for known containers, a `children` range that can be passed as the next scan's options. It scans siblings without collecting a box tree; callers own source lifetime, input admission and any traversal/index backing. The returned UUID bytes are owned. This is a range parser primitive; explicit document APIs still build resident models. Use `probeMp4Source` for native source-backed probe records. AMR-NB/WB in 3GP reports native codec names, fixed 8/16 kHz sample rates, mono streams and frames, and zero compressed sample bit depth while preserving `samr`/`sawb` tags.

`scanMp4SampleTable(source, tables, options)` replays classic `stbl` sample spans from the box ranges, using at most seven 16 KiB table pages. It preserves timing runs, composition offsets, chunk mappings, clipped payload sizes and subtitle prefixes without collecting timing/chunk/size arrays. For nonempty `stss`, supply a fresh caller-owned `syncSamples` membership index with `add(sample)` and `has(sample)` methods; use external backing for large indexes. The caller owns its cleanup. `signal`, `checkpoint`, `budget` and `type` support cancellation, cooperative execution, existing resource policies and subtitle handling. The resident parser shares this traversal but still collects its explicit document's samples.

`scanMp4Fragment(source, trafChildrenRange, options)` streams fragmented sample spans using one 16 KiB run page. Pass `trackId`, `moofOffset`, `defaults` from the track's `trex`, and optional `{ dts, sampleCount }` state from the last retained classic sample or previous fragment. The generator returns updated state even when an empty fragment only changes its timestamp. It shares run parsing with the resident document API, including signed composition offsets, default fields, keyframe flags and clipped ranges. Headers can occur after runs; two sibling scans avoid retaining a box list. Source lifetime, track/default indexing and staged publication remain caller-owned. Both source sample APIs honor `signal`, `budget` and cooperative `checkpoint` hooks. `probeMp4Source` composes this traversal with native stream and format metadata. Both probe APIs expose nonidentity MP4 display matrices as nine signed coefficients in ffprobe-formatted `displaymatrix` side data, including translation, scale and reflection matrices with zero rotation. Identity matrices omit the record.

`scanMp4Packets(source, options)` combines classic tables and fragmented runs across tracks without retaining a box tree, track array or sample list. Reads stay within 16 KiB; media payloads are skipped except for subtitle prefixes. Supply `syncSamples(trackIndex)` to create a fresh caller-backed membership index for each track, and retire those indexes yourself. The scanner replays samples to resolve duration limits and subtitle packing before emitting packets. It preserves track ordering, absolute file packet offsets (including interleaved and fragmented samples), edit-list duration checks and subtitle gaps. Spans may precede later validation failures; stage output before publication. Use `probeMp4Source` for stream/format metadata and `scanMp4Frames` below for frame descriptors.

`scanMp4CodecDescriptions(source, stsdRange, options)` yields scalar codec descriptions through bounded source reads, skipping opaque configuration payloads. H.264 interpretation retains only the first SPS (at most 65,535 bytes), read in chunks of at most 16 KiB; other codec headers and ES descriptors use bounded prefixes/pages. Codec interpretation is shared with resident MP4 parsing. The caller owns input admission, lifetime, and publication after validation.

`scanMp4Frames(source, options)` replays native frame descriptors with the same timing, subtitle normalization, dimensions, pixel/sample formats and channel fields as `probeMp4`. Video frames are emitted in presentation order using a memory-budgeted descriptor buffer; packets retain decode order. It shares normalized sample traversal with `scanMp4Packets`, accepts the same per-track caller-owned keyframe indexes and limits, and never decodes media samples. Both probe APIs omit `pict_type`: container sync flags identify keyframes but cannot establish I/P/B picture types. Frame-only and mixed packet/frame ffprobe requests use retained or caller-staged sources with all five writers. Stream/format metadata and counts are available through `probeMp4Source`.

`probeEsdsSource(source, { payloadOffset, payloadSize }, { signal, budget, checkpoint })` reads audio codec metadata from an MP4 `esds` payload with one 16 KiB cache page. It returns object type, sample rate, channel count, bitrates and decoder configuration size, skipping opaque descriptor and decoder payloads. The caller owns input admission and source lifetime. `parseEsds(bytes)` remains the explicit resident API when decoder bytes are needed. The full `probeMp4Source` reader uses this for audio codec properties.

`probeMp4Source(source, { filename, showPackets, showFrames, syncSamples, signal, budget, limits, checkpoint })` returns source-backed streams, format, chapters and optional packet/frame records. It scans track summaries without retaining track/sample arrays, then replays selected records; handler names and format tags stream from the source. Supply fresh caller-backed keyframe indexes through `syncSamples(trackIndex)` and retain their backing and the input until output admission finishes. Stream fields share the resident probe's schema, including duration, bitrate, frame rate, rotation, language and subtitle normalization. Timecode data tracks and video tracks linked through `tref/tmcd` expose the referenced first sample as `tags.timecode`, with drop-frame formatting; the source reader reads only four packet bytes. Native ffprobe explicit MP4/MOV requests and automatic requests using media-only options use this reader. Automatic strict-audio metadata and readFile-only backends still require separate source adapters.

`probeMp4MetadataSource(source, durationSeconds, { signal, budget, checkpoint })` reads native MP4 format tags as strings or replayable `MediaProbeText` fields and chapters as an asynchronous iterable. MP4 parsing, serialization, and both probes preserve `metadata.compilation` as `"0"` or `"1"`; an absent or empty value omits the flag. Pass the final movie duration to determine the last chapter's end. Brand arrays, tag payloads and chapter lists stay in the caller source; reads and text chunks use at most 16 KiB, with one chapter of lookahead. Tag aliases, duplicate replacement, null suffix trimming, Unicode decoding, and QuickTime/FullBox metadata layouts match the resident probe. Keep the source alive until all selected fields and chapters finish, and stage output before publication. The full `probeMp4Source` reader supplies the final duration and combines these tags/chapters with track aggregates.

## Features

- **Lossless MP4 / Multi-Container Merging (`concatMp4`)**: Concatenates multiple videos at the sample/packet level without pixel re-encoding, automatically handling multi-entry `stsd` codec tables (`sample_description_index = 1, 2, ...`) and aligning video/audio durations at segment boundaries. Decoded audio is concatenated at the first segment’s sample rate and channel count, using linear resampling, mono duplication, and averaging when downmixing to mono. `startTimesSeconds` sets segment packet/frame timestamps while retaining decoded PCM in input order. Alignment gaps contain silence; mixing encoded and decoded segments in one audio track requires decoding all segments first.
- **Keyframe & Edit-List Cutting (`sliceMp4`)**: Slices decoded audio at rounded PCM sample boundaries. Trims video and audio tracks by time range (`startSeconds`, `endSeconds`, `durationSeconds`) with `edts`/`elst` edit lists preserving keyframe preroll and the requested playback duration by default. Set `copyAudio: true` to keep the full final compressed audio packet and its playback duration when stream copying. Set `useEditList: false` for sample cutting without preroll (for example, at HLS keyframe boundaries).
- **Track Muxing & Remapping (`muxMp4`)**: Matroska/WebM stream copies retain projection type, pose, and private projection data verbatim. Mixes tracks across files, strips audio (`stripAudio`) or video (`stripVideo`), preserves composed movie and track display matrices, updates display rotation (signed and fractional degrees), and relocates `moov` before `mdat` (`faststart`).
- **IRCAM Audio**: `ircamAst()` reads PCM16 and float32 sound files in either byte order, plus mu-law and A-law, with a 1024-byte header; it writes little-endian PCM16, mu-law, and A-law; `audioCodec: "copy"` preserves encoded samples.
- **Creative Voice Audio**: `vocAst()` reads legacy type-1 PCM8 audio (including type-8 stereo extensions), reads and writes type-9 PCM16 and G.711 audio, and reads type-2 continuation blocks. Input preserves packet offsets and timing, skipping silence, marker and text blocks like FFmpeg. Output defaults to PCM16; stream copying preserves encoded samples.
- **Sun AU Audio**: `auAst()` reads and writes AU headers and PCM, floating-point, mu-law, and A-law samples. Mono G.726 little-endian ADPCM input decodes at 3, 4, or 5 bits per sample. Encode mono 8000 Hz audio with `audioCodec: "g726le"` at 32 kbit/s. Mono G.722 encoding uses `audioCodec: "g722"` (64 kbit/s at 16000 Hz), and G.722 input decodes to PCM. Output defaults to big-endian PCM16; encoded PCM packet copying is supported.
- **Headerless PCM Audio**: Select a raw format with `createMediaAstRegistry(allMediaAsts()).findByFormatName("s16be")` and call `parse(bytes, { sampleRate: 8000, channels: 1 })`. Signed/unsigned 8-bit, signed 16/24/32-bit, float 32/64-bit, mu-law, and A-law inputs are supported, including both byte orders for multibyte samples. Omitted stream parameters default to 44100 Hz mono. Decoding retains complete frames before an incomplete trailing frame; nonempty input without a complete frame fails. Stream copy retains every input byte. Serialize decoded audio to unsigned 16/24/32-bit PCM with the `u16le/be`, `u24le/be`, and `u32le/be` formats; silence uses the unsigned midpoint.
- **Modular AST Registry (`createMediaAstRegistry`, `allMediaAsts`)**: `latmAst()` reads single-program, single-layer AAC-LC LOAS/LATM (mux version 0), decodes audio, and copies original LATM packets. Pluggable format descriptors consumed by `ffmpeg` and `ffprobe` to dynamically determine which container formats, extensions, demuxers, muxers, and codecs are enabled. Matroska/WebM probes expose stereo layout tags and Stereo 3D side data, including eye order.
- **Consumer-Defined Resource Limits (`MediaResourceLimits`, `cloudflareWorkerLimits`)**: Imposes zero default restrictions while offering a ready-made Cloudflare Worker limit preset and `MediaBudgetTracker`.

`hlsAst()` and `dashAst()` parse local media playlists using a caller-provided
`resolveResource(uri)` option. The URI is relative to the manifest; return the
referenced file bytes. HLS supports MPEG-TS and fMP4 segments with `EXT-X-MAP`,
including media and initialization byte ranges and implicit media offsets.
DASH supports a static single Period, `SegmentTemplate` (duration or timeline),
`SegmentList`, and `BaseURL`, selecting the first representation per adaptation
set. Missing resources fail rather than producing synthetic streams. Encrypted
HLS, multi-variant or nested master playlists, and DASH byte-range segments are not supported.
Single-variant HLS master playlists resolve their media playlist and its resources
relative to the containing playlist.

`serializeDashDocument()` also returns `publications()`: iterate its resource batches, write each batch before its manifest, and publish dynamic updates followed by the final static manifest.

Set `mpdProfile: "dvb_dash"` to declare the DVB DASH profile, or `"dash+dvb_dash"` for both DVB and the default ISO live profile.
Set `minPlaybackRate` and/or `maxPlaybackRate` to advertise DASH playback bounds in `ServiceDescription`; the omitted bound defaults to 1. Both accept 0.5–1.5; reversed bounds and the default 1/1 pair omit `PlaybackRate`.
Set `windowSize` to bound each DASH timeline or segment list to its last N segments (`0` retains all), preserving segment numbers and resource references.
H.264/AAC DASH adaptation sets advertise independent segment access and bitstream switching when every representation uses one codec description and starts every segment at a keyframe.
For DASH output, `serializeDashDocument(doc, { segmentDuration: 1 })` splits at the requested duration
(in seconds, default 5), aligning video cuts to keyframes, and returns `{ manifest, resources }`.
VP9 representations declare their profile, level, and bit depth in `codecs` (for example, `vp09.00.10.08`) while preserving the encoded packets.
Audio timelines exclude encoder priming while retaining every packet and the initialization edit list.
Write the manifest and each `resources` entry beside it; the output contains one
initialization file and media fragments per audio/video track. Set
`initSegmentName` and `mediaSegmentName` to customize resource names with DASH
tokens such as `$RepresentationID$`, `$Number%05d$`, and `$ext$` (the selected container extension).
Set `singleFile: true` to write one WebM or indexed MP4 per representation with inclusive initialization and media byte ranges (plus index ranges for MP4); `singleFileName` customizes its name template.
`adaptationSets: "id=0,streams=a id=1,streams=v"` controls set IDs and membership;
stream selectors accept audio/video types or comma-separated output stream indices.
`dashAst().serialize(doc)` returns only the manifest bytes.
H.264 decoding handles native CAVLC/CABAC streams, reference pictures, delayed B frames, SPS cropping, and color conversion. `decodeH264Samples` yields complete tracks in presentation order; standalone access units can pass their `avcC` configuration to `decodeH264FrameToRgba`.

AIFF container bitrates truncate to whole bits per second. Ordinary AIFF has no compression FourCC and probes with a zero codec tag. AIFF probing reports nominal PCM stream bitrates even with no sound samples. AIFF CHAN speaker bitmaps are retained for channel-layout probing and audio downmixing. AIFF probing reports the COMM-declared count as `nb_frames`, separately from read packet/frame counts; a zero declaration leaves `nb_frames` unknown. AIFF serialization preserves title, author (`metadata.custom.author`), copyright and comment in standard text chunks without ID3. AIFF serialization accepts `writeId3v2: true` to embed ID3 metadata and `id3v2Version: 3` or `4` (default `4`); ID3 writing is disabled by default.

`mp3Ast().probeMetadata(source)` scans MPEG Layer III frame boundaries using bounded reads. `probeMetadataStream(chunks)` accepts borrowed chunks without retaining audio payloads. Both retain frame descriptors for replay after source closure, with actual packet sizes, positions, counts, and timestamps on FFprobe's 14,112,000 Hz clock. ID3 and Xing/Info/VBRI headers are excluded from audio packets; decoded frame timing accounts for encoder delay and padding. MP3 probing omits undeclared `nb_frames`; scanned counts are available as `nb_read_packets` and `nb_read_frames`. Truncated or invalid MPEG frames fail explicitly. Pass `writeXing: false` to MP3 serialization to omit Xing and gapless playback metadata.

`flacAst().probeMetadata(source)` scans bounded caller-owned ranges; `probeMetadataStream(chunks)` scans borrowed chunks through EOF. Both validate FLAC frame checksums and report actual packet sizes, timestamps, durations and counts without retaining encoded audio. FLAC probes omit `nb_frames`, which the container does not declare. Named Vorbis-comment chapters (`CHAPTER001` / `CHAPTER001NAME`) are exposed with millisecond timing; the final chapter ends at the STREAMINFO duration. The caller owns source lifetime and admission limits.

`probeOggFlacSource(source, { filename, signal, checkpoint, showPackets, showFrames })` validates the legacy FLAC-in-Ogg mapping through caller-owned ranges of at most 16 KiB. It retains a 51-byte identification packet and scalar sizes, returns the existing media probe schema, and returns `undefined` for other Ogg codecs. The caller owns source lifetime, limits and optional cooperative checkpoints. `probeOggStreamMetadata(stream, size, options)` formats a validated Opus/Vorbis stream using the existing general-media record schema without retaining sample bytes; callers remain responsible for validating the full container and all logical streams.

FLAC `{ exactRiceParameters: 1 }` minimizes Rice residual bit cost; `0` (default) estimates parameters from residual sums. Both preserve exact PCM in FLAC and Ogg FLAC. FLAC `{ minPartitionOrder: 3, maxPartitionOrder: 3 }` bounds Rice residual partitioning (0–8; `-1` selects defaults). An explicit minimum requires an explicit maximum. Short blocks reduce the bounds to valid partitions. FLAC `{ multiDimQuant: 1 }` refines the first-order LPC coefficient against encoded Rice size; `0` disables refinement. Both settings select LPC unless a predictor is explicitly specified. FLAC prediction order bounds are configurable with `minPredictionOrder` and `maxPredictionOrder` (1–32 for LPC, `-1` selects the default); `predictionOrderMethod` accepts `estimation`, `2level`, `4level`, `8level`, `search`, or `log`. FLAC LPC coefficient precision is configurable with `{ lpcCoeffPrecision: 8 }` (1–15 bits; `0` selects the default 15); fixed and verbatim predictors ignore it. FLAC encoding accepts `{ lpcType: "cholesky", lpcPasses: 3 }` for iterative prediction (default: two passes); decoded PCM remains exact, while compressed bytes may differ from native FFmpeg. FLAC parsing exposes compressed packets and decoded PCM for sample-exact trimming; `{ decodeAudio: false }` skips decoding. FLAC encoding accepts `channelMode: "indep"`, `"left_side"`, `"right_side"`, or `"mid_side"` for lossless stereo decorrelation in FLAC and Ogg FLAC. FLAC output accepts `{ writeHeader: false }` to emit only raw audio frames, without the stream marker or metadata blocks. FLAC output encodes decoded PCM as lossless 16-bit or 24-bit frames, preserving input precision. `compressionLevel` accepts 0–12; omitted, `-1`, and `5` produce identical level-5 encoding, with verbatim fallback when smaller. `{ audioCodec: "copy" }` retains selected compressed packets. Ogg output defaults to Vorbis; `{ audioCodec: "opus" }` selects Opus and `{ audioCodec: "flac" }` selects Ogg FLAC. `.opus` format output defaults to Opus. All write complete audio packets with page checksums and accurate final durations. For Opus copy and Opus/Vorbis encoding, `pageDuration` sets the target page duration in microseconds (default `1000000`, `0` disables duration-based flushing), bounded by the Ogg lacing limit. Encoding requires decoded PCM; Ogg-to-Ogg `{ audioCodec: "copy" }` preserves Opus or Vorbis packets and metadata without PCM decoding. Opus stream copy into MP4 preserves decoder configuration, channel mapping, and 48 kHz timing. The codecs run as static JavaScript in browsers and Workers, without native processes or runtime WebAssembly compilation.

VPlayer input accepts a colon, space, or equals sign between the timestamp and dialogue, uses the next timestamp to close each subtitle cue, including empty closing lines, and converts `|` to line breaks. FFmpeg accepts `-f vplayer` or detects the content in generic `.txt` files.

AQTitle input (`-f aqtitle` or automatic detection) converts frame markers at 25 fps by default; `-subfps 50` before the input overrides the rate. Multiline captions are preserved and empty closing markers end the preceding cue. The media parser accepts the same override as `subtitleFrameRate`.

Spruce text STL input requires `-f stl`; colon-separated clocks use hundredths of a second and `|` becomes a line break. Binary EBU STL is not supported.
