# Remote invocation state and recovery

The v1 invocation key is generated by the client and bound to authenticated
principal, session epoch, exact submitted payload and build. Retrying an accepted
create with the same binding attaches to its job; conflicting payloads fail with
409. Transport reconnection never authorizes another native start. Orphaned
durable acceptance cannot restore sandbox attachment and fails with 410.

Durable state events have version 1 and monotonically increasing decimal
sequences. The normal history is accepted, running, process-exited, io-settled.
Accepted and running records precede native launch. Process-exited records a
confirmed native observation independently of output credit. Io-settled requires
complete output channels and owned cleanup; native exit zero alone cannot grant
shell success. Effect receipts retain settled changes independently of native
outcome, including partial writes. Earlier applied changes are not rolled back.
Storage adapters receive independent effect-receipt carriers. Retaining or
mutating a carrier cannot rewrite the server's acknowledged byte count, revision
or settlement observation exposed by later job inspection. This ownership rule
does not restore receipts lost from durable storage or make external writes
transactional with receipt publication.
A launch failure publishes unknown-outcome with its original spawnError observation,
never process-exited or io-settled. This keeps durable inspection available across
reconnect without authorizing another native start. Loss events may retain structured
transport failure or unconfirmed cancellation evidence; neither grants native exit
or I/O settlement authority. A known native exit remains preserved when later
I/O settlement fails.
Unavailable callback admission or effect-receipt publication closes native
admission and wakes waiting callbacks with the original provider cause. Even a
provider TypeError reports unknown transport settlement, rather than invalid
caller input. A settlement retry joins the same failed receipt promise; it never
repeats the canonical operation or assumes that a lost durability reply means
the receipt was not published. Callback admissions bind the session build and
expire with its fixed retention deadline, alongside lifecycle and effect records.

Cancellation request and action are separate observations. Native exit observed
before cancellation acts wins. A returned signal hook establishes an action,
never confirmed process-group termination. If the provider throws, the action
receipt is uncertain: retain the request with cancelActed=false, stop execution
waits and settle as unknown-outcome. Retrying the request does not repeat that
uncertain signal. Cleanup must independently establish native resource retirement.

Only the isolation owner can assert sandbox-lost or unknown-outcome recovery;
a network disconnect alone establishes neither. Retained native outcome,
effect barrier and independently completed output/cleanup observations survive
loss. Explicit actions are inspect, recover-partial-outputs, reauthorize and
start-new-invocation. A new invocation is a newly authorized execution, which may
repeat earlier effects. There is no exactly-once guarantee after sandbox or
durable-state loss.

An attached lifecycle owner checks its acknowledged durable prefix before
publishing another transition. A missing event, a changed last acknowledged
event, or a contradictory prefix closes publication with an unrecoverable
transport result. Inspection cannot present an older
surviving prefix as current state. Complete ledger loss is detectable from this
owner's retained evidence; a fresh owner without that evidence cannot prove an
invocation never ran. Recovery must never turn absence into an exactly-once claim.
Publication also checks the next immutable event slot. If an isolation owner has
advanced the journal, the former execution owner rejects publication with 410
and remains closed, while inspection retains the recovery event. A surviving
acknowledged prefix cannot restore attachment or overwrite the loss decision.
An inspection that detects unrecoverable history loss or contradiction also
permanently retires that owner's writer. Restoring the ledger afterward permits
inspection of surviving evidence, but cannot reopen publication or recovery writes
through the retired owner. Explicit isolation-owner recovery uses a new journal
owner and never launches native execution.

Each durable read is copied before another provider read begins. A provider may
reuse its response carrier; later changes to that carrier cannot invent an effect
barrier, change a native outcome, or corrupt recovery's retained evidence. An
unavailable or uncopyable provider response reports transport uncertainty with
its original cause and does not authorize execution or mutation replay.

Replay retention is bounded by acknowledged frame bytes and session retention.
Job inspection evidence also survives replacement SDK clients when the caller
retains the same session object in this process. Evidence is scoped to the
authenticated service origin. A later receipt cannot retract an observed native
exit, event sequence, invocation binding or completed settlement, including when
an older request completes after a replacement client's final publication.
Reconstructing a session object or losing the process does not restore this local
evidence; durable inspection and explicit recovery remain necessary.
Caller-owned stream cursors advance after the sink accepts a complete frame and
before HTTP acknowledgment. Reconnecting with those same sinks first retries the
acknowledgment and resumes at the next sequence, preserving delivered bytes.
For the same cursor object, delivery evidence survives replacement SDK clients
within the process and remains bound to the issuing HTTPS origin. Reconnecting
that cursor to another origin fails before credential renewal or transport work;
matching opaque session/job/lane IDs do not transfer delivery authority.
Changing its sequence, channel offsets or END observations
returns an unrecoverable transport result before any request; clearing uncertainty
flags cannot authorize replay of a possibly applied sink write. The retained record
also owns active delivery: clearing the public busy flag cannot
admit another consumer, including through a replacement SDK client. Sink callbacks
and credential renewal may yield, but acknowledgments use independently retained
sequence and channel observations. Mutating the public cursor during a callback
cannot erase previously delivered bytes or END observations from that receipt.
The SDK publishes the completed delivery back to the public cursor after the sink
accepts the frame. This evidence is
weakly owned and process-local. Reconstructing a cursor after process/state loss
requires independent delivery evidence and explicit recovery; it does not restore
atomicity between a sink and a persisted cursor.
Interrupted incomplete frames never reach the sink. If a sink rejects after a
possible partial write, automatic replay is unrecoverable and requires explicit
recovery. An expired cursor returns 410 and an unrecoverable transport result;
it never synthesizes missing output or END.

Once a complete frame reaches a sink, the process-local delivery record binds
the cursor to that consumer callback. Reconnect with the same callback and cursor,
including through a replacement SDK client. Switching callbacks after delivery
returns an unrecoverable transport result before credentials, ACK or stream access:
the replacement cannot inherit bytes or END accepted by the original sink. A sink
may be replaced before any complete frame reaches it. Callback identity does not
prove external storage durability or protect against changes inside a callback;
callers must preserve its canonical sink authority across reconnects.

Credential expiry, session retention, execution duration and settlement deadlines
remain independent of polling waits. Renewing credentials cannot revive expired
retention or restore discarded bytes. Provider/transport failure remains distinct
from native tool exit, signal or spawn error. In-memory conformance does not
establish that a deployed provider can restore attachment or terminate every
escaped descendant.

The SDK rejects failed HTTP responses labeled as native outcomes; native outcome
observations belong to job metadata. Authorization failures retain their separate
classification. An output-complete job receipt cannot contradict pending or unknown
cleanup or an included durable journal that has not reached io-settled with both
barriers complete. Such contradictory receipts report transport uncertainty with
the original recovery identity. Failed acknowledgment receipts leave already
delivered bytes and the retained cursor intact for reconnect.

Incomplete reconnect metadata may lead durable publication, but cannot retract
its effect barrier, cancellation request, completed output or completed cleanup.
Such contradictions remain transport uncertainty even when native exit is known.
Within the same SDK client and caller-owned session identity, an already received
live observation is retained independently of journal publication. Later replies
cannot retract or change that native outcome, reduce its effect barrier, clear its
cancellation request, or retract completed output or cleanup. A delayed older
inspection reply is rejected without replacing the retained evidence, including
when both replies carry the same durable sequence. These process-local receipts
do not reconstruct evidence after client or durable-state loss.

When a final receipt includes a durable journal, its outcome and optional native
observation must match the confirmed durable process outcome. Its effect barrier,
retention deadline and cancellation request must also match that settled event.
A final output-complete receipt must explicitly report terminal state, complete
owned cleanup and the versioned durable io-settled event. Missing evidence is
transport uncertainty even when the reported native exit is zero. These server
barriers do not replace the caller's awaited sink writes and delivery cursor.
A contradictory final publication reports transport uncertainty, never a native
tool error or shell success. Inspection of an incomplete lifecycle still preserves
a known native exit alongside unknown output or cleanup settlement.
