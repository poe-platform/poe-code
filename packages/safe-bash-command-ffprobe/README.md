# safe-bash-command-ffprobe

Inspect audio and video with `ffprobeCommands()` from
`@poe-platform/safe-bash/commands/ffprobe` or
`poe-code/safe-bash/commands/ffprobe`.

```sh
ffprobe -v quiet -of json -show_format -show_streams recording.wav
ffprobe -show_entries stream=sample_rate,channels:format=duration -of csv recording.wav
```

Supports `-v quiet|error|warning|info`, `-of` / `-print_format` with
`json`, `compact`, `csv`, `default`, `flat`, `ini`, `xml`; `-show_format`, `-show_streams`,
`-show_error` for structured missing-input errors (with a nonzero exit status),
`-show_entries section=fields` (including format/stream tags and `stream_disposition`), `-select_streams a:0`,
`-sexagesimal` for `H:MM:SS.ffffff` timestamps and durations, and `-i`. Media inputs also support `-show_packets`, `-show_frames`, `-show_chapters`,
`-show_programs`, `-count_frames`, `-count_packets`, and video stream selectors such as `v:0`.
FLAC cover art appears as attached picture streams with image dimensions and `disposition.attached_pic=1`.
Raw and RLE true-color TGA files report the `targa` codec, source dimensions, and `bgr24` or `bgra` pixel format for 24-bit or 32-bit images.
Matroska stream inventories include attachments with filename, MIME type, description and data size, without generating playable packets.
`-unit` appends `byte` to packet sizes and `s` to packet timestamps and durations in seconds. Output without `-unit` is unchanged.

`-show_data` adds WAV, MP3, FLAC and MP4/MOV packet payloads as hexadecimal and ASCII dumps, selectable with `-show_entries packet=data,size`. WAV payloads exclude container headers; retained packet payloads stream through bounded reads, and stdin is staged when data is requested.
`-show_data_hash sha256` adds packet payload checksums, selectable with `-show_entries packet=data_hash,size`. Supported algorithms are `md5`, `sha160`, `sha224`, `sha256`, `sha384`, and `sha512`; hashes exclude container headers and use bounded reads.
Packet scans support `-read_intervals START%END` (comma-separated intervals), relative `+` times, omitted endpoints, and `+#N` packet limits. For example, `-read_intervals '0%+0.4' -show_packets` reads 0.4 seconds from the seek point. Seeking starts at a preceding keyframe; durations start at the packet actually reached. Packet descriptors replay through caller-backed storage with a bounded cache, preserving interleaving and backward seeks. Decoded-frame intervals are not supported.
Selecting `packet` or `frame` with `-show_entries` also requests those records without a separate show flag. Selecting both in JSON emits a single `packets_and_frames` array with a `type` field on each record; selecting only one retains the `packets` or `frames` array.
Local HLS input skips media segments with disallowed file extensions before reading them; disallowed initialization files fail. Use `-allowed_extensions mp4,m4s,txt` to replace the default media extension list, or `ALL` to allow any extension.

Local DASH input tolerates missing media fragments when initialization is available, preserving surviving packet timestamps. Missing initialization files and other read errors still fail.
The audio and ffmpeg plugins share this command implementation. Use `-` or `pipe:0` for stdin. Unknown flags fail explicitly.
Only explicitly selected sections are printed; without section flags or `-show_entries`, JSON output is `{}`. Counting packets or frames does not select output sections. H.264 and AAC in MP4, plus MP3, FLAC, Vorbis and Opus streams expose `mime_codec_string`, also selectable with `-show_entries stream=mime_codec_string`. Audio metadata includes `codec_long_name` and `format_long_name`, also selectable with `-show_entries`. WAV, FLAC and MP3 streams report `time_base`; FLAC and MP3 also report stream `start_pts` and stream/format `start_time`, including MP3 encoder delay when available.
Ogg comments appear in stream tags with their original field names; M4A format tags include container brands. Xing MP3 bitrates include the header frame, matching native ffprobe. Audio format metadata includes `probe_score`, selectable with `-show_entries format=probe_score`; MP3 confidence depends on the number of validated frames.
`-show_optional_fields auto|always|never` controls unavailable stream and format metadata. By default, JSON omits unavailable fields and text writers include placeholders such as `nb_frames=N/A`. Use `always` to include them in JSON or `never` to omit them in text output. Known values are preserved. Matroska/WebM streams omit undeclared `id`, `duration_ts`, `duration` and `nb_frames`; use `-count_frames` and `-count_packets` for read counts, and `-show_format` for the container duration.
XML output uses an `ffprobe` root, collection elements such as `packets`, and attributes such as `<packet size="32"/>`.
Writer options include `nk`, `nw`, `p` and `s` where applicable. INI output uses native section paths and escaping; `ini=h=0` (or `ini=hierarchical=0`) omits the parent collection names.

`createFfprobeCommand`, `createFfprobeCommands`, `FfprobeCommandsOptions` and
`FfprobeLimits` support direct host integration. Defaults: 32 MiB input, 1 MiB output.

Native MP4/MOV inspection uses bounded retained reads or staged sequential input for explicit `-f mp4`/`-f mov` requests and automatic requests using media-only options (packets, frames, chapters, programs or counts). Stream/format metadata, tags, chapters, packet/frame rows and counts share native source scanners; keyframe membership and output use caller-authorized backing with bounded caches. All writers preserve field selection, Unicode metadata, rotation, timing, bitrate and subtitle gaps. H.264 streams report progressive or interlaced field order from sequence and picture-timing metadata, plus `chroma_location`, `is_avc`, `nal_length_size` and `bits_per_raw_sample`; these fields are selectable with `-show_entries`. Handler names and large format tags stream without whole-field buffers. Frame codec properties use bounded header reads; the first H.264 SPS is capped by its 16-bit format length and read in chunks of at most 16 KiB. Input, membership storage and output admission complete before stdout publication. Use external backing for large inputs or outputs. Automatic strict-audio metadata and readFile-only backends retain their existing compatibility paths and still need source adapters.

Custom media plugins can provide `probeRecords(source, options)` with one-shot synchronous or asynchronous stream, chapter, packet and frame records. All writers consume selected records incrementally; JSON supports packet/frame arrays without collecting them first. Retained inputs and staged sequential input stay alive through enumeration. Optional result `close()` retires plugin-owned backing, even when its sections are not selected. Input and plugin cleanup finish before stdout publication, so late source, iterator or cleanup failures publish no partial output. Stream, format and chapter tags can return replayable `{ kind: "text", chunks() }` values, allowing large text fields to stream through all writers with bounded escaping. Each call must return identical text in bounded chunks; CSV may replay a field to decide quoting. Unselected fields are never read. Keep field backing alive until result cleanup. Native MP4 source metadata uses the same field representation.

Inspection uses the supplied virtual filesystem and never spawns native tools. Explicit FLAC probes (`-f flac`) use bounded header reads on retained filesystems and discard encoded audio incrementally on stdin or streaming filesystems, including packet/frame and count requests. Input limits apply to the full logical size and input closes before output. Automatic FLAC requests with media-only options (packets, frames, counts, chapters/programs or extended writer options) use the same bounded probes after signature detection. Strict automatic FLAC metadata and tags use the retained source probe and caller-backed key/value indexes. Sequential input stages in caller backing with a 64 KiB cache. Keys and values stream through all writers, preserving Unicode case normalization, aliases, duplicate joining within blocks, replacement across blocks and numeric-key order. Large inputs, indexes and output require an external backing provider to keep spilled bytes out of Worker memory; source and index backing close before stdout publication.

Explicit MP3 probes (`-f mp3`) and automatic requests using media-only options use bounded retained or sequential input. They preserve the existing fixed-frame media metadata and emit packet/frame records lazily. Sequential probes discard payload bytes; retained probes use source size after admission. Strict automatic MP3 probes also use bounded retained reads or staged sequential input, with a 64 KiB cache and caller-authorized backing. MPEG timing, declared VBR byte rates, ID3v1 ordering, ID3v2 replacement, encodings and unsynchronization are preserved. Tag values and output stream through bounded caches; large input/index/output backing should use an external provider. Input and tag storage stay alive through output admission and close before stdout publication. Malformed strict audio retains the existing general-media fallback; source and backing failures propagate.

Automatic Opus/Vorbis Ogg metadata probes scan checksum-validated pages with bounded reads, storing logical streams, packet spans and tag keys in caller-authorized backing. Retained files, stdin and streaming filesystems preserve chained/multiplexed stream timing, raw comment names and duplicate values across all writers. Large tags and embedded-picture validation stream without collecting payload-sized models. Input and indexes close before stdout publication. Explicit and general-media Opus/Vorbis requests use the same bounded scan and preserve the existing first-stream packet/frame schema. Ogg-FLAC reads checksum-validated pages with at most 16 KiB transfers, retaining only its 51-byte identification packet and scalar sizes; automatic and explicit requests preserve the legacy mapping rules. Sequential Ogg input stages through caller backing before validation. Use an external backing provider for large inputs; readFile-only backends still have buffering paths.

For WAV inspection, `ffprobe -f wav -show_streams recording.wav` uses bounded header reads when the injected filesystem supports retained reads. Input limits still apply to the full logical file size. For stdin (`-`) and streaming filesystems without retained reads, the command scans headers incrementally and discards sample payloads without temporary storage. WAV packet/frame descriptors are generated incrementally. `-show_chapters` reports RIFF cue points and LIST/adtl labels with sample-rate timing. Output uses a bounded cache and caller-authorized filesystem backing before publication, so output-limit failures write no stdout. Large output needs a backing provider with retained read/write handles and conditional removal; memory filesystems keep backing data in RAM.

Automatic WAV metadata probing also uses retained caller reads, preserving the strict audio schema, INFO tags and multiple-data-chunk timing. Strict audio rejection preserves the existing general-media fallback. For stdin and streaming-only filesystems, automatic WAV probes stream into caller-backed storage with a 64 KiB cache, then replay the admitted input through the strict and fallback probes. Large inputs require retained read/write backing and conditional removal; an external backend keeps spilled data out of Worker memory. Input limits and source errors are resolved before output, and the backing is closed before publication. INFO keys and value spans use a caller-backed index, preserving duplicate replacement and numeric-key ordering. All writers replay UTF-8 values and emit bounded fragments, including quoting and trailing-whitespace removal. Source and tag backing remain open until output admission finishes, then close before publication. Automatic WAV requests using media-only options (including packets, frames, counts and extended writer options) use the same bounded general-media scanner as explicit WAV requests. Sequential media-only probes discard sample payloads without input backing. Other automatic formats and readFile-only backends still have buffering paths.
