# safe-bash-command-ffprobe

Inspect audio and video, including NUT PCM audio and RGB/BGR video packets, with `ffprobeCommands()` from
`@poe-platform/safe-bash/commands/ffprobe` or
`poe-code/safe-bash/commands/ffprobe`.

```sh
ffprobe -v quiet -of json -show_format -show_streams recording.wav
ffprobe -show_entries stream=sample_rate,channels:format=duration -of csv recording.wav
```

CAF inputs on stdin omit file size and report duration only when a packet table precedes audio data; named files retain seekable duration and size.

Supports `-v quiet|error|warning|info`, `-of` / `-print_format` with
`json`, `compact`, `csv`, `default`, `flat`, `ini`, `xml` (compact/CSV `s` and `item_sep` separators must be exactly one UTF-8 byte); `-show_format`, `-show_streams`,
`-show_error` for structured missing-input errors (with a nonzero exit status),
`-show_entries section=fields` (including format/stream tags, `stream_disposition`, and `stream_side_data=rotation`), `-select_streams a:0` (decimal, hexadecimal `a:0x1`, and octal `a:01` ordinals; compose type and metadata filters with `a:m:title:Bob` or `a:m:language:fra`, or MPEG-TS programs such as `p:202` (also `p:0312`, `p:0xca`, and `p:+202`) or `p:202:a:0` (first audio stream within program 202), or stream IDs such as `i:77` and `#0x4d` (also octal `#0401` and signed `i:+257` or `#-1`)),
`-sexagesimal` for `H:MM:SS.ffffff` timestamps and durations, and `-i`. Media inputs also support `-show_packets`, `-show_frames`, `-show_chapters`,
`-show_programs` (MPEG-TS program membership and service tags), `-count_frames`, `-count_packets`, and video stream selectors such as `v:0`. Uppercase `V` and `V:N` exclude attached pictures and video thumbnails before counting video stream ordinals; lowercase `v` includes them. A trailing colon in `a:`, `v:`, `s:`, or `d:` selects all streams of that type. `-select_streams u` selects streams with a known codec and usable configuration: audio needs a sample rate, channels and sample format; video needs dimensions and a pixel format. Configured subtitles, data and attachments also qualify. Combine usability with type filters, such as `a:u` for usable audio streams or `t:u` for usable attachments; the same selection applies to packets. Data stream selectors `d` and `d:N` select MP4 timecode streams and packets, returning an empty list when no stream matches.
`-of json=c=1` (or `json=compact=1`) preserves native JSON section and array line breaks, with scalar fields on one line per row and nested tags on their own line.
Repeated `-show_entries` selections accumulate fields within each section, including tags; a later empty assignment preserves earlier selections.
JSON chapter reports honor `-show_entries chapter=id` and other selected chapter fields; use `chapter_tags=title` to select a tag alongside them. `-show_chapters` without a selection reports complete chapters. WAV cues without labels omit title tags; explicitly empty labels retain an empty title.
ADTS packet `pos`/`size` and frame `pkt_pos`/`pkt_size` describe physical frames, including their headers.
Y4M packet positions, `-show_data` dumps and `-show_data_hash` hashes cover the original YUV payloads, excluding stream headers and frame tags.
Y4M file duration is estimated from file size; frame tags can increase it without adding frames. `nb_frames` is omitted; `-count_frames` and `-count_packets` report actual counts.
`concatf:parts.txt` probes newline-listed local files as one seekable byte stream; relative entries resolve from the working directory. Concat manifests support `-f concat` (or the `ffconcat version 1.0` header), with per-file `duration` and packet tags. Add `-segment_time_metadata 1` to expose `lavf.concatdec.start_time` and known `lavf.concatdec.duration` in microseconds on each packet, with Strings Metadata side data. The default (`0`) omits these generated tags.
MP4 `nclx` color tags report stream color range, matrix, transfer and primaries; full-range H.264 reports the corresponding `yuvj` pixel format.
3GP AMR-NB/WB reports `amr_nb`/`amr_wb`, native long names, 8/16 kHz mono audio, mono frames, and `bits_per_sample=0`, preserving the `samr`/`sawb` codec tags.

Raw AAC-LC LOAS/LATM inputs report format `loas`, codec `aac_latm`, sample rate and channels, with complete packet bytes available for dumps and hashes from files or stdin. AAC trailing APE tags expose text metadata such as title and artist, preserving audio packets. MP4/M4A format tags include title, artist, album artist, composer, track/disc numbers and totals, compilation, copyright, and description. MP4 timecode streams retain `codec_type=data` and `codec_tag_string=tmcd`; JSON omits their unavailable `codec_name` and `codec_long_name`. MP4/MOV timecode data tracks and video streams linked to them expose `stream_tags=timecode`, including drop-frame notation. Unlinked video streams omit the timecode tag. MP4 stream language tags decode legacy QuickTime IDs (including `eng`, `fra`, and `ger`) and packed ISO codes. AMR-NB/WB edit lists expose first-packet Skip Samples and trim decoded-frame timestamps, duration, and sample counts without changing packet payloads.
AAC inputs with leading ID3v2 tags retain title and artist metadata and support packet scans from files or stdin.
FLAC and MP4/M4A `covr` cover art appears as attached picture streams with image dimensions and `disposition.attached_pic=1`.
Headerless RGB24 video supports `-f rawvideo -pixel_format rgb24 -video_size WIDTHxHEIGHT -framerate RATE` (default rate: 25; fractions such as `30000/1001` are accepted). Packet scans preserve a final short packet; frame counts include only complete frames. For example, 74 bytes at `3x2` produces four 18-byte packets and one two-byte packet. Files and stdin use the same boundaries. Other raw pixel formats are rejected explicitly. YUV420 Y4M streams report the `I420` codec tag, sample and display aspect ratios, chroma location, field order, and any declared color range.
Raw and RLE true-color TGA files report the `targa` codec, source dimensions, and `bgr24` or `bgra` pixel format for 24-bit or 32-bit images.
QOI images report the `qoi` codec, source dimensions, and `rgb24` or `rgba` according to the file's channel count, including inputs read from stdin.
AU inputs preserve the channel count without inferring a speaker layout. On stdin, AU duration comes only from a known header length; file size is omitted, and format bitrate is reported only for unknown-length audio. NIST SPHERE PCM16 inputs report `nistsphere`, the declared sample rate, channels and sample count, string header tags, and packet positions after the declared header length. AU inputs identify G.722 and G.726 ADPCM streams and report durations from their encoded sample widths without decoding PCM. AU omits undeclared `nb_frames`; `-count_frames` and `-count_packets` report read counts independently. PCM packets target 25 packets per second, capped at 1024 sample frames, with individual timestamps and sizes. AU frames expose `duration`, `duration_time`, and file-relative `pkt_pos` alongside `pkt_duration`.
Matroska video streams report `field_order` from their interlace metadata. Attachment selectors `t` and `t:N` select all attachments or the Nth attachment, returning an empty list when none matches. Matroska stream inventories include attachments with filename, MIME type, description and data size, without generating playable packets. Spherical video streams report equirectangular or cubemap projection, cubemap padding, and signed yaw, pitch and roll in `side_data_list`. Matroska/WebM video streams expose `stereo_mode` tags and Stereo 3D side data with layout and eye order directly from the input; unmarked streams omit both.
`-unit` appends `byte` to packet sizes and `s` to packet timestamps and durations in seconds. Output without `-unit` is unchanged.

`-show_data` also exposes MP4/MOV H.264 and AAC decoder configurations and QuickTime timecode descriptions as `extradata`, selectable with `-show_entries stream=extradata,extradata_size`. `-show_data_hash` exposes their `extradata_hash`; neither field is emitted without its corresponding option.

`-show_data` adds WAV, MP3, FLAC, AIFF, AU, MP4/MOV and standalone WebVTT packet payloads as hexadecimal and ASCII dumps, selectable with `-show_entries packet=data,size`. WebVTT dumps and hashes contain the exact caption bytes, including line breaks, and exclude cue IDs and settings. AIFF PCM stream bitrates use the sample rate, channel count and sample width, even with no sound samples. AIFF container bitrates truncate to whole bits per second. AIFF payloads exclude SSND offset bytes and chunk padding. Piped AIFF input requires `COMM` before `SSND`; filename input accepts either order. AU payloads exclude the header and annotation bytes. AIFF `nb_frames` comes from COMM; `-count_frames` and `-count_packets` report records read independently. Zero counts are unavailable fields, omitted from JSON by default. Ordinary AIFF reports `codec_tag_string=[0][0][0][0]` and `codec_tag=0x0000`. WAV payloads exclude container headers; retained packet payloads stream through bounded reads, and stdin is staged when data is requested.
`-show_data_hash sha256` adds packet payload checksums, selectable with `-show_entries packet=data_hash,size`. Supported algorithms are `md5`, `sha160`, `sha224`, `sha256`, `sha384`, and `sha512`; hashes use native packet bytes (including ADTS headers for AAC) and bounded reads.
Numbered image inputs (`in%d.png`, `in%03d.png`) expand consecutive files with `-f image2` or an image filename extension. Auto-detected single PNG inputs report `png_pipe`; numbered image inputs and explicit `-f image2` report `image2`. Probing searches starting numbers 0–4, stops at the first gap, and timestamps packets at 25 fps by default or the supplied `-framerate`. For numbered or literal image files, `-ts_from_file 1` uses file modification times in whole seconds; `-ts_from_file 2` uses nanosecond ticks derived from filesystem millisecond timestamps. `-ts_from_file 0` keeps frame-rate timing.

`-export_path_metadata 1` adds `lavf.image2dec.source_path` and `lavf.image2dec.source_basename` tags plus Strings Metadata side data to each image2 packet, using its actual input filename. Omit the option or pass `0` to leave path metadata disabled.

Packet scans support `-read_intervals START%END` (comma-separated intervals), relative `+` times, omitted endpoints, and `+#N` packet limits. Metadata and track-ID stream selectors apply before interval limits and packet counting. For example, `-read_intervals '0%+0.4' -show_packets` reads 0.4 seconds from the seek point. AIFF PCM seeking starts at the requested sample and reads packets of up to 4096 bytes from that point. Other seeking starts at a preceding keyframe; durations start at the packet actually reached. Packet descriptors replay through caller-backed storage with a bounded cache, preserving interleaving and backward seeks. Decoded-frame intervals are not supported.
WebVTT packet `pos` matches native ffprobe’s source byte position after each cue separator, or EOF for the last cue.
WebVTT packets expose nonempty cue identifiers and settings as `WebVTT ID` and `WebVTT Settings` side data, separate from caption payloads. Standalone WebVTT streams report `disposition.default=0`. Input `-kind captions|descriptions|metadata` sets the matching disposition; `-kind subtitles` is the default.
MP4 stream reports include the combined movie and track display matrix and its rotation; transforms that cancel to identity omit display side data.

Decoded WebVTT frames use microsecond `pts` values and millisecond display intervals (`start_display_time`, `end_display_time`), with subtitle `format` and `num_rects`; packet timestamps remain in milliseconds. WebVTT stream start timestamps remain unknown until packets or frames are read or counted.
Selecting `packet` or `frame` with `-show_entries` also requests those records without a separate show flag. Listing packets or frames exposes the corresponding `nb_read_packets` or `nb_read_frames` stream count without an explicit count flag. Selecting both in JSON emits a single `packets_and_frames` array with a `type` field on each record; selecting only one retains the `packets` or `frames` array.
Local HLS input skips media segments with disallowed file extensions before reading them; disallowed initialization files fail. Use `-allowed_extensions mp4,m4s,txt` to replace the default media extension list, or `ALL` to allow any extension.

Local `concat:head.part|tail.part` inputs join file bytes before probing, including headers and packets split across parts. Local concat manifests support `-f concat` or automatic `ffconcat version 1.0` detection. `file` entries resolve relative to the manifest, and optional `duration` entries position the next clip without trimming packets. Packet queries preserve each clip's packet durations, sizes and positions; WAV clips use 4096-byte packets.

Local DASH input tolerates missing media fragments when initialization is available, preserving surviving packet timestamps. Missing initialization files and other read errors still fail.
The audio and ffmpeg plugins share this command implementation. Local `subfile,,start,13,end,313,,:bundle.bin` inputs expose only bytes 13–312 for probing, packet reads and seeking; sizes and offsets are relative to that range. Use `-` or `pipe:0` for stdin. Inline `data:TYPE;base64,DATA` inputs are decoded directly, including `audio/wav` and `application/octet-stream`; WAV probes omit unavailable input size and duration. Piped WAV input requires `fmt ` before the first `data` chunk; seekable filename input accepts either order. Unknown flags fail explicitly.
Only explicitly selected sections are printed; without section flags or `-show_entries`, JSON output is `{}`. Counting packets or frames does not select output sections. H.264 and AAC in MP4, plus MP3, FLAC, Vorbis and Opus streams expose `mime_codec_string`, also selectable with `-show_entries stream=mime_codec_string`. Audio metadata includes `codec_long_name` and `format_long_name`, also selectable with `-show_entries`. AU stream duration follows the declared header length, while packets retain all available audio bytes, including zero-length headers and partial final samples. Raw ADTS timestamps use the native `1/28224000` clock for streams, packets and frames; decoded sample counts and timestamps in seconds retain their sample-rate timing. AAC in MP4 uses the container clock. Y4M streams, packets and frames use one tick per frame, with an exact rational time base such as `1001/30000` for 30000/1001 fps. WAV, FLAC and MP3 streams report `time_base`; FLAC and MP3 also report stream `start_pts` and stream/format `start_time`, including MP3 encoder delay when available.
Automatic MP3 and WAV probes expose ID3 PRIV frames as `id3v2_priv.<owner>` format tags, escaping binary bytes and backslashes as `\xNN` while preserving printable characters and spaces. Ogg comments appear in stream tags with their original field names; M4A format tags include container brands. Xing MP3 bitrates include the header frame, matching native ffprobe. Audio format metadata includes `probe_score`, selectable with `-show_entries format=probe_score`; MP3 confidence depends on the number of validated frames.
`-show_optional_fields auto|always|never` controls unavailable stream and format metadata. By default, JSON omits unavailable fields and text writers include placeholders such as `nb_frames=N/A`. Use `always` to include them in JSON or `never` to omit them in text output. Known values are preserved. Standalone WebVTT streams leave duration and bit rate unknown; cue durations remain available on packets. Standalone WebVTT streams omit undeclared language tags. Plain WebVTT omits undeclared `nb_frames`; `-count_frames` and `-count_packets` report counted cues separately. Chapterless FFmetadata omits unknown duration and bit rate from JSON; chaptered files report their measured values. Matroska/WebM streams match ID selectors `#0` and `i:0` while omitting undeclared `id`, `duration_ts`, `duration` and `nb_frames`; use `-count_frames` and `-count_packets` for read counts, and `-show_format` for the container duration.
XML output uses an `ffprobe` root, collection elements such as `packets`, and attributes such as `<packet size="32"/>`. Metadata tags are nested under `tags`, for example `/ffprobe/format/tags/tag`, matching ffprobe 7. Use `xml=q=1` (or `xml=fully_qualified=1`) for a namespaced `ffprobe:ffprobe` root with namespace declarations and schema location; `q=0` keeps the ordinary root.
Writer options include `nk`, `nw`, `p` and `s` where applicable. Compact and CSV writers accept `escape=c|csv|none` (alias `e`) to select C escaping, CSV quoting or literal values; defaults remain `c` for compact and `csv` for CSV. Flat output uses periods between key components by default; `flat=s=_` (or `flat=sep_char=_`) uses underscores without changing scalar values. Flat metadata values preserve literal tabs, including with the default writer. `flat=h=0` (or `flat=hierarchical=0`) omits collection names, for example `packet.0.size` instead of `packets.packet.0.size`; plain `flat` and `h=1` retain them. INI output uses native section paths and escaping; `ini=h=0` (or `ini=hierarchical=0`) omits the parent collection names.

`createFfprobeCommand`, `createFfprobeCommands`, `FfprobeCommandsOptions` and
`FfprobeLimits` support direct host integration. Defaults: 32 MiB input, 1 MiB output.

QuickTime timecode tracks expose their packets and declared `nb_frames`, but produce no decoded frames or `nb_read_frames`. Native MP4/MOV inspection uses bounded retained reads or staged sequential input for explicit `-f mp4`/`-f mov` requests and automatic requests using media-only options (packets, frames, chapters, programs or counts). Stream/format metadata, tags, chapters, packet/frame rows and counts share native source scanners; keyframe membership and output use caller-authorized backing with bounded caches. All writers preserve field selection, Unicode metadata, rotation, timing, bitrate and subtitle gaps. H.264 streams report progressive or interlaced field order from sequence and picture-timing metadata, plus `chroma_location`, `is_avc`, `nal_length_size` and `bits_per_raw_sample`; these fields are selectable with `-show_entries`. Handler names and large format tags stream without whole-field buffers. Frame codec properties use bounded header reads; the first H.264 SPS is capped by its 16-bit format length and read in chunks of at most 16 KiB. Input, membership storage and output admission complete before stdout publication. Use external backing for large inputs or outputs. Automatic strict-audio metadata and readFile-only backends retain their existing compatibility paths and still need source adapters.

Custom media plugins can provide `probeRecords(source, options)` with one-shot synchronous or asynchronous stream, chapter, packet and frame records. All writers consume selected records incrementally; JSON supports packet/frame arrays without collecting them first. Retained inputs and staged sequential input stay alive through enumeration. Optional result `close()` retires plugin-owned backing, even when its sections are not selected. Input and plugin cleanup finish before stdout publication, so late source, iterator or cleanup failures publish no partial output. Stream, format and chapter tags can return replayable `{ kind: "text", chunks() }` values, allowing large text fields to stream through all writers with bounded escaping. Each call must return identical text in bounded chunks; CSV may replay a field to decide quoting. Unselected fields are never read. Keep field backing alive until result cleanup. Native MP4 source metadata uses the same field representation.

Inspection uses the supplied virtual filesystem and never spawns native tools. Explicit FLAC probes (`-f flac`) use bounded header reads on retained filesystems and discard encoded audio incrementally on stdin or streaming filesystems, including packet/frame and count requests. Input limits apply to the full logical size and input closes before output. Automatic FLAC requests with media-only options (packets, frames, counts, chapters/programs or extended writer options) use the same bounded probes after signature detection. Strict automatic FLAC metadata and tags use the retained source probe and caller-backed key/value indexes. Sequential input stages in caller backing with a 64 KiB cache. Keys and values stream through all writers, preserving comment spelling, FFmpeg aliases (`album_artist`, `track`, `disc`, `comment`), semicolon-separated duplicates within blocks, replacement across blocks and numeric-key order. FLAC comments appear in format tags, not audio stream tags. Track or album Replay Gain comments also expose `side_data_list` with `side_data_type="Replay Gain"` on the audio stream. Large inputs, indexes and output require an external backing provider to keep spilled bytes out of Worker memory; source and index backing close before stdout publication.

Explicit MP3 probes (`-f mp3`) and automatic requests using media-only options use bounded retained or sequential input. They preserve the existing fixed-frame media metadata and emit packet/frame records lazily. Sequential probes discard payload bytes unless ID3 metadata requires staged input; retained probes use source size after admission. Track or album Replay Gain ID3 tags expose `side_data_list` with `side_data_type="Replay Gain"` on the audio stream; peak-only tags do not. Strict automatic MP3 probes also use bounded retained reads or staged sequential input, with a 64 KiB cache and caller-authorized backing. MPEG timing, declared VBR byte rates, ID3v1 ordering, ID3v2 replacement, encodings and unsynchronization are preserved. ID3 user-defined text descriptions become format-tag keys, including ReplayGain names with their original text values. Tag values and output stream through bounded caches; large input/index/output backing should use an external provider. Input and tag storage stay alive through output admission and close before stdout publication. Malformed strict audio retains the existing general-media fallback; source and backing failures propagate.

Automatic Opus/Vorbis Ogg metadata probes scan checksum-validated pages with bounded reads, storing logical streams, packet spans and tag keys in caller-authorized backing. Retained files, stdin and streaming filesystems preserve chained/multiplexed stream timing, raw comment names and duplicate values across all writers. Large tags and embedded-picture validation stream without collecting payload-sized models. Input and indexes close before stdout publication. Explicit and general-media Opus/Vorbis requests use the same bounded scan and preserve the existing first-stream packet/frame schema. Ogg-FLAC reads checksum-validated pages with at most 16 KiB transfers, retaining only its 51-byte identification packet and scalar sizes; automatic and explicit requests preserve the legacy mapping rules. Sequential Ogg input stages through caller backing before validation. Use an external backing provider for large inputs; readFile-only backends still have buffering paths.

For WAV inspection, `ffprobe -f wav -show_streams recording.wav` uses bounded header reads when the injected filesystem supports retained reads. Input limits still apply to the full logical file size. For stdin (`-`) and streaming filesystems without retained reads, the command scans headers incrementally and discards sample payloads without temporary storage. WAV packet/frame descriptors are generated incrementally. Use `-ignore_length 1` to scan WAV audio through EOF; `-ignore_length 0` (the default) honors a nonzero declared data length. `-show_chapters` reports RIFF cue points and LIST/adtl labels with sample-rate timing. Without a declared sample count, the final cue ends at its start on stdin; named files use the audio duration. On stdin, only cues and labels before the first audio data chunk are imported; named files also expose trailing cues. Output uses a bounded cache and caller-authorized filesystem backing before publication, so output-limit failures write no stdout. Large output needs a backing provider with retained read/write handles and conditional removal; memory filesystems keep backing data in RAM.

Automatic WAV metadata probing also uses retained caller reads, preserving the strict audio schema, INFO and embedded ID3 text tags (with later chunks taking precedence), and multiple-data-chunk timing. Broadcast WAV extensions use the general-media reader and expose `comment`, `encoded_by`, `originator_reference`, `date`, `creation_time`, `time_reference` and `coding_history` in format tags; the sample-based time reference retains its full 64-bit decimal value. Strict audio rejection preserves the existing general-media fallback. For stdin and streaming-only filesystems, automatic WAV probes stream into caller-backed storage with a 64 KiB cache, then replay the admitted input through the strict and fallback probes. Large inputs require retained read/write backing and conditional removal; an external backend keeps spilled data out of Worker memory. Input limits and source errors are resolved before output, and the backing is closed before publication. INFO keys and value spans use a caller-backed index, preserving duplicate replacement and numeric-key ordering. All writers replay UTF-8 values and emit bounded fragments, including quoting and trailing-whitespace removal. Source and tag backing remain open until output admission finishes, then close before publication. Automatic WAV requests using media-only options (including packets, frames, counts and extended writer options) use the same bounded general-media scanner as explicit WAV requests. Sequential media-only probes discard sample payloads without input backing. Other automatic formats and readFile-only backends still have buffering paths.

WAV inputs support `-max_size BYTES` to set packet boundaries, rounded down to complete audio samples. Use `0` for automatic sizing. Packet/frame counts use the same boundaries. IMA WAV stream duration honors valid `fact` sample counts and otherwise estimates duration from coded bits; packet durations reflect complete decoded blocks independently.
