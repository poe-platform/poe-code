# safe-bash-rust

The Rust `commands::spreadsheet::Spreadsheet` API edits sparse workbooks in batches, recalculates formulas, formats cell values, and reads and writes XLSX. `to_json` and `from_json` preserve typed cells and workbook metadata as editable text; each cell is one atomic JSON batch for shared-document sync. Failed batches restore their previous cells. Calculation and imports accept explicit resource limits. The same API compiles for native Rust and WebAssembly. Cell indentation survives JSON and XLSX round trips, including differential styles. ISO date-and-time cell input remains numeric in both Excel date systems, so pasted timestamps continue to work in formulas; prefix a value with an apostrophe to keep it as literal text. `TypedCell::convert_date_system` preserves literal calendar dates when moving cells between the 1900 and 1904 Excel calendars, leaving formulas, clock times, durations and ordinary numbers unchanged. It uses the shared number-format parser and a caller-supplied work budget; unrepresentable calendar days are rejected before changing the cell. Dynamic array formulas include `EXPAND(array, rows, columns, padding)`, which preserves typed inputs, fills new cells, and checks output allocation against the calculation limit. `TEXT(value, format)` formats numbers and dates with typed array broadcasting, per-cell errors, both Excel date systems, and bounded output; numeric masks preserve literal separators. `DATEVALUE` and `TIMEVALUE` parse explicit-year numeric and English named-month dates, separator spaces, AM/PM and fractional seconds, including arrays and midnight rollover. `DATEDIF(start, end, unit)` measures full years, months and days, including remaining units, month-end anniversaries and both Excel epochs. `YEARFRAC` supports all five financial day-count bases, positive reversed intervals, and constant-time calculation across long date ranges. `DAYS` counts whole days; `DAYS360` applies US or European month-end rules to dates and arrays. `TIME` discards component fractions before normalization; `HOUR`, `MINUTE` and `SECOND` round together across minute/hour/midnight boundaries and honor Excel date bounds. Displayed times use the same rounding rules. `DATE` and date parts honor both Excel epochs, serial zero, the fictitious 1900 leap day, year offsets and bounded month/day rollover. `EDATE` and `EOMONTH` apply Gregorian month-end clamping with truncated offsets, typed arrays, explicit omitted-input errors and bounded arithmetic in both date systems. Compact English dates such as `1Feb2016` share the date parser. Calendar week numbering preserves year-end weeks, including week 54, separately from ISO week-years. `PROB` sums probabilities for an inclusive interval or array of bounds, validates the distribution, preserves tiny probabilities, and handles sparse whole-column inputs without filling empty cells.

`set_named_expression(index, definition, limit)` creates (`None`) or updates (`Some(index)`) a workbook or sheet-scoped name, including ranges, constants and named functions. `remove_named_expression(index, limit)` deletes a definition and recalculates dependent formulas. Renames use resolved parser tokens across cells, fixed arrays, calculated columns, conditional rules and other names; text and LET/LAMBDA local variables remain intact. Imported name bindings and relative reference origins survive edits and JSON/XLSX round trips. Renames that would capture a local variable or change an existing reference's scope fail without modifying the workbook. Invalid names, duplicate names in one scope, malformed formulas and resource-limit failures are also atomic. Name indexes belong to the current workbook; look up a name again after deleting definitions or importing a file.

`resize_axis(sheet, columns, start, count, pixels, limit)` changes row heights or column widths without recalculating formulas. Pass `Some(pixels)` for an exact CSS-pixel size or `None` to restore default sizing. It preserves hidden state, outline levels, styles, and cells, and validates the whole range and Excel size limits before changing sparse metadata.

`edit_axis(sheet, columns, start, delta, limit)` inserts or deletes whole rows or columns at a zero-based position (`columns = false` for rows, positive `delta` to insert, negative to delete). It updates references, tables, filters, merges, arrays, comments, and formatting atomically. Insertion rejects data pushed beyond the worksheet edge; static arrays cannot be split. OpenFormula and affected 3D references currently reject structural edits without changing the workbook.

`filter_table` supports value lists, date groups, custom conditions, and top/bottom item or percentage filters. Date groups use calendar prefixes from year through second, combine with selected values using OR, and follow the workbook's 1900/1904 date system. Value-checklist edits preserve existing date groups. Gregorian XLSX date filters round-trip through JSON and Excel. Numeric cutoffs include ties and exclude text, blanks, booleans and errors; percentages round up. Column criteria intersect independently. JSON and XLSX retain criteria and saved row visibility until filters are reapplied.

`set_pivot(id, definition, limit)` creates, updates, or removes a pivot table. `pivot_filter_values` returns typed choices, display labels, counts, and selections; `pivot_filter_selection` resolves checklist edits in a Rust batch before applying the definition. Numbers, text, booleans, errors, and blanks stay distinct, while text comparisons follow the calculation engine. Saved selections absent from the current source remain available. Definitions retain a source range or a stable `PivotSource::Name`/`PivotSource::Table` binding, row and column fields, multiple value aggregates, typed selections, and grand-total settings in JSON. Source edits recalculate groups and formulas that reference their totals; calculated output stays outside authored cells. Totals aggregate the original records, including for averages and variances. Supported aggregates are sum, nonblank count, numeric count, average, min, max, product, sample/population standard deviation, and sample/population variance. Pivot cells allow formatting but reject value edits, merges, and overlapping tables. Structural edits move destinations and source references atomically. Named and table sources follow resizing and renames; deleting a bound source leaves `#REF!` instead of capturing a new object with the same label. Table totals are excluded. `pivot_source_range` exposes the current resolved source; `resolve_pivot_sources` resolves a batch of exact name/table identities without scope shadowing. `resolve_ranges` resolves a batch of names, structured references, spill references, and reference-returning formulas through the Rust AST without resampling existing volatile cells. Fixed-range pivots must be removed before deleting their source sheet.

XLSX imports retain range, named, and table pivot definitions and filter selections, including caches outside `xl/`. Exports retain real pivot/cache relationships and calculated worksheet cells, with Excel refreshing axis items when opened. `PivotLayout` retains compact, outline, and tabular layouts, per-field repeated labels and blank rows, values-field layout, and row-label indentation. Compact labels retain their original values; generated indentation is exposed by `cell_style` and exported as formatting. JSON definitions without layout metadata retain their existing grid coordinates and repeating labels. `PivotDataAxis` places values before, between, or after row or column fields, including a single measure; placement survives JSON, XLSX, and source-column edits. `PivotSubtotal` adds automatic or custom per-field subtotals, before or after groups, on either axis. All eleven aggregates use original records, including weighted averages; custom functions use Excel's fixed order through JSON/XLSX round trips. Imported pivot-label merges inside the cached result area do not obstruct recalculation. Calculated/grouped fields, relative aggregates, date-item selections, and external pivot sources are not yet supported; unsupported source definitions are rejected explicitly. Compatibility cases use original ClosedXML 057f5976 and XlsxWriter 238e935a fixtures under their included MIT and BSD licenses.

`map_grid_references` visits resolved cells, ranges, and whole-axis formula references using the Excel parser. Callers can bind them to stable grid identities or remap coordinates while preserving absolute markers, strings, structured references, external workbooks, and unchanged formula spelling.

```rust
use safe_bash_rust::commands::spreadsheet::Spreadsheet;

let mut book = Spreadsheet::new();
book.edit(&[(0, 0, 0, "12"), (0, 0, 1, "=A1*2")], 10_000_000)?;
assert_eq!(book.display(0, 0, 1, 10_000)?, "24");
let xlsx = book.export_xlsx(10_000_000)?;
```

Markdown and GFM heading identifiers preserve Unicode and follow their respective duplicate-ID rules. CommonMark and disabled identifier extensions leave automatic IDs empty. Enabled heading attributes preserve authored IDs, classes and properties in JSON; HTML keeps supported passive attributes and rejects unsupported ones before publication. Optional ATX closing hashes do not become heading text. Markdown inputs normalize CRLF/CR line endings and replace NUL with U+FFFD, matching the JavaScript reader; only one initial BOM is removed.

Markdown, GFM and CommonMark preserve recognized leading YAML metadata as typed Pandoc values in JSON and DOCX/PDF. YAML strings use the same configured Markdown inline parser; body reference definitions do not resolve inside metadata. Lists, maps, booleans and numeric text retain their types, and explicit CLI metadata overrides source values. Matching the existing reader, malformed or unrecognized frontmatter stays ordinary Markdown; a recognized envelope requires a closing fence and a nonblank body. Metadata parsing uses the existing Rust YAML codec with bounded alias expansion, source work, depth, nodes and memory. Only visible title-block metadata can acquire image-read capabilities.

Native HTML input preserves authored head title and author metadata, including implicit head elements and CLI overrides. Title markup and author attribute content remain literal text, so embedded-looking image tags cannot acquire resource access. JSON and text output reuse the existing typed HTML lowering and reject unsupported elements before publication; DOCX/PDF retain the shared HTML renderer for full body tables, styles and admitted images. Source title/author blocks use the same metadata mapper as Markdown and canonical JSON.

Native and WebAssembly Pandoc execute Lua filters (`--lua-filter`, `--lua-filter=FILE`, `-L FILE`, `-LFILE`, and `-L=FILE`) through the portable Rust evaluator. Filters support shared Pandoc constructors and traversal, closures, tables, shared string metatables, operator callbacks, chained indexing, patterns and byte strings. Source strings and identifiers retain the streaming engine’s interning behavior, including raw-byte names. Numeric values distinguish wrapping 32-bit integers from binary64 floats, including hexadecimal literals and coercion, explicit-base `tonumber` parsing and rounding, loop types, and 14-digit float text. `string.format` supports numeric fields, quoted values, padding and precision. `string.pack`, `string.unpack`, and `string.packsize` support byte order, alignment, integer and floating-point fields, and fixed, length-prefixed or zero-terminated strings. `math.randomseed` reproduces existing seeded random sequences, `math.random` supports unit fractions and integer intervals, and `math.ult` compares unsigned 32-bit values. Global reads and writes follow lexical `_ENV` bindings and their `__index`/`__newindex` metatables. Reassigning `_ENV` updates functions that share that environment. Backward `goto` restores the label’s lexical scope while retaining closed-over values; invalid jumps and misplaced `break` statements fail before execution. `...` is accepted only within the current variadic function or the top-level chunk. Remaining library/parser behavior still needs feature-parity work; this is not a complete Lua 5.3 implementation. Failed filters preserve existing output files.

Native Pandoc preserves paragraph boundaries between Markdown input files, including operands read from stdin. Use `--file-scope` to parse each input independently before combining its blocks; for example, separate list files stay separate lists. Failed input reads preserve the final destination. Inline HTML tags and comments remain typed as `RawInline` in JSON; `-raw_html` keeps them literal. HTML output passes HTML raw nodes through by default (`--raw-content=escape|reject` overrides this); plain output rejects raw nodes unless an explicit `--raw-content=retain|escape` policy is selected. Markdown output preserves raw nodes with format attributes. `--strip-comments` removes HTML comments without changing code spans. Rejected conversions leave saved output unchanged.

Markdown reference links and images resolve definitions across their document, including headings, lists, quotations and tables. Markdown readers use the last duplicate definition; GFM and CommonMark use the first. Enabled bracketed spans and link attributes preserve IDs, classes and properties. Markdown's implicit figures retain standalone image captions; the same extension can be enabled for GFM. Code spans and fenced code preserve literal reference syntax. JSON, HTML and Markdown retain image references; plain text and RTF retain their alternative text. Native DOCX and PDF embed supported local or data-URL raster images without fetching external resources. Native JSON input preserves raw HTML blocks; unsupported meaningful constructors and malformed nodes fail before replacing the output instead of disappearing.

Canonical Pandoc JSON exports to DOCX/PDF go directly through `document-converter-rust` and the shared document AST, retaining notes, rich tables, container and inline anchors, and nested content. Both ordinary and `--file-scope` JSON operand lists append blocks in order; later metadata wins and explicit CLI metadata overrides it. Authored title, subtitle, author and date metadata use the shared visible title block; its images and raw markup follow the same VFS and output policies as body content. Without an explicit title, native exports retain only the package title `Document`. Heading shifts apply recursively; section numbering remains supported. Raw HTML block and inline policies are applied before image discovery; descriptive image text cannot trigger resource reads or raw-content rejection. Image paths resolve from the virtual working directory, and remote images must be explicitly embedded. DOCX embeds supported PNG, JPEG, GIF, BMP and TIFF originals; PDF renders admitted raster profiles from those formats. Resource bytes and PDF layout/output are bounded by the shell limits before publication. Unsupported custom constructors fail explicitly; add their lowering to the shared Rust mapper to support them in both native and portable exports.

Run virtualized shell commands in native Rust or WebAssembly (`wasm32-unknown-unknown`), with a TypeScript bridge on native hosts for document and media tools. Native-only `ls -l` lists permissions, link counts, numeric owner/group IDs, sizes, timestamps and symlink targets without a TypeScript host. Hybrid mode retains the TypeScript presentation for long listings (`-l`, `-g`, `-o`, `-n`); ordinary filename listings remain native. Native `magick` exports 8-bit RGB/RGBA pixels to `.rgb`, `.rgba`, and `RGB:`/`RGBA:` destinations, preserving transparency in RGBA output.

`safe-bash-rust` provides a Rust `Shell`, `PoeAgentShellHost`, and WebAssembly runtime (`createRustWasmBash`) with built-in POSIX/Bash grammar, virtual filesystems (`MemoryVfs`, `OverlayVfs`, `MountVfs`, `RealVfs`), resource budgets (`ShellLimits`), and native implementations of `rg`, `find`, `xargs`, `sed`, `awk`, `jq`, `yq`, `xan`, `csvcut`/`csvgrep`/`csvsort`, `sqlite3`, `tar`, `gzip`/`zstd`/`xz`/`bzip2`/`zip`, `sha256sum`, `xxd`, `od`, and `dd`. Document and media commands, including `pandoc`, use the TypeScript safe-bash bridge in hybrid mode. Native-only and WebAssembly execution use the Rust document and media commands. Pandoc supports `--lua-filter` and `-L` through an internal Rust evaluator, including ordered scripts, returned filter tables, element/list/document callbacks and metadata edits. Lua language and standard-library parity remains incomplete; see [the evaluator](../lua-rust/README.md). `xmllint` supports explicit XPath axes, namespace nodes, `id()`, `lang()`, and grouped node-set predicates. XML output honors a declared UTF-16 encoding unless overridden with `--encode`. `pdftotext` exports word, line, and block bounds and filters words by crop regions, including inherited CropBoxes and DPI scaling. Plain and spatial extraction support simple Standard 14/WinAnsi fonts and the writer's 16-bit Identity-H fonts with `bfchar` and `bfrange` Unicode mappings, including Unicode sequences, surrogate pairs, range arrays and later mapping overrides. Other composite encodings and malformed mappings fail explicitly instead of returning glyph IDs as text. PDF-to-SVG export preserves vector paths, glyph outlines, clipping, axial gradients, masks, and embedded bitmap images, including page rotation, cropping, and selected-page output. Non-isolated groups that blend with the page use a bitmap composite. PDF rasterization applies nonzero and even-odd path clipping to fills, strokes, text, and images, including saved graphics states and Forms. Axial gradients support DeviceGray/RGB/CMYK and exponential functions, transforms, Extend flags, and clipping; unsupported or malformed shading fails without replacing the output. It supports Standard 14 fonts and embedded simple TrueType fonts with WinAnsi encoding and horizontal Identity-H CIDFontType2 fonts with identity or explicit CID-to-glyph maps and CID widths, including filled and stroked text with transformed line widths and dash patterns; unsupported font programs fail without replacing the output. Python still requires the host bridge. Spreadsheet imports resolve names in XML sheet and cell order while retaining workbook output order; later local declarations preserve earlier global bindings. The `concat:` media input protocol joins raw file bytes before demuxing. MP4 video seeking and loops exclude hidden preroll from encoded frames, and raw `yuv420p` extraction preserves decoded H.264 planes. MP4 and APNG conversion support `-fps_mode`, output `-r`, legacy `-vsync`, and mapped output selectors; GIF output retains intervals between presentation timestamps. APNG probes report native source rates, 100 kHz timestamps, original packet offsets and sizes, keyframe flags, pixel formats and aspect ratios; unknown durations remain absent and requested frame/packet counts are included.

Native `qpdf --json=1` and `--json=2` honor `--json-key` selection, including repeated keys. Page summaries include content references, inherited images, page labels and outline destinations. Version 1 exposes `objects` and `objectinfo`; version 2 keeps its object graph under `qpdf`. Selecting page metadata does not export unselected streams. Attachment listing and extraction skip entries whose selected embedded-file reference is not a stream. Encrypted-document, form and attachment JSON metadata remain limited.

For trusted Python in native hybrid mode, install Pyodide 314.0.6 and set the host process's `SAFE_BASH_PYODIDE_MODULE_URL` to its `pyodide.mjs` file URL. This registers `python` and `python3` with the existing Python worker adapter, sharing the shell's virtual files, working directory, stdin and environment. No host Python fallback is used. Pyodide JavaScript interoperability is not a security sandbox. Package provisioning is separate from the standard-library runtime.

## Feature Index

Native `awk getline` preserves its target value at EOF. Array indexes and field
targets are evaluated once before reading, including when no record remains.

Native `seq` rejects trailing numeric whitespace while accepting leading whitespace.
Invalid-number diagnostics quote the operand; format errors identify missing,
incomplete, unknown, and repeated conversions.

Native `read` consumes malformed UTF-8 units with the byte that invalidates them,
including newline or NUL, and preserves the remaining input for later commands.
IFS splitting preserves Bash's single-byte backslash quoting for multibyte
separators; raw reads retain normal UTF-8 separator matching.

Native `ffprobe` reports Y4M packet positions relative to the input file, including
variable-length `FRAME` tags, and exposes frame positions as `pkt_pos`. Timestamps
use the stream's frame time base, including fractional rates such as `30000:1001`.
When both packets and frames are requested as JSON, the shared media formatter
interleaves them in `packets_and_frames`, with a `type` field on each record.
Packet and frame field selections apply independently.

VFS script execution populates the command cache. `hash -t` reports cached entries;
`hash -r` and changes to `PATH` clear them. `set +h` disables hashing and `set -h`
restores it. `shopt -s checkhash` retries `PATH` when a cached executable becomes
unusable. Current-directory hashes are rechecked even with `checkhash` off.

`zip -X` strips optional metadata from new or replaced members; `-X-` restores timestamp and known virtual owner-ID records. The last flag wins. Existing unselected members retain their metadata, and required ZIP64 fields remain. Filesystems that omit either owner ID produce no owner record.

Inside a registered Rust command, `ctx.invoke(name, args, options, &mut stdin)` runs literal arguments in a child with the current filesystem and execution budget. It returns the exit status and both output streams; changes to the child’s variables and working directory stay in the child.

Native Rust callers can pass `ExecOptions { fs: Some(filesystem), ..Default::default() }` to read and write a different `SafeBashFs` for one call. Subsequent calls use the shell’s original filesystem. `shell.exec_with_stream(script, chunks)` takes an iterator of `Result<Vec<u8>, String>`. Commands pull stdin on demand and duplicated descriptors share unread bytes. Streamed calls use the native backend, including in hybrid mode, so an unknown command returns status 127 without replaying the script. TypeScript-only mode rejects streamed calls.

Supply a live JavaScript filesystem with `new RustWasmBash({ fs, cwd })`. Commands and sessions use that root; `exec(script, { fs: other })` overrides it for one call. Host filesystem execution requires WebAssembly Promise Integration. Seed files through the supplied filesystem itself; synchronous shell file helpers and `execSync` require the built-in Wasm filesystem.

The standalone Node loader supports stream commands installed with `bash.register(command)` or `bash.use(plugin)`. Install the optional `safe-bash-contracts` peer and use `await bash.exec(...)` on a Node runtime with WebAssembly Promise Integration (JSPI). Register middleware with `bash.use(async (ctx, next) => { ... })` or `host.use` during plugin setup. Return or await `next()` to run the command in the current shell, or return an exit code object to skip it. Plugin setup can also register commands and filesystem factories. Use `host.provideCapabilities(defaults)` to supply capabilities to handlers; options passed to `exec` take precedence. Execution waits for setup. Handlers receive byte streams, arguments, cwd, exported variables, cancellation and invocation capabilities. Use `onInternalError` on the shell or an individual execution to receive private plugin errors while keeping them out of stderr. Use `ctx.stdinIsDefault` to distinguish the default input from a supplied stream, pipe, or file, even when it contains no bytes. While a handler is running, `ctx.fs` supports `open`, `readFile`, `readStream`, `openReadFile`, `writeFile`, `appendFile`, `stat`, `lstat`, `readdir`, `mkdir`, `rm`, `access`, `chmod`, `readlink`, `realpath`, `rename`, `symlink` and `unlink`. Handlers can also use `copyFile` on the built-in filesystem or on an external filesystem with `deviceView: "provided"`. When the shell overlays its own devices on an external filesystem, `copyFile` returns `ENOTSUP`. Plugins can check `ctx.fs.capabilities` for shared features or `await ctx.fs.capabilitiesFor(path)` before changing permissions or creating private output. On memory filesystems, use `writeFileConditional` and `removeFileConditional` with parent and destination stats to reject stale changes. Use `createStagedFile` for private output, then `publishStagedFile` to replace the destination only if it still matches the observed stat. Request `retainCleanup: true` to append chunks through the staged writer and clean up the original stage even if its parent is renamed. A memory-file stream pins the bytes on its first pull. Set `start`, `endExclusive`, and `chunkSize` to read a range without loading the entire file. Open descriptors and retained readers stay on the opened file if its path is replaced and close when the handler finishes. Memory and mounted filesystems support writable descriptors; overlays support retained readers. These calls share the script’s filesystem operation and pathname limits. New files and directories use the shell umask unless the handler provides a mode. Use `ctx.registerCleanup(callback)` to release resources when the command ends. The shell waits for the callbacks before running the next command. Use `ctx.invoke(name, args, options)` to call a command with literal arguments, inherited or replacement environment, cwd and byte streams. The child shares the script’s limits. Explicit input and child output are buffered; output sinks receive the child’s bytes after it finishes. Admitted process handles, process signal endpoints and shell redirection descriptors are not yet available. The registry lists custom commands only. Await `bash.dispose()` to run plugin cleanup.

Wasm hosts can register a command with `safe_bash_register_command(session, namePtr, nameLen, callbackSlot)`. Pass a UTF-8 name and a function in the exported indirect table; a return value of 0 means the registration succeeded. The session and subsequent forks can invoke it by name or by its virtual executable path.

The callback receives `(packetPtr, packetLen, replyPtr)` and returns an exit status from 0 to 255. The packet starts with three little-endian 32-bit words: argument count, exported environment count, and whether an explicit `argv0` follows. Next come the working directory, optional `argv0`, arguments, and environment key/value pairs. Each field is a 32-bit byte length followed by that many bytes. The rest of the packet is stdin. Use the packet only during the call. To return stdout or stderr, write a pointer and byte length for each stream at `replyPtr` (stdout first); both pairs start at zero. Write the number of stdin bytes consumed to the fifth word (offset 16, initially zero). The next command sharing that descriptor receives the remaining bytes. The sixth word (offset 20) contains the remaining output budget in bytes. If the seventh word (offset 24) is 1, stdout and stderr share a destination: append both to the stdout buffer in write order. Offsets 28 and 32 contain the remaining filesystem operations and maximum path components. Write the number of filesystem operations admitted to offset 36 (initially zero); Rust charges them to the current execution. Offset 40 contains the file creation mode after applying the current shell umask. Offset 52 is 1 if stdin is the default source. At offset 56, bits 0, 1 and 2 indicate whether stdin can be read, stdout can be written, and stderr can be written, respectively. Offset 60 contains the directory creation mode after applying the umask. A host can return −5 for an exceeded filesystem operation budget, −2 for cancellation, −3 for an exceeded output budget, or −4 for an internal handler failure. An internal failure preserves earlier output and reports the shell source line without exposing the handler exception. For a public diagnostic, transfer its UTF-8 pointer and length at offsets 44 and 48 and return −6. Transfer each nonempty stream in its own buffer from `safe_bash_alloc(length)`. Rust frees those buffers and applies the shell's output limits and redirections.

A host command can return −7 to run a child before finishing. Transfer a request at offsets 44/48, leave stdout, stderr and consumed stdin empty, and report any filesystem operations since the previous callback. The request starts with three little-endian u32 words: flags, argument count and environment pair count. Length-prefixed byte fields follow: command, optional cwd (flag 1), optional argv0 (2), arguments, environment pairs and stdin. Flags 4, 8, 16 and 32 select a replacement environment, external command lookup, default stdin and a shared stdout/stderr destination respectively. Rust runs the child with the caller’s budget and calls the host again with the same command packet. Offset 72 (i32) is −1 on the initial call, the child exit status on success, or −2 on failure. The borrowed response at offsets 64/68 contains a u32 unread stdin count followed by length-prefixed stdout and stderr, or a UTF-8 error on failure. Copy it before returning or suspending. Offsets 76/80 on a −7 reply reserve previously uncharged stdout/stderr bytes; on a final reply they identify returned bytes already charged by a reservation or a child. Offset 84 contains the maximum input byte count. Return −9 if supplied child input exceeds it. On each child or final reply, set offset 88 to the cumulative bytes reserved for file output by this host command. Include outstanding writes; if a counted write accepts fewer bytes than reserved, subtract the unused bytes. File output shares the script’s output limit with stdout and stderr. Finish with an ordinary host reply.

On a host with JSPI, passing an abort signal to `exec` makes `sleep` wait at the command itself. Aborting keeps earlier filesystem writes and skips the commands that follow. A surrounding `timeout` shortens the wait. `execSync` continues to advance the virtual clock without a wall-clock wait.

Custom Wasm hosts can call `safe_bash_exec_stream(session, scriptPtr, scriptLen, callbackSlot)`. Install the callback in a new slot of the exported `__indirect_function_table`. Rust calls it with `(session, dataPtrOut, lengthOut)`. Return 0 for EOF, 1 for a chunk, -1 for a UTF-8 error message, or -2 to cancel the execution. Cancellation stops the script and preserves earlier filesystem writes. For a nonempty chunk or error, transfer a buffer from `safe_bash_alloc(length)` by writing its pointer and length to the two output addresses. Rust frees the buffer. A chunk of length zero does not end the stream. On hosts with WebAssembly Promise Integration (JSPI), the JavaScript loader pulls async stdin as Rust commands read it and closes the iterator when they finish. On hosts without JSPI it still collects async stdin before execution.

Pass a filesystem to `exec(script, { fs })` to use it for that call only. On Node with WebAssembly Promise Integration, the standalone Rust shell calls the supplied filesystem directly for file contents, metadata, directory entries, and links. Concurrent calls may use different filesystems. Redirects keep using the opened file across renames when the host supports positioned descriptors. On a host with exclusive file creation but no writable descriptors, `set -C` buffers the redirected output and creates the destination when the redirect closes. A competing file wins and its contents are preserved. Renderers can publish output conditionally on filesystems that provide atomic writes or publication. A destination replaced during rendering is left alone. A configured companion continues to handle external filesystem calls.

`sort` uses byte order in the C and POSIX locales. For other locales the Wasm loader uses `Intl.Collator`, and native Linux, macOS and Windows builds load the system ICU library on demand. An unavailable locale or collation service gives exit status 2 before any input or destination is opened. Language availability and ordering can differ between ICU versions. Shell `[[ < ]]` and `[[ > ]]` use the same locale service for UTF-8 locales, with the locale’s default case order. Custom Wasm hosts must provide the `safe_bash.collator_open(tagPtr, tagLen, lowerFirst)`, `collator_compare` and `collator_close` imports alongside the clock and entropy imports. AWK’s `strftime` and `mktime` use the shell’s `TZ`. For named zones the Wasm loader uses `Intl.DateTimeFormat`; native builds read system ICU time zone data. Custom Wasm hosts must also provide `safe_bash.timezone_fields(namePtr, nameLen, epochSeconds, offsetPtr, labelPtr, capacity)`. It writes a signed 32-bit offset in seconds east of UTC and a UTF-8 short label, returning the label length in bytes or −1 on failure.

### 1. Zero-Dependency Rust Shell with `MemoryVfs`

```rust
use safe_bash_rust::{BackendMode, MemoryVfs, SafeBashFs, Shell, ShellOptions};
use std::sync::Arc;

let vfs = MemoryVfs::new();
vfs.mkdir_all("/workspace").unwrap();

let mut shell = Shell::new(
    Arc::new(vfs.clone()),
    ShellOptions {
        cwd: Some("/workspace".into()),
        mode: BackendMode::NativeOnly,
        ..Default::default()
    },
);

shell.exec("echo '3\n1\n2' > numbers.txt").unwrap();

let result = shell
    .exec("for n in $(sort numbers.txt); do echo \"v=$n\" >> sorted.txt; done")
    .unwrap();
assert_eq!(result.exit_code, 0);

let sorted = String::from_utf8(vfs.read_file("/workspace/sorted.txt").unwrap()).unwrap();
assert_eq!(sorted, "v=1\nv=2\nv=3\n");
```

If you supply a custom `SafeBashFs`, implement `create_file` to let `touch`, `cp`, and `xmllint -o` create files. It must create the file with the requested mode and return `EEXIST` if the name is already occupied, including by a dangling symlink. To support `ln` and `cp -l`, implement `supports_hard_links` and `hard_link`. A hard link shares the source inode, including when the source is a symlink. In a filesystem snapshot, entries with the same `link_group` share an inode; file payloads use `Arc<[u8]>` so a snapshot stores those bytes once.

For `sed -i`, the filesystem must support retained reads and guarded file replacement. For `sed -i.bak`, implement `replace_file_with_backup` to move the original inode to the backup name in the same commit that installs the edited file. The native memory filesystem supports this; unsupported providers return an error without replacing either file.

Custom filesystems can update timestamps for `touch` and timestamp-preserving copies by implementing `set_times(path, atime_ms, mtime_ms)`. Each time is an `Option<f64>` in milliseconds since the Unix epoch; leave the corresponding time unchanged for `None`. Implement `append_file` if the backend supports atomic append or writing without read permission. The default reads the existing file and stops if that read fails for any reason other than `ENOENT`.

Implement `open_chunks` if a custom filesystem can stream input. Each call to the returned reader replaces its buffer with the next chunk, or clears it at EOF. The default reads the whole file. For external sorting, implement `scratch_file(directory)` to return a private, unnamed file with positioned reads and writes. Its storage must stay available until the last handle is dropped. When a sort needs to spill and the filesystem does not support scratch files, it fails. The memory filesystem charges scratch bytes against its normal quotas.

### 2. WebAssembly Shell from JavaScript / TypeScript

The JavaScript entry point requires Node.js to load the packaged WebAssembly binary. Use `await bash.fs.open(path, { access: "readwrite" })` for positioned I/O on memory files. Use `await bash.fs.link(existingPath, newPath)` to give a file or symlink a second name. The descriptor stays attached to the opened file after renames and unlinks; call `await descriptor.close()` to release it. Use `await bash.fs.readdir(path, { maxEntries })` for sorted `{ name, type }` entries; exceeding the limit raises `EFBIG`. The synchronous `bash.readdir(path)` returns names.

Use `await bash.fs.openReadFile(path)` for positioned reads from regular Wasm files. The handle follows the opened file across renames and unlinks; close it when finished. Pass `{ allowDirectory: true }` to read directory metadata. Directory handles reject byte reads with `EISDIR`. Production JavaScript commands such as `cat` can read these files through this interface. Use `await bash.fs.appendFile(path, bytes)` to append bytes or create a file. Production shell redirections (`>` and `>>`) and `tee` can write to this filesystem.

Use `await bash.fs.access(path, mode)` to check existence (0), read (4), write (2), or execute/search permission (1). Combine permission bits to require all of them. Pass an abort signal to `bash.fs.chmod(path, mode, { signal })` to cancel a mode change. On memory-backed paths, including ordinary files alongside a device mount, pass `parent`, `expected`, and an ordered `ancestors` list from `lstat` to change only the inspected entry. A stale receipt returns `EAGAIN`; a final symlink changes mode without affecting its target. On memory-backed overlays, guarded chmod replaces regular files in the upper layer and preserves directory identity across copy-up. Guarded overlay symlinks return `ENOTSUP` without changing the target. A mounted root returns `EBUSY`, and device files do not support guarded permission changes.

Use `await bash.fs.symlink(target, path)` to create a symbolic link in an existing directory. `await bash.fs.readlink(path)` returns the stored target even if it does not exist. Both methods accept `{ signal }` and report filesystem errors such as `ENOENT` for a missing parent.

Use `await bash.fs.utimes(path, atimeMs, mtimeMs)` to set access and modification times, including fractional milliseconds and dates before 1970. Read both values with `await bash.fs.stat(path)`. Memory files also expose `birthtimeMs` (creation) and `ctimeMs` (last change to the inode). Appending changes modification and status times while preserving access time.

Inode numbers are local to each filesystem. When comparing two entries with `stat`, compare `identityScope`, `dev`, and `ino` together. Metadata such as `nlink`, `uid`, `gid`, and `allocatedBytes` may be absent when the backing filesystem does not report it.

By default the shell exposes a virtual `/dev/null` alongside files you supply under `/dev`. Use `deviceView: "provided"` to keep your own `/dev/null`, or call `bash.mountDevices()` to mount the device filesystem over `/dev`.

To checkpoint a session, save `JSON.stringify(session.state)` after an execution. Pass the parsed snapshot to `bash.createSession(snapshot)` or assign it to `session.state` to restore the shell bindings. Files stay on the filesystem; restoring bindings never repeats file writes. The older Rust-only `rawHistory` format is rejected because it contains commands rather than state.

PBM packs black pixels as one and uses ordered dithering for grayscale/color conversion. Zero-frame image conversions emit no image and preserve existing files. APNG input preserves frame delays, transparency and disposal; convert animations or write `.apng` output with `-plays` to set the loop count. AIFF/AIFF-C (`.aiff`/`.aif`) reads and writes PCM, floating-point, A-law, μ-law and QuickTime IMA audio; conversion supports seeks, loops, concatenation, text metadata and packet copying. AIFF reads ID3v2.2–2.4 tags and writes v2.3/v2.4 with `-write_id3v2 1`; select version 3 or 4 using `-id3v2_version`. Unicode, track/disc numbers and custom tags are preserved. IRCAM (`.sf`/`.ircam`) reads PCM16 and float32 in either byte order, μ-law and A-law, and writes PCM16 little-endian, μ-law or A-law. NIST SPHERE (`.sph`) reads PCM16 in either byte order, preserves declared durations and custom probe tags, and converts audio or exports metadata. SPHERE output is unsupported. IRCAM probing retains packet offsets, and input/output seeks use PCM frame/packet boundaries. `ffmpeg` reads ASS/SSA, AQTitle, VPlayer, Spruce STL, SubViewer v1/v2, MicroDVD, RealText, SAMI, JACOsub, PJS and MPL2 subtitles and converts them to ASS, SRT, WebVTT, LRC, Matroska, WebM or MP4 (`-c:s mov_text`). AQTitle accepts integer, decimal and rational frame rates with `-subfps`. MicroDVD preserves inline and default styles, honors embedded frame rates, and supports `.sub` stream copy with `-c:s copy`. RealText preserves centisecond timing, literal entities, and native line-break and whitespace handling. SAMI input preserves styles and speaker names across cues and reports rejected clearing markers. TTML output preserves subtitle timing, line breaks and escaped text, with a default layout and stream language metadata. JACOsub reads tick rates, timing shifts, continuation lines and alignment. ASS/SSA probing supports UTF-16 input; ASS stream copy preserves headers, styles and dialogue fields. Python still requires the host bridge.
