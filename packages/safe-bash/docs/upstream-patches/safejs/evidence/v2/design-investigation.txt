SUMMARY

run.ts-only replacement can restore a clean, source-bound AbortError without
reading or mutating the caller's reason: construct an interpreter-owned error
through createSubsetErrorValue, retain the exact object/function reason as
cause, and materialize that cause through the existing helper. Keep primitive
reasons, including null and false, as exact rejection values.

the sole failure is the original probe's additional exact raw Error identity

PROPOSED SEMANTICS AND BOUNDED TRADEOFFS
- Already-aborted object/function reasons become an engine-owned AbortError
  record, with a fixed nonempty message and clean stack. error.cause === reason;
  the original custom name, message, fields, inner cause, and freezing remain on
  that exact reason object. No property of the reason is inspected, no descriptor
  is fetched, no prototype is traversed, and no JSON/string coercion occurs.
  The top-level message is deliberately generic; this changes diagnostics for
  custom reasons relative to raw rejection. It is not custom-message equivalence.
- null, false and all other primitive reasons remain exact raw rejections. This
  intentionally does NOT promise an Error-shaped envelope for primitives. Native
  AbortSignal.abort(undefined) creates its default object reason; it follows the
  object branch, rather than becoming an undefined rejection.
- Frozen default/custom Errors, frozen records/functions and own/inherited
  throwing accessors are preserved through cause without writes or reads. No
  native Error stack is read or formatted. No Proxy, host evaluator, signal drop,
  thenable assimilation, host callback or quota redesign is introduced.
- The span is an entry anchor, NOT a claim that a particular guest expression
  executed. createSourceSpan(source, 1, 1, 1, 1) uses upstream endpoint handling
  to cover the first source unit (or a zero-length empty-source anchor). It also
  handles a leading newline correctly and avoids parsing invalid source before
  cancellation. No caller filename/modules/bindings/options.budget getter is read.
- A fresh internal Budget is used only to create the small error record through
  the existing error-construction pathway, with its existing chargeBudget:false
  behavior. It is not a replacement run budget and never executes guest code.
  Caller budgets, quotas, limits, and live-signal execution are untouched.
- The outward stack is sanitized, NOT the recursive cause graph. That graph may
  contain native paths, getters or capabilities supplied by the caller. This is
  an intentional host-side diagnostic preservation tradeoff already present in
  the upstream host-Error cause path. Do not recursively serialize/expose it to
  guests or call it a recursively sanitized error.
- Trusted native AbortSignal and string source inputs remain prerequisites.
  Arbitrary getters on options.signal or monkeypatched host intrinsics are not
  addressed. The existing fast-path lack of dump-controller attachment is also
  unchanged; this task does not redesign lifecycle setup.

WHY UNIVERSAL EXACT IDENTITY CANNOT ALSO BE REQUIRED
A caller can freeze an Error whose stack contains native paths and which has no
span. If the outward rejection must be that same object, no wrapper is allowed;
if mutation is forbidden (and freezing makes it impossible anyway), there is no
way to add the required span or replace its stack. General simultaneous raw
identity, source-bound sanitized shape, and immutable caller reasons are
incompatible. Cause identity is a safe alternative, not raw identity.

A default-DOMException-only special case could make the currently observed ten
tests green while passing the audit, but it would leave custom/frozen Error
reasons unshaped and lacks a reliable provenance distinction: callers can supply
the same default-looking DOMException themselves. That is not a general solution
to the requested contract. This report does not claim the literal test assertions
alone are mathematically impossible to satisfy; the conflict is the general
contract when arbitrary frozen reasons must also have the shaped outward error.
