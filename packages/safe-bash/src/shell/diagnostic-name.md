# Command-name diagnostic rendering

This internal formatter renders command-not-found names without changing their
original bytes or command lookup identity. It is not shell argument quoting or
`printf %q`. Printable names, including spaces and shell punctuation, remain raw.
When quoting is needed, the entire name uses `$'…'`; ASCII controls use Bash's
mnemonics (including uppercase `\E`), quotes and backslashes are escaped, and
other nonprinting bytes use three-digit octal escapes. Builtin-not-found names
remain raw and do not use this formatter.

## Locale routing

The existing `byteLocale()` contract is unchanged: effective `LC_ALL`, then
`LC_CTYPE`, then `LANG` selects byte classification for exactly `C` and `POSIX`.
Those routes treat only bytes 32–126 as printable. All other names and an absent
locale retain the existing virtual UTF-8 route. Its classifier uses the pinned
table in `diagnostic-name-ranges.ts`; this is not a claim of native parity for
every locale or for the host's default locale.

For a direct missing command, temporary prefix assignments affect its execution
environment but do not replace the ambient locale used to render the diagnostic.
Persistent assignments and command/function/eval prefixes retain their active
locale behavior. Explicit middleware environment changes remain effective. This
distinction is scoped to command-not-found rendering, not a global restoration
of shell variables or the command environment.

UTF-8 decoding is strict: overlong encodings, surrogates, out-of-range scalars,
isolated continuations and incomplete sequences are not printable. Invalid bytes
advance individually, preserving any following valid printable sequence. Valid
printable sequences retain their original bytes even inside a quoted name;
valid nonprinting sequences are escaped byte by byte. No replacement-character
decoding, Unicode-property approximation, display-width classifier or runtime
native dependency is used.

## Pinned business data and evidence

The table is classification data, not vendored executable code. Its 713 sorted,
inclusive, maximal ranges were generated by exhaustive classification of all
1,112,064 Unicode scalar values (surrogates excluded). `en_US.UTF-8` and
`C.UTF-8` agreed for every scalar: 286,484 printable and 825,580 nonprinting.
The C profile admitted exactly 95 printable scalars. Native `iswprint`, its
macro route and the `wctype("print")` route agreed. Strict UTF-8 conversion
round-tripped every scalar. Native qualification covers these pinned profiles,
not arbitrary operating-system or Unicode versions.

The author tests authenticate the canonical table digest, interval invariants,
population and every interval endpoint and adjacent scalar. Separate tests cover
invalid UTF-8, raw-byte forwarding, cancellation, output and allocation budgets.
The formatter computes the exact output length before allocation, bounded by
`4 * inputByteLength + 3`, using the invocation's existing value allocation.
Diagnostics still flow through the awaited, budgeted stderr route.

The native `command -p` forwarding witness remains a separate pending feature
test, recorded by `/tmp/command-name-runtime-UTF8-frozen-handoff.json`. Its
unsupported-option failure is not a formatter failure or a passing qualification
case. This formatter increment does not deliver `command -p` support.
