6. Exact byte/read/cancellation constraints
src/contracts/io.ts exports ByteSource = AsyncIterable<Uint8Array>, ByteSink
write(chunk): Promise<void>, readBytes(source, signal?), writeBytes(sink,
chunk, signal?), collectBytes(source, {maxBytes, signal?}) and pipeBytes.
Await sink writes, preserve chunk ownership, count retained bytes and emit
byte streams; terminal Shell.exec buffers, internal pipes remain byte-oriented.
collectBytes is bounded WHOLE collection and throws EFBIG on excess; it is
not a prefix-reader and must not be used as a truncating sample operation.

FileSystem.readStream? accepts {signal, start?, endExclusive?, chunkSize?}.
For a bounded file sample, request start:0/endExclusive:sampleBound with a
bounded chunk size, consume via readBytes, copy only owned bounded sample
bytes, and stop/close the iterator once the bound is met. Enforce consumer
chunk/byte limits as well; a provider can overfetch internally, which this
surface cannot universally prevent. Do not claim prefix sampling proves
whole-file text encoding or exact libmagic behavior for unseen bytes.
readFile(path, {signal,maxBytes}) has no offset/prefix return API. Memory
readFile rejects EFBIG for larger files before returning any prefix; do not
retry unbounded readFile when streaming is absent. Nonstreaming large-file
prefix support is missing and needs an explicit limitation/unsupported result,
not a contracts edit or fabricated classification. Small bounded whole-file
fallback is possible. The generic commands/internal.ts input fallback omits
maxBytes, so it is not itself a sufficient bounded classifier-input helper.

readBytes checks pre-abort before acquiring the source iterator; validates
Uint8Array chunks; races next() against cancellation; invokes iterator.return
on early exit/failure. Without cancellation it awaits cleanup; after abort it
observes late cleanup rejection rather than waiting forever. Consumer code
must actually close its wrapper iterator (for-await break/finally or explicit
return) rather than abandoning manual next() calls. Do not assume cancellation
forcibly stops uncooperative provider work or undoes completed effects.
writeBytes similarly races the awaited sink operation and observes rejection.
Forward context.signal into every FS call and rethrow cancellation before
ordinary diagnostics, including errno-shaped abort reasons. For stdin sample
consumption, preserve stdinIsDefault provenance and explicitly manage owned
iterators; implicit/default stdin does not establish that bytes are absent.

7. Traversal, symlinks, identity and collection caveats
Required FileSystem methods: stat/lstat/readdir/realpath; optional readlink,
symlink and compareEntry. All accept signal-bearing FsOptions where applicable.
Use lstat to inspect the final link itself, stat to follow it, readlink for its
text only when supported. Do not turn missing readlink support into a fabricated
target. Realpath resolves through the adapter; lexical resolvePath/joinPath are
virtual POSIX helpers, not symlink containment or cross-mount authority.
DirectoryEntry is only {name,type}; readdir returns Promise<DirectoryEntry[]>,
NOT an iterator, page API or bounded listing. Memory readdir collects and sorts
the whole directory before return. A command entry limit can bound subsequent
retention/traversal/output, but cannot cap that adapter-side allocation. Whole
subtree collection/sorting likewise needs explicit limits and cancellation
yields. No directory snapshot, descriptor-relative traversal or lease exists.
Ancestor cycle detection plus depth/entry/work bounds are needed if authors
choose link-following; unknown identity is not proof that a new path is safe
to recurse forever, nor permission to collapse unrelated entries as duplicates.

FileStat identity is complete only with non-null object/symbol identityScope
AND safe nonnegative integer dev and ino. Compare scope by ===, never stringify
or invent per-client scopes. Same complete tuple means same observed entry;
different complete tuples/scopes mean distinct under truthful authority.
Any missing/invalid identity remains unknown; bare inode or differing pathname,
URL, wrapper/client, credentials or ETag is not authority. compareEntry? returns
same/distinct/unknown for FOLLOWED backing entries, not link entries or content.
Missing support/unrecognized peers are unknown; real FS/cancellation errors
propagate. Invalid/conflicting answers fail EIO; known aliases are not overridden.
At most one query per distinct operand authority, no recursive negotiation.
Comparison is point-in-time only, never a lease, transaction or ABA defense.
