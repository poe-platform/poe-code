BOUNDED I/O / RUNTIME CAPABILITY GAPS
Optional readStream is used with start/endExclusive/chunkSize and combined signal.
Copies retained samples, charges delivered input, awaits sink backpressure and
normal early iterator return, aborts per-file signal at prefix termination to
unblock signal-dependent cleanup. Only the exact intentional local abort reason
is accepted from return; unrelated cleanup/read failures remain errors. Empty
chunk producers consume steps and yield. Prefix data does not validate unseen
later bytes; EOF exactly at range cap cannot prove JSON completeness.

readFile-only fallback requires safe nonnegative known size within the minimum
of maxReadFileBytes, maxChunkBytes and remaining input budget; maxBytes and signal
are supplied and returned length rechecked. Unknown size without readStream is
ENOTSUP. Whole fallback bytes may ALREADY have been allocated by the backend:
neither metadata gating nor returned-length checks bound backend storage
allocation, prevent concurrent growth or constrain an untruthful host adapter.
Oversized delivered chunks are rejected after their host allocation too.

Family-local SharedBudget aggregates entries, input/output bytes, steps and
deadline; existing CommandContext has no public SharedBudget object. Parent
shell signal and budgeted sinks preserved, not replaced by a fake global quota.
Timeouts/abort propagate, late host rejections observed; uncooperative host code
may continue and completed effects are not undone. Diagnostics share output
quota and may truncate/be absent when exhausted. No root runtime changes.
No deployed-provider, real FS, S3 or WebDAV verification was performed here.
