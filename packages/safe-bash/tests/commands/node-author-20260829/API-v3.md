Status: post-bf9a7a3e SOURCE successor; no author execution or provider acceptance. API-v1/v2 and the bf9a7a3e / independent289ec188 history remain unchanged. This additive version records ROOT's Q01–Q03 decisions before the new focused controls execute. It changes no core contract, public export, default command count or fixed cap.

## Explicit disposition (Q01)

Provider start() rejection is an escaping execution failure, including undefined, false and a NodeProfileError/NodeUsageError instance. Internally selected profile outcomes resolve NodeCompletion.kind=profileFailure. A provider forwarding a parent request/reservation failure must finish through that explicit completion; it must NOT forward that rejection through start and then expect class/equality demotion. The parent already records its own request failure's origin. services.fail({present:true,value}) is the Node-local, execution-origin reporting route for an independent escaping provider/control failure after start has settled. It is unavailable during prepare and after retirement.

NodeReason preserves presence and reference, not origin. The owner stores origin separately. No code/name/class/equality comparison chooses origin. Source-reader, stdin, FS rejection, provider prepare/start and sink boundaries explicitly record escaping execution; the command's own admission/validation paths record profile disposition. The first escaping failure replaces a prior profile selection but is not replaced by later execution failures. Final precedence is actual caller reason > escaping execution/control/sink > cleanup failure > numeric profile/guest/completion result. An independent start rejection identical to the prior profile reason still follows its explicit escaping route. This is a provider-contract negative, not evidence that forwarding should upgrade an internal outcome.

Fatal execution or profile cancellation aborts the invocation-private parent-work signal before requesting provider retirement. Cooperative VFS work observes this signal; normal entry-return cutoff instead closes admission and drains already admitted work without aborting it. No caller/sibling signal is aborted. Retirement awaits actual provider closure and enrolled parent work; opaque noncooperative jobs cannot be declared clean or forcibly undone.

## Publication completion (Q02)

publishNodeObservation returns a Promise<NodeObservationPublication>. A genuinely asynchronous publisher must return its native Promise only after its owned publication work AND publication cleanup settle. Its caller enrolls/awaits the returned helper promise in the already-owned invocation/Worker execution. A synchronous journal publisher explicitly returns undefined; a void annotation is not proof of sync completion. Thenables and non-undefined completion values refuse. The resulting publisherFault preserves presence/value, including an undefined rejection. A fault only marks diagnostic failure; it cannot replace the original execution/caller/sink/cleanup reason. Worker publication is awaited inside the owned Worker execution; normal L retirement may abandon guest jobs, not claim them settled. A diagnostic fault is never silently converted into diagnostic success.

## Genuine FS transport (Q03)

Only a failure caught at the bound FS-operation route is eligible. Before DTO extraction, the accepted package isFsError must recognize the actual object. Proxy instances/prototypes and unbounded prototype traversal refuse. Ordinary FS-shaped objects remain the original raw failure. After genuine recognition, the own nontransported stack and cause fields are ignored without reading their descriptors' values, invoking getters, coercing, traversing or serializing either. All other own keys must be the declared finite selected name/message/code/errno/path/syscall/dest fields. Selected accessors and unrelated extras refuse. Optional fields absent or own-undefined normalize to null in the transport; the original error reference stays in parent ownership until actual postcopy delivery. A sink/control failure is never converted merely because it is a genuine FsError.

## Static reference provider, not implicit engine loading

createNodeWorkerProvider({entry,identity,observe?}) is a Node-local explicit TRUSTED host capability. entry is a canonical literal file URL supplied by the host. The shipping module imports no engine; an adapter is a separately qualified test/host dependency. The static worker-main.js loads only that explicit adapter. Its default export has exact abi/identity/execute fields; abi=NP1-ENGINE-PUBLIC-SYNC-1, identity matches the provider. execute receives request, synchronous bridge and an explicit limited(reason) callback, and returns {ok:true} or {ok:false,error}. limited reports an engine-owned limit event, not error-code inference. Bare PUBLIC95 is not intrinsically a qualifying provider or an arbitrary-source containment proof.

Worker start gates the adapter load behind parent ownership enrollment. A constructor attempt without a returned/confirmed Worker is UNCONFIRMED, never acquisition:none. Cancellation wakes the fixed SAB and requests immediate termination. Successful retirement requires actual Worker exit plus parent request/message/stdio cleanup. Unknown exit or cleanup failure retains ownership and is not clean/free. The parent grants no native process, filesystem, Worker, SAB, port, engine factory or raw builtin to guest code.

The generated facade now ends with a private cutoff(null,null,null,null,null) bridge marker AFTER guest entry returns and required primitive-print output succeeds. Parent validates actual entry and all postcopy delivery before publishing entryReturned. This is the defined lifetime cutoff, not execute() Promise settlement or all guest jobs settled. The existing entry/printRefusal/delivered/request actions remain as in API-v2. ACK is transport copy receipt; only delivered(postcopy-v1,sequence,kind,null,null) retires parent FS-error ownership and operation credit.

## Enforced profile and allocation roles

The module tokenizer, lowerer and interpreted value rules admit the declared finite grammar/member inventory and route property/call/mutation operations through kind-aware checks. Ordinary records/arrays, process.env and argv remain guest-local. This is new SOURCE enforcement requiring actual qualification, not a retrospective claim about the bf9 checkpoint. No new CLI form, local-JS loader, ESM, async-fs, Promise constructor, eval/Function, package search or native fallback is added. Promise.race([]) is the qualified pending-job form; no all-jobs completion is promised.

The same fixed caps remain: 16MiB command-owned logical ledger including1MiB diagnostic reserve;197056-byte SAB;5s admission deadline (not cleanup bound); V8 old32/young8/code8/stack4MiB; source256KiB combined trusted/user interpreted text. Multiple reservations can make individual maxima unreachable together; no lowered product caps or fabricated boundary passes. Native guest JSON/object/string allocation and V8/RSS remain distinct from this logical ledger.
