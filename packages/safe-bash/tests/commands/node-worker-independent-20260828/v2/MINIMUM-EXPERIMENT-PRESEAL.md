# Minimum next WRQ preseal — proposal, NOT a grant

This does not run or authorize a Worker, engine, compiler, product or native
oracle. ROOT must first accept the corrected design, then explicitly authorize
the concrete author recipe and a different review. Do not turn these descriptions
into counted semantic fixtures before their exact scripts/schedules are frozen.

## Gate A: exact executable inputs and DATA model

1. Freeze byte hashes for parent entry, Worker entry, interpreted scaffold,
   provider bridge, operation tracker/cancellation/cleanup code and every guest
   script/input/output. Pin the legitimate public bb23 engine, compiler if needed,
   complete emitted/import closure, package exports, Node binary and launch config.
   No live-HEAD/private fallback, native user eval, added runtime dependency or
   hidden test-only entry becomes a public command feature.
2. Resolve R1–R4 and K1's actual options/JSON/hidden-facade/cache source mechanism.
   Freeze the exact post-copy/error-handoff witness. A promise to add a hook, an
   ACK, a terminal watermark, provider strings or host-object cache cannot stand
   in for that source proof. If the public seam cannot supply it, stop at that
   precise blocker rather than fake ordinary FS catchability.
3. Seal finite allowed/forbidden state/phase/tag edges, fresh/duplicate/stale
   session/frame/predecessor cases, empty/1/65535/65536/65537-byte transfers,
   per-operation1MiB boundary, full-payload-before-effect and cutoff races, zero
   result FINAL_ACK, stop while peer owns payload, and final ACK without delivery.
   The executable model must use the same eventual implementation transition and
   validators, or be labeled a model-only discriminator, not duplicate proof.
4. Authenticate sender-before-serialization/receiver-after-decode own-data checks,
   exact control and namespace scalar schemas, prototype-independent handling,
   typed-origin versus arbitrary-code errors, and the amended optional-field rule.
   Include missing/extra/getter/hole/undefined/null/stale negatives and restored
   positives. No unlisted cross-realm VM/engine execution follows from DATA approval.
5. Seal allocation categories/overlaps, exact capture caps and cooperative producer
   contract. Use explicit operation IDs, admitted/settled/closed ledgers, byte
   effects and actual sink results. Global16MiB/RSS assertions are forbidden.

No actual Worker admission until a different reviewer accepts those concrete
inputs and ROOT authorizes execution. Do not add a broad CLI/default integration
or production API merely to make a probe load.

## Required observation and safe stopping

- Parent owns cleanup before acquisitions, including failed/late construction.
  Capture actual creation/exit separately from termination request and operation
  cleanup; no inferred exit from absent messages. Prove no-acquisition separately.
- Every record binds source/entry/session/slot/sequence/frame/operation and actual
  effect. Captures must attest loaded module bytes, not just manifests. No access
  to private sources or compiler/native fixture execution without separate GO.
- The admission timer closes at normal cutoff. A deliberately held cooperative
  cleanup is released by a presealed event barrier after exit, not a sleep-based
  fake settlement. Caller cancellation remains live during drain. A failed output
  cannot cancel a sibling merely because the destination closed.
- Unknown exit, capture failure, identity mismatch or unclosed owner stops later
  admissions. Any rescue is labeled rescue, not subject cleanup. The observer's
  own containment/cleanup authority and failure recipe need independent review;
  they are not created by a five-second command timer.
- Preserve every initial failure, role/schedule mismatch, stale-load negative,
  mutation survivor and restored-positive evidence. Real observation counts stay
  separate from DATA/model counts and original historical obligations.

A successful bounded run would support only the selected optional Worker profile
and supplied provider/launch setup, not native Node parity, original NP1's
whole-guest8MiB/all-jobs requirement, all backends, hard process-preemption or a
public default command. All of that remains outside this review.
