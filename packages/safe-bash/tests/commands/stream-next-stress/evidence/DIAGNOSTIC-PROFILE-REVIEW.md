# Pre-execution classifier self-review

Before product execution or new author-source inspection, the independent
verifier identified a weakness in its original frozen selected-diagnostic
profile. This is a harness-design limitation, not a product failure.

The raw native expectations and strict comparisons remain exact. However, the
original optional diagnostic word lists can accept a path token such as
`missing` without proving ENOENT rather than another filesystem error. The
split mode-conflict list even includes the generic command name. Therefore the
original selected profile is not sufficient evidence of preserved error meaning.

Root authorization has been requested for a separate stronger classification
profile. It must retain original inputs, raw results, strict comparisons, and
the original selected classification rather than rewrite them. Filesystem-error
categories and relevant operands must match; option/value failures must preserve
their actual error class rather than merely emit the command name or any text.
Any stronger profile is added only after root authorization. No product outcome
was inspected when raising this request, and no source fix is involved.

Until that supplemental profile is authorized and measured, any original
selected count must be explicitly labeled as the weak original policy, not
claimed as full semantic/diagnostic agreement. Strict counts remain valid for
the exact measured byte/status/namespace inputs.
