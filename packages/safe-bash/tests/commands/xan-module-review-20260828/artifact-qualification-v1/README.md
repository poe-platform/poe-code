# Artifact-only independent review v1

This namespace alone is owned. All product, root/package/configuration, AGENTS,
frozen and prior-review files are read-only. This is the assigned leaf's work;
no further delegation or worker execution occurs.

The recipe operates on DATA only. It does not import, build, execute or instrument
the candidate, the prior validators or extracted product source. The safety hold
cannot be overridden here. No product repair or runtime continuation is authorized.

## Files and procedure

- `PROFILE.md`: verbatim new root adjudication, exact delta and finite data domain.
- `prepare-data.mjs`: authenticates pinned JSON/archive inputs, generates compact
  receipt data, controls and matrices; never imports the predicate or old code.
- `predicate.mjs`: pure data predicate and bounded synthetic mutations.
- `qualify-data.mjs`: one exclusive `attempt-1`, raw decisions durably written
  before expectation assertions, no retries. Imports only the owned predicate.
- `DATA.json`: exact 30 held diagnostic receipts plus 14 separate M/`-I` guard
  receipts with original status, raw lines, input/argv/layout/freeze/source binding.
- `STILL-UNQUALIFIED.json`: all 195 diagnosis rows and all 161 original obligations,
  original mappings plus disclosed diagnosis links, counts and exact remaining
  subassertions; `MATRIX.md` is its readable family summary.
- `F11-ASSESSMENT.json` / `F11.md`: four exact historical cases, observed versus
  static versus absent evidence. Not a conditional-runtime pass.
- `SOURCE-FINDINGS.json` / `SOURCE-FINDINGS.md`: pinned source findings, uncertainty
  and future conceptual observations, not runnable reproduction instructions.
- `SAFETY.md`: exact known/missing interruption evidence and unchanged holds.
- `INPUTS.json`, `PRE-SEAL.json`, `attempt-1/*`, `RESULT-SEAL.json` and `REPORT.md`:
  input, recipe, single-attempt and delivery provenance.

Preparation is data extraction, not predicate qualification. After all manual
recipe/doc edits, preparation writes new files exclusively. Commit explicit owned
files with `git commit --only`; the qualified recipe is then invoked once with
that exact 40-hex commit identifier:

```sh
node tests/commands/xan-module-review-20260828/artifact-qualification-v1/qualify-data.mjs PRESEAL_COMMIT
```

That command is ONLY the new benign data qualification, never an alternate runner
for blocked work. It refuses an existing `attempt-1`. Do not rerun old controls.
The runner records the commit supplied by the coordinator; Git sealing checks
are separate read-only Git operations, not product execution or a trust oracle
inside the predicate. PRE-SEAL binds recipe/data/tool hashes. Input postchecks
cover the enumerated artifacts only; they do not establish an append-proof
external repository. Owned-directory checks do detect added/removed files.
