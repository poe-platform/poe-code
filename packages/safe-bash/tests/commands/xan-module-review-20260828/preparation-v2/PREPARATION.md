## Executable engines and limitations of synthetic proof

`cases.mjs` drives literal argv through a command interface, collects bounded
bytes/effects, waits registered cleanup and validates frozen outcomes. It executes
P0 for every case; P1/P2/P3/every CUT apply only to the frozen F02 list. F03 uses
fresh allocations, reused Uint8Array and Buffer.subarray storage. F12 checks
independently declared logical vectors with the pinned V1 dialect decoder.
`scenarios.mjs` defines finite workflow/lifecycle/FS constraints; each expected
trace field has a separately predeclared faulty mutant. `lifecycle.mjs` also runs
real small synthetic gate/scope/sink/identity exercises, not merely trace labels.

The synthetic command and driver modules intentionally replay trusted fixture
outcomes. They are validator fixtures, not alternate CSV implementations or
candidate evidence. Both SOURCE and physically moved executor jobs validate the
same sealed rows, schedules, family constraints, guard and resource trace logic.
Mutable author source cannot supply synthetic rows or expectations: every row
and execution-document bundle is hash-bound, and the module must carry the
synthetic-only classification. Future source-specific tracing is a reviewed host
adapter, never product self-reported counters accepted as independent proof.

The resource table's defaults/ceilings are unchanged. Small parameters qualify
generators and ledger rejection, not default boundaries. Unattainable grammar,
cardinality, quote overhead or repeat-output targets are NOT_REACHABLE, never
passes. Structural node fixtures enumerate clauses/endpoints/occurrences and
complement slots independently; actual node allocation correspondence must be
checked in source. Work traces count repeated inspected/compared/copied/encoded/
decoded/output bytes and emitted indices separately. Retained occupancy counts
owned capacity plus 2/UTF16 unit, 8/index and 32/node/span/ring slot, including
overlap before real release. Borrowed/provider memory is not claimed owned,
unbounded-safe, constant-memory, RSS or a default-scale stress result.

## Sealed adapter/handoff protocol

`admission.mjs:authenticate` is the executable schema. The handoff declares
`schema: xan-different-review-v2`, `classification:
ROOT_ROUTED_IMMUTABLE_CANDIDATE`, final freeze, full candidate/base/tree SHAs,
and exact XAN-module-only delta. The exact base is
`5137a74ec855a32d8a8860eb66b62eb44d11e290`; default registry remains 77, with no
public XAN export. No replacement of unrelated base files is admitted.

Every selected source/build/runtime/tool/receipt/adapter/consumer entry carries
path, mode, exact bytes and SHA256; Git inputs also carry blobs. JSON receipt
references are full descriptors, not truthy strings. Build receipts bind actual
candidate, input/output/tool manifests, executable identity, argv, zero exit,
reaped/nontruncated/non-timeout settlement and emission grant. Pack receipts bind
the build receipt and exact emitted module tree. Scope and reviewed adapter
receipts bind the same candidate. Actual replay still authenticates Git trees,
exact deltas and blobs, and checks artifact/layout trees before and after.

The review-tool adapter exports `openReview({module, factoryExport, options})`.
These are test-protocol names, not invented product APIs. It returns actual
`command`, `runShell`, `runLifecycle`, `runFilesystem`, `runResource`, `runGuard`
and `dispose` bindings. The driver arguments are the executable frozen scenario,
resource and guard specifications, plus exact local reference objects where
identity matters. Root must authenticate its source review and actual candidate
factory, local registration, FsError and source-capacity/lifetime mapping.
Drivers capture events/effects from actual calls, not copy expected traces.
They release every admitted cooperative gate and return closed/intact receipts.

SOURCE and INSTALLED_MOVED use independent subprocesses and exact runtime plus
adapter manifests. Installed execution copies selected files into a new owned
staging directory, physically renames it, verifies the old path absent, and
denies the original layout/source fallback. The module loader permits only
manifest entries and reviewed safe builtins; Node permissions deny native child
processes and outside reads/writes; string code generation is disabled. Trusted
supervision/Git evidence utilities alone spawn bounded processes without a shell.

`run-selected-build` is an optional authorized reproduction of a previously
authenticated selected build receipt. Its only write grant is a new owned
emission directory; source, tool, declarations and all other original paths stay
read-only. Compiler argv is bound by the handoff; only the explicit
`$OWNED_EMISSION` token is replaced. Emitted files must match the exact expected
output manifest. This is neither product execution nor runtime acceptance.

## One qualification and evidence discipline

The recipe, inputs, tool hashes, supervisor and complete COHORT.json are committed
before one `qualify-synthetic` invocation. The evidence directory uses exclusive
creation, so accidental reruns refuse. No post-seal expectation correction or
retry-to-green is permitted. Each planned control is synthetic-only; expected
negative kill/exit cases are separated from natural positive completion.

Supervision streams raw bytes with a full-delivered digest and separately records
retained artifact bytes/hash and truncation. Normal logs are 16,384 bytes; CLI
preview is 1,024 characters. The finite large stream is 5,242,897 bytes, never
retained as giant JSON. JSON admission allocates only each artifact's exact
declared size; this is distinct from 65,536-byte transport and not an RSS claim.
Required missing/failed phases and raw overflow cause durable nonzero aggregates.
Ordinary failures continue only after closure and integrity verification;
unreaped/cleanup/integrity breaks stop dependent work. Evidence inventory checks
new entries as well as original file bytes/modes, without rewriting old evidence.

Before sealing, `node --check` found one duplicate local binding in runner.mjs;
it was corrected with apply_patch. No qualification ran during these static
checks. Other preseal refinements were manual reviews, not hidden test retries.
The handoff records the actual one-run outcome, including any failures/unrun
controls. V1's 74 controls/21 children remain separate historical helper proof,
not rescored or counted as this cohort.
