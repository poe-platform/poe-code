## Capture and Proof Roles

Actors MUST capture bytes, events, effects and thrown-reference facts before
external assertions. Local actual reason references MUST remain in-child;
JSON descriptions are not identity evidence. Captured numeric command status
MUST remain unchanged. Actor capture failure MUST remain independently sticky
even if a fake or future command catches the sink failure and returns zero.
The future bridge MUST persist raw capture first and fail independently on
`local.harnessFailure` or a false terminal `captureComplete`; it MUST NOT infer
success from the command status alone.

An OBSERVED input-binding row means the concrete input/mechanism was observed,
not that every natural-language assertion is true. `obligationComplete` remains
false. Private assertions and UTF22 retained ownership remain UNOBSERVED;
available bytes and events still remain available for independent assertions.
Source-primary WRK06/07/13 observations are supplementary raw events, not
discharge of core-owned source arguments. Runtime and synthetic roles MUST be
kept distinct; `SYNTHETIC_STUB_ONLY` cannot be admitted as candidate evidence.

The host drain records its own cooperative waiting separately from target
settlement. It MUST NOT claim the target waited merely because the harness did.
No guarantee of terminating opaque work, instantaneous timers, hard RSS limits
or host sandboxing is asserted. No Budget construction/reset/cap replacement or
counter injection is performed; private calls use only existing session roles.

## Resource and Integration Contract

Every catalogue profile requests one future outer slot, zero nested tools and
at most30000ms total wall allowance, including future loading/guards/cleanup.
The future parent MUST pass only the remaining absolute allowance to the actor;
the actor's local elapsed check cannot reset or extend the parent deadline.
Requests are not granted budgets. Catalogue stdout/stderr maxima remain inside
the existing16MiB worker capture and32MiB per-job evidence ceiling; actor command
output also keeps the existing2MiB combined host-fixture ceiling. Metadata is
bounded separately with a terminal reserve; actual final metadata size is checked.
No full public WRK17 output boundary is claimed under that host cap.

Each profile requests12MiB filesystem evidence storage,1MiB metadata and20000
events. Fixtures are generated in memory, never materialized as input files by
these actors; the largest declared source is8388609 bytes. That source size is
not a simultaneous heap/RSS claim. Final serialized capture size is checked;
overflow retains a bounded prefix and failure record, never acceptance.
The synthetic tranche has one parent and one child, no descendants, ten cases,
60s child cap,256KiB per-stream supervisor buffer and bounded exclusive captures.
No retry follows an unexpected child failure. All source/tool/import identities
MUST be committed in SOURCE-PRESEAL before synthetic execution.
