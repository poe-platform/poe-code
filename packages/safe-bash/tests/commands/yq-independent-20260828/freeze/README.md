## Normative Language

`MUST` and `MUST NOT` below govern evidence handling only. Product expectations
are subordinate to the authenticated adopted contract, not new requirements.
The future replayer MUST distinguish a frozen assertion from an observed result
and MUST NOT count a blocked case, preparation check, or missing harness as a
product pass. No implementation or replay is authorized by this packet.

Goals are original minimal examples, exact authority bindings, preallocation and
shared-counter witnesses, chunk/cleanup/effect assertions, type-consumer cases,
and explicit gaps. Non-goals are a YAML implementation, native oracle, copied
test suite, broad source archive, public limit injection, invented API, exhaustive
grammar coverage, performance/heap proof, compatibility or superiority claims.
No official example or third-party fixture is copied. Syntax was checked against
the primary YAML specification; all concrete input constructions are synthetic.

## Case Model and Interpretation

The five case JSON files contain **194 records**, not 194 executed tests and not
an expanded count of all parameter variants. Defaults apply only to literal
command cases: JSON compact identity, empty stdin, no writes. Explicit argv
replaces rather than appends defaults. `scenario` and `typescript` are inert
descriptions, never evaluated strings. `stdinRecipe` is a fixed bounded fixture
constructor; it is not a parser, oracle, public API, or limit-injection hook.

`documents` records the ordered semantic query results using JSON notation.
It is not permission to decode expected values through the product under test.
Byte assertions are exact where supplied; internal identity/prototype assertions
need separately authorized observation. No exact spelling is invented where the
adopted encoder permits multiple legal escape presentations. A blocked record
can retain settled partial assertions, but its unresolved portion has no golden.

For WORK records with a boundary/projection, `status`/`diagnosticCode` apply only
to the over-limit variant. Passing a particular admission does not assert whole
invocation success. Counter traces isolate the specified admission with other
caps having slack; they do not prove the state is reachable through public CLI.
In particular maxSteps may make huge input/output/result/node boundaries
unreachable first. No public limits or mutable Budget is invented to force them.
Fixed work caps must not be weakened to make a boundary run.

Authority aliases resolve as follows: `initial#section` is the sealed initial
README; `final#/pointer` and `adoption#/pointer` are JSON pointers; `primary#section`
is the primary reference; `baseline:name` and `length:commit` identify selected
Git sources. `freeze#integrity` refers only to this packet's integrity procedure.

Effect profiles are exact future assertions:

| Profile | Required observation |
| --- | --- |
| read-only | VFS bytes/namespace unchanged; only explicit virtual inputs, signal forwarded; no host files or writes |
| information | Status 0, exact help/version stdout; no session/Budget/compile/stdin inspection/input-VFS acquisition; normal output cleanup/backpressure |
| cli-rejection | No compile/session/stdin/input-VFS/stdout acquisition; only selected bounded stderr permitted |
| compile-rejection | One failed compile attempt, no input or stdout acquisition; only selected bounded stderr permitted |

## Replay Prerequisites

All cases require root authorization, accepted additive reviewer reconciliation,
and an authenticated immutable candidate. There is currently no product replayer.

| Identifier | Required before the described assertion can run |
| --- | --- |
| R-CANDIDATE-AUTHENTICATION | Authenticate exact baseline, accepted length delta, candidate tree/diff and test sources; no unrelated live overlays |
| R-INTERNAL-OBSERVATION | Separately approve a bounded observer/test seam at the actual private implementation; no public DI, resettable counter, fake engine pass or copied parser |
| R-HOST-HARNESS | Bind direct `CommandDefinition.execute`/existing contract host resources and raw-rejection identities; observed event ordering, deterministic cooperative cleanup and bounded timeouts |
| R-PUBLIC-CONSUMER | Authorized build, inspected real package exports/declarations, strict NodeNext consumer and actual Shell/registry invocation; no proposed-name import before integration |
| R-AUTHORIZED-ADAPTER | Explicit configured real/remote root or endpoint, permissions, exact input/effect captures and provider qualifications; no ambient credentials |

Direct-handler rejection and outer Shell behavior MUST be recorded separately.
An outer downstream-close numeric result is not itself a yq raw-failure defect.
Compile is synchronous and not fully metered by maxSteps. Source/AST admission
does not imply preemption. Engine graph checks occur after engine allocations;
owned composer/alias/encoder projections precede their controlled allocations.
Input received bytes are charged once; output is charged once before first
submission and never reclaimed following a rejected write. Cleanup scopes for
stdout/stderr are siblings; no whole-context cancellation to close one sink.

Before any future oracle execution, a separately authorized sealed protocol must
bind executable/package, inputs, environment, bounds and unique output location.
None is authorized now. Historical just-bash 3.4.2 single-positive evidence is
not a current comparator cohort or parity proof.
