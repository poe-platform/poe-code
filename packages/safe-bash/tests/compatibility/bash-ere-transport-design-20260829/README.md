## Nine concrete integration risks

1. **Five-field result omits cumulative state use.** Keep exact result {matched,groupCount,spans,steps,allocatedUnits}; use the source-defined seven-key EreUsage as a separate envelope. Engine usage.states is cumulative admissions, usage.work maps to result.steps. The current EreLedger.usage getter permits post-failure snapshots; wire validation must still prove all fields. Engine EreResult has captures/values, not the five-key transport result; its no-match vectors are empty. The adapter must use the same-module compiled program.groups to canonicalize0..N without transporting AST/values.
2. **Root accounting cannot be per Worker/session/state clone.** Shell.exec creates fresh Budget/scope (shell.ts165); descendants pass the same Budget (runtime.ts957,1391,1985,2488). Key a private root owner by that identity, enroll it at the root, and share a single reservation ledger. No resets on timeout/restart/invoke, and no refunds from absence of replies. Exact numeric formulas and parent-copy unit weights were proposals in the supplied clarification; no additional ratification is inferred. The new unaccepted engine now implements those exact formulas and five cumulative/two high-water semantics; integration must explicitly bind/ratify them and parent transport accounting before positive boundary fixtures.
3. **Acquisition and cleanup are not interchangeable with promises settling.** Existing withRegexSession registers before open (client.ts28); Slot constructs Worker before installing handlers (78), and pump's catch rejects without a partially acquired Slot handle (202). These are SOURCE-only fault-injection risks, not an observed existing leak. ERE owner must enroll acquisition immediately, contain every later throw, retain failed retirements, and await all owed cleanup. Root close cannot settle just because a request rejected.
4. **Falsy failures/provenance cannot use truthiness or nullish terminal storage.** Existing Slot uses terminal ??= and undefined sentinel (91), while run separately consults the actual signal (223). Do not generalize that storage to ERE arbitrary rejections. Use explicit presence+origin; preserve undefined/null/false/0/empty-string reasons, caller/control precedence, and cleanup secondaries. No class/name/equality-based conversion of arbitrary host errors to status3.
5. **Legacy validation is not the new hostile-frame validator.** protocol.ts94 checks Object.keys and later accesses fields; startup client.ts231 uses in/property access. Leave those expr contracts unchanged, but new ERE validation must inspect finite own DATA, reject proxies/accessors/extras/holes/NaN/-0/replays before copying, distinguish null participation from [k,k], and validate full0..N cardinality and checked usage/capture sums. Bounded deserialization is not a hard parent-memory claim for an arbitrary compromised Worker.
6. **Shipped internal declarations are observable.** src/index.ts5 exports RegexExecutionOptions; package files=dist ships protocol/client d.ts despite no regex-execution export subpath. Preserve the eight public options, Descriptor/Request/Reply/RegexErrorCode and every Expr* shape. Preferred additive placement is a sibling private ERE executor/session/entry in the same subsystem, not widening old request overloads. This packaging choice needs ROOT approval if “existing executor” strictly requires the same RegexExecutor class/pool; no invisible refactor is assumed.
7. **Loader/asset authority does not inherit old qualification.** Existing Slot uses static worker.js, source-to-dist fallback and execArgv:[]; workerData/env are omitted. New engine imports/new ERE Worker change the closure, while [] does not inherit parent loader hooks. ERE uses an explicit inert WorkerData schema and empty env; any bootstrap execArgv must be separately pinned/approved, not copied from process.execArgv or enabled by old Node/SafeJS permissions. Old expr Worker construction remains unchanged.
8. **Capture/output publication is a separate transaction.** Successful matching is not permission to allocate strings or write BASH_REMATCH. Validate spans and checked total capture bytes/slots, reserve complete array staging plus old/new overlap, recheck caller, then let the separately owned runtime writer publish atomically. Syntax/unsupported/private-limit/transport failure preserve old captures. Actual expansion/output sink failures remain original ShellLimitError/raw failures; private capture limits are status3, never synthetic public expansion-fields errors.
9. **Error/observation settlement needs a single owner.** Current RegexExecutor has no public observer hook. Do not introduce one implicitly. Future test observers are source-bound instrumentation; any admitted async observer must be an owned awaited host job, never fire-and-forget or allowed to replace a primary reason. Startup/request timeout, crash, protocol violation, worker error and failed retirement stay execution/cleanup failures, not syntax2/no-match1. The existing conditional wrapper needs an explicit ERE mapping branch only after N14 acceptance; it must not swallow status3 inside !/&&/||.
