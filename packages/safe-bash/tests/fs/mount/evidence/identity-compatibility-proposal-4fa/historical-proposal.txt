SMALLEST NATIVE-DELEGATION CONTRACT OPTION (PROPOSAL, NOT APPROVED)
  FileSystemCapabilities.guardedCopy?: boolean
Meaning true: this backend's copyFile authoritatively rejects actual same-entry
aliases with EINVAL (exclusive existing target EEXIST) BEFORE source acquisition,
destructive writes or publication, for every supported pair in its own namespace;
unsupported/unprovable pairs fail ENOTSUP before effects. It preserves the source
on destination failure, forwards cancellation, and honors exclusive creation.
It does NOT promise destination rollback, atomic rename, disjointness from another
backend, or lease/ABA/pathname stability. Absence/false conveys no such guard.

Mount may delegate unknown identity only when BOTH resolved paths use the exact
same backend object AND that explicit native-operation promise is present; keep
known-alias/exclusive checks first. Reference equality here routes one operation
authority, NOT an assertion that different objects have disjoint storage. This
also covers one backend mounted twice without streaming it through itself.
Do NOT infer the promise from class/name/protocol/readOnly/atomicRename/method
presence. Remote owners must verify native behavior before advertising it;
S3's direct same-path success needs reconciliation, and arbitrary WebDAV servers
must not acquire this promise merely because they implement COPY/LOCK.

This option restores qualified same-backend native copies only. It is NOT full
cross-backend compatibility closure. Blindly moving same-mount delegation above
the unknown guard is source-only but lacks this explicit arbitrary-provider
safety promise; I do not recommend presenting that as a universal repair.

MINIMUM ADDITION IF CROSS-BACKEND REMOTE COMPARISON IS REQUIRED
  type EntryComparison = "same" | "distinct" | "unknown";
  FileSystem.compareEntry?(
    path: string, peer: FileSystem, peerPath: string, options?: FsOptions
  ): Promise<EntryComparison>;
This is an alternative proof seam when providers cannot truthfully publish the
already-approved complete tuple; it does not replace/redefine identityScope.
Compare the actual followed entries (copy semantics) using native/provider/shared
negotiated identity authority, metadata-only and before source/target effects.
Unknown remains unknown; equal content/ETags, distinct clients, roots, URLs, or
unrelated tokens NEVER establish distinctness. Peer recognition must use explicit
shared authority/registration, not casts/private reflection/constructor tests.
Wrappers route both operands to their actual selected backing views; readonly
cannot erase its policy, and overlay must resolve its actual selected entry.
The consumer can try either authority once; unknown does not authorize writing,
and contradictory authoritative answers fail before effects. This seam can
authorize distinct-key streaming without fabricated numeric inodes or per-client
disjoint scopes. It cannot manufacture knowledge for unnegotiated arbitrary
clients. Do not add both seams by default: Curie/root should choose the smallest
native-operation or comparison proof actually available from remote owners.
