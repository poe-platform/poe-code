## Candidate acceptance criteria, frozen before inspection

1. Inventory candidate changes by exact original test/case IDs. Preserve every
   original source string, stdin, fixture, expected status and effect; changes
   to invocation/name/profile require an explicit uniform helper boundary and
   a side-by-side original context archive. No mass golden rewrite.
2. One supported modern profile for the entire affected cohort. GNU absence
   must fail clearly, never skip or silently select Apple 3.2. Keep historical
   strict diagnostic expectations as separately named evidence rather than
   disguising them as the supported modern assertions.
3. Compare stdout **and stderr bytes**, status, files and existing assertion
   fields. No status-only comparison, discarded stderr, blanket substring
   relaxation, per-case binary selection, skip/xfail or stdout normalization.
   Additional mode observations remain explicit: old suites did not assert
   modes, and their absence does not justify an independent full-tuple parity
   claim. A mode-only difference is not silently changed into equality.
4. Registry truth is a distinct supported-plugin contract, not native parity.
   Prove native `printf` is builtin with native type output; prove actual virtual
   registry membership and the truthful `command`/`registered command` output.
   Keep the two native raw losses. Independently authored exact safe-plugin
   tuples in `review-checks.mjs` are not made by replacing native output strings.
5. The three added controls exercise named diagnostic line/source identity,
   NUL/stdout/stderr/status/file/mode fidelity, and truthful plugin classification.
   Mutations must reject wrong status, omitted stderr, changed stdout, file bytes,
   mode, source/name/line/profile, mass rewritten expected records and a fake
   builtin label. Each later candidate review must rerun the negative controls;
   their own passing status means detection works, not shell feature coverage.
6. Verify all original input hashes and candidate diff, actual archive/import
   hashes and full source/export inventory. Record each loaded dependency and
   symlinked development toolchain before/load/after. A stable runtime hash alone
   does not establish a stable product import graph.
