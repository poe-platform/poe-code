## Frozen acceptance principles

1. Each original-five adaptation must start **exactly one owned source read or
   request**, release its original `started.promise` middleware barrier, then
   cancel that work on downstream close before any first write. Keep the exact
   1200ms inner bound and original command `producer | head -n 0; true`.
   HTTP GET-entry counts are request counts, not body-read counts. A zero-start
   implementation, speculative demand gate or successful timeout is a failure.
2. Enrollment is optional, explicit and bound to the actual output sink/context,
   before admitting/acquiring owned work. Only that enrolled operation is
   canceled on that output's close. Assert separately that the operation signal
   aborts with EPIPE while stage and caller remain live, and actually complete
   a VFS/stderr effect using the live stage afterward. Do not merely compare
   signal object inequality. No automatic enrollment of arbitrary commands.
3. Borrowed/shared stdin is not output-owned. Preserve real shared input bytes
   and return counts through sequential actual Shell consumers. Intentional
   no-enrollment is appropriate when source ownership is not exclusive; it
   still must execute the positive workflow, not merely reject an API call.
4. Unused stdout cannot cancel independent files, stderr, normal empty work,
   delayed error completion or other/nested output lifetimes. Curl request/body
   ownership depends on all actual destinations, including `-o`, `-D`, and
   `--write-out`, before response headers arrive. Preserve needed file/header
   work, not just admission. Do not suppress diagnostics to turn failures green.
5. Reuse the existing cooperative cleanup ownership contract where possible:
   register synchronously before acquisition, close admission, use the same
   idempotent cleanup from finally, and share its pending completion across
   overlap/disposal. Await registered cooperative work, never opaque host
   acquisition/handler promises. Observe their late rejections. No global drain
   or hard-preemption claim is permitted.
6. Existing public precedence remains: observed caller abort wins by exact
   identity; otherwise preserve a selected execution rejection; otherwise sole
   cleanup rejection unchanged or AggregateError for multiple; otherwise the
   selected result. Internal EPIPE is not caller abort. Preserve pipeline status
   selection, including existing 0/7/141 controls, with/without pipefail as
   specified in the cases. Do not invent a generic cancellation exit status.
7. Normal writer completion is not downstream reader-close cancellation.
   Unsupported sink close-notification must be reported honestly: absent or
   explicitly unsupported capability, never an invented close event or silently
   successful enrollment. Ordinary ByteSink use must remain valid. Do not
   introduce a zero-demand scheduler; ordinary bounded queue acceptance remains.
