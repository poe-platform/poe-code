## Proposed internal structure (not a public API/signature)

One private owner per public exec, one private scope per dispatched invocation, explicit parent/child links and separately cancellable pipeline/nested branches. Scope states open -> closing -> drained; close seals registration/invoke first, snapshots admitted hooks/children, drains ALL even after failure, and memoizes completion. Scope admission is synchronous and fail-closed. Child scopes are linked before calling any user code; closed ancestors reject late invokes before acquisition. A closed-over registration capability checks state at call time. Normal/error/cancel/dispose all converge on the same scope close. Reentrant hook registration is rejected. No mutable process-global current-scope variable or runtime-wide cancellation of sibling execs.

Error selection is separate from drain: caller's original abort reason by identity > original execution rejection > cleanup failure. Preserve undefined thrown/rejection values using explicit presence flags, not truthiness. Internal PipelineClosed is a stage-control result, not caller priority. Every cleanup rejection is observed and retained internally even if secondary; never mutate the primary Error or invent a new public error channel. Parent drains cannot double-count identical child failures. Closed scope makes late work fail before invoking acquisition, but arbitrary host code can still ignore the contract; no hard-preemption claim.
