## Binding decisions for the design author

- **P1 — options and publication.** `+` clusters contain only `x`; `-` clusters
  support `a/r/p/x`. Scan tokens/letters lexical left-to-right: `a/r/p` are sticky,
  the last `x` sign wins for scalars, and every request retains any-x-operation
  provenance. Validate the entire leading option region and global invocation
  usage before declaration-target publication. First operand or exact `--` ends
  option recognition. Named `-p` ignores supported attributes without mutation;
  unsupported flags still return 2. Unnamed listing intersects selected negative
  attribute filters and rejects any `+x` with 2. Scalar-syntax duplicates remain
  sequential; compound/element duplicate targets are global usage 2.
- **P2 — export guard.** A separate successful scalar `+x`, followed by later
  array conversion, is explicitly authorized. Same-invocation toggles cannot
  bypass the entry-exported scalar/exported-unset guard. Any `x` operation on
  an existing or requested indexed binding returns 1 regardless of its final
  sign, except named print's ignored attributes. Existing readonly/control
  guards remain; no export-history taint rule is introduced.
- **P3 — declaration and local absence.** Missing names and hidden local absence
  query with 1/no record; declared-unset queries with 0 and no assignment in its
  printed record, distinct from set-empty. Whole local unset removes observable
  membership but retains the owner-frame absence barrier. Nested unset changes
  the owning caller frame; nested local redeclaration saves/restores that absence,
  not the concealed parent. The original owning function's exit restores the
  exact saved binding and attributes once. Explicit `declare` recreates unset
  membership without a value, preserving the original frame save.
- **P4 — status, effects and precedence.** Invalid invocation usage returns 2
  before target publication, without undoing earlier expansion/redirection
  effects. Ordinary identifier/query/readonly/type/export/control/domain/stale/
  serialization refusals latch 1 and continue applicable operands/records;
  later success cannot clear it. Preparation/resource failure stops. A canonical
  decimal index outside `0..2147483647` is domain 1, not grammar 2. Private ledger
  exhaustion returns 1/stops; public `ShellLimitError` rejects, not 125/126.
  Earlier resource failure prevails over an undiscovered error. Final publication
  checks cancellation, then readonly, then stale; charged earlier preparation
  cannot be bypassed. Sink/abort/cleanup retain existing route-specific
  settlement/rejection precedence, not a new universal status mapping.
- **Diagnostic capacity.** Use admitted capacity or checked reservation. If
  capacity cannot admit the diagnostic, stop with 1 and **NO diagnostic**: no
  uncharged bytes, counter reset or continuation. This is not permission to
  suppress an attempted sink/public-budget failure or override settlement.
