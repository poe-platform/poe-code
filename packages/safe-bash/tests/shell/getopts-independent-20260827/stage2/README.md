Bounded freeze and native evidence only. **Not a usable builtin or runtime gate.**
Sixteen integration scripts, twelve host/profile invariants, two explicit fixture
bodies and three pending root decisions. No canonical discovery or default test
count change; `.data` fixtures are explicitly native/VFS input data, not TS tests.

## Inputs and support

`corpus.mjs` is the normative script/expectation corpus. Its productScript values
use only existing scalar grammar and supported routing except pending getopts
itself. Functions, arithmetic assignment, parameter assignment, read redirection,
for, local/export/readonly declarations, prefix assignment, groups, source, eval,
subshells, pipelines and substitution already exist. Existing `printf` command
support is a harness prerequisite, not a getopts plugin or a false builtin claim.
`builtin`, `declare` and `typeset` commands are unsupported at baseline; neither
their implementation nor general arrays/namerefs are demanded. Native-only
`declare -p` preludes observe startup attributes and are not product script bodies.

For future VFS replay, cwd is `/review-stage2`; fixture contents are the exact
committed `fixtures/reset-input.data` and `fixtures/shared-source.data` bytes at
the paths in `invariants.json`. Native cwd is this sidecar; there are no fixture
outputs or implicit host source paths. Normal stdin is closed; the read scenarios
explicitly redirect the frozen input file. All native scripts are finite and use
only native builtins; no installation, network, external utility or stress matrix.

## Intentional policies and open decisions

I05 forbids readonly OPTARG deletion/attribute stripping despite the native quirk.
I06 requires ASCII options, permits Unicode values, and rejects native byte-option
emulation. N12-N15 native readonly status/partial effects are observations, NOT
automatically accepted product expectations. D01 needs explicit root ordering/
status decisions; D02 needs shared-budget and failure publication mapping; D03
needs invoke/middleware hidden-state ownership. Host controls remain definitions
until the released API is inspected. They are neither executable passes nor new
public controls, signatures, blanket failure statuses or rollback promises.

## Opt-in tooling and preservation

`prepare.mjs` creates baseline/freeze artifacts with exclusive writes; it does not
launch any candidate or native script. Commit all frozen paths explicitly first.
`capture.mjs` requires that committed freeze, authenticates both supplied Darwin
binaries before/after, and exclusively creates `capture-01`. It captures 16 scripts
per profile and one version query per binary, with C locale, sanitized environment,
closed stdin, five-second/128-KiB bounds and awaited process closure. Raw exact
stdout/stderr plus byte encodings are preserved; stderr predicates are explicitly
partial semantic assertions, not universal diagnostic-byte parity. Historical3.2
results are compared separately to selected5.3 expectations, never pooled passes.

`node tests/shell/getopts-independent-20260827/stage2/verify.mjs` checks frozen
inputs against their commit, capture integrity and separate sidecar inventory.
`--seal` exclusively creates the evidence manifest; `--committed` also checks the
complete sidecar against its evidence commit. No candidate, oracle, TypeScript
compiler or old Phase1 verifier runs in this integrity tool.
