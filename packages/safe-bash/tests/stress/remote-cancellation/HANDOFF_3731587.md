the author's new test cases were not used as an oracle. Each test has an 8-second
outer bound, individual asynchronous settlement gates use 1200 ms, and deadline
cases configure a 60 ms adapter request timeout. Durations are functional test
observations, not performance benchmarks.

## Cancellation policy and validation boundary

The original audit's no-new-operations assertions were not weakened. The
supplement separately checks that no request begins with an already-aborted
operation signal. After caller cancellation or observed deadline settlement,
the permitted request sequence is empty **except** in V04/V05: exactly one
UNLOCK, to `http://independent.invalid/dav/target%20%C3%BC/`, with the exact
granted `Lock-Token`, using a fresh request signal. No COPY, MOVE, GET, PUT,
metadata revalidation, or other normal operation may resume. This is a narrow
authorized cleanup exception, not blanket permission for post-abort I/O.

The late-response cleanup gate validates redirect state, supplied final response
URL confinement/resource identity, status 200, and a syntactically valid token
header. **It does not read or fully validate the late LOCK XML body.** Normal
non-abandoned LOCK acceptance separately validates the XML grant. Tests assert
zero late XML-body pulls so the distinction is explicit. Synthetic Responses
can have an empty URL under the contract; the new LOCK cases explicitly supply
a URL, and the valid case uses the actual MockDav grant/token/body.

"Foreign" here means a token supplied by an untrusted/foreign final response,
not a token URI whose text happens to contain another authority. LOCK tokens are
opaque identifiers; this test does not invent token-URI same-origin validation
that the contract does not provide, nor prove a malicious trusted transport
cannot fabricate a well-formed token on otherwise acceptable response metadata.

Outward settlement is not rollback, forced host completion, or cancellation
atomicity. Accepted PUT bytes remain in V02; accepted LOCK state exists after
the outward rejection in all LOCK cases; an ignored/rejected UNLOCK can leave a
lock until server expiry. Cleanup is best effort and can itself outlive the API
call. Fixture teardown settles/releases deferred work and clears remaining mock
locks, and those fixture actions are not attributed to the product.

## Injected versus native limits

All twelve selected rows use injected transports; there are **zero actual HTTP
requests or sockets** in this follow-up. The supplemental cases use the pinned
MockDav through public `WebDavFileSystem` methods and Node WHATWG Response/body
objects. Final-URL/redirect metadata is explicitly injected on Response objects
for validation probes. The `.invalid` hosts are labels only; no DNS or Fetch
network call occurs. No credentials, production endpoints or runtime dependency
installs are involved.

Ignoring the provided signal is intentionally nonconforming transport behavior
used to test outward robustness. Results do not establish native Fetch socket
closure, real-server lock expiry, remote-provider interoperability, or forced
termination of uncooperative host work. The original audit's native/injected
distinction remains unchanged.
