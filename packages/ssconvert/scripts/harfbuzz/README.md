# HarfBuzz artifact maintenance

Normal verification reads the committed generated string, parses its TypeScript
literal without evaluation, validates the WASM import/export and memory ABI, and
checks the compiler input and license digests. It does not download, instantiate
WASM, or invoke a compiler:

```sh
node packages/ssconvert/scripts/harfbuzz/verify.mjs
node --test packages/ssconvert/scripts/harfbuzz/verify.test.mjs
```

To reproduce the artifact, supply the complete `src` directory from HarfBuzz
commit `863d3f7787c6df18d20e4535c5906bf3eb803bd5` and an already installed
Emscripten 4.0.13 `em++` executable:

```sh
node packages/ssconvert/scripts/harfbuzz/build.mjs /absolute/harfbuzz/src /absolute/emsdk/upstream/emscripten/em++
```

The script authenticates the complete upstream source tree and compiler version,
copies sources into a fresh repository `out` directory, applies the exact owned
patch, checks every patched digest, and builds with the recorded flags. It uses
an isolated Emscripten configuration/cache/temp directory and the current Node
executable. It never installs or activates a toolchain, mutates the supplied
source tree, or changes global configuration. The result must match the frozen
artifact digest before `data.ts` is regenerated. Build output stays under `out`.

The upstream harfbuzzjs build recipe at commit
`b2ec00c97159ee8aa563691792aa3081adbc8a50` supplied the Emscripten 4.0.13 baseline.
The maintained recipe deliberately retains full shaping instead of its
`HB_TINY` reductions. `exports.json` is the production ABI: fault injection,
allocator reset and test-only preallocation exports are excluded.

`completion.patch` changes only failure reporting. `allocator.cc` implements
HarfBuzz's `HB_CUSTOM_MALLOC` hooks and the public failure accessor. HarfBuzz
sources and all generated bytes remain subject to the notices in the runtime
asset directory. Changing source, flags, hooks, or exported ABI requires renewed
native differential and failure qualification before updating the manifest.
