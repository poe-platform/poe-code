### Exact classifications

1. **Unterminated EOF context:** all generators emit the same patch for
   `a\nz` -> `b\nz`. Forward application succeeds everywhere. Reverse succeeds
   on GNU/product with status 0 and `a\nz`; Apple returns 1, retaining `b\nz`.
   This is an Apple self-roundtrip limitation, not a product fix request.
2. **Zero-context beginning deletion/insertion:** GNU/product emit `+0,0` or
   `-0,0`. Apple emits `+1,0` or `-1,0`. For Apple-generated beginning insertion,
   both native patch binaries return 0 but produce `b\na\n` rather than intended
   `a\nb\n`; product repairs it. Reversing Apple's beginning deletion gives
   `b\na\n` on GNU but `a\nb\n` on Apple/product. GNU-generated beginning deletion
   reverses correctly on GNU/product; Apple returns 1. Do not use Apple-generated
   coordinates to redefine the product's canonical output or infer a GNU bug.
3. **Zero-context interior deletion:** all generators agree on `@@ -2 +1,0 @@`.
   Reversing from `a\nc\n` yields status 0 and `a\nb\nc\n` on GNU/product;
   Apple returns **0 with wrong bytes `b\na\nc\n`**. Status-only checks miss this.
4. **Asymmetric fuzz `-F1`:** the literal no-leading-context fixture from the
   existing suite succeeds on GNU/product (`new\nactual\n`) and fails on Apple
   (1, unchanged). The `-F0` rejection control and symmetric `-F1` success control
   agree on all three. Existing BSD-policy failure is not a GNU product gap.
5. **Displaced asymmetric exact anchor `-F0`:** GNU **and Apple reject**
   `head/-old/+new` when `prefix\nhead\nold\ntail\n` has trailing material;
   product accepts it. GNU's pinned `patch.man:96` explains that excess leading
   context requires EOF, even without fuzz. Removing `tail` or adding it as
   symmetric patch context succeeds on all engines. Do not classify this as an
   Apple oracle bug. Product differs from GNU; root must explicitly choose and
   document a permissive policy or preserve it as a compatibility gap. The
   bundled manual's SHA256 is in `provenance.json`.
6. **`/dev/null` deletion and reversal:** without `-E`, GNU/product delete the
   file; Apple leaves an empty file with status 0. GNU/product reverse creation
   from an absent target; Apple returns 1. GNU also reverses into an existing
   empty file; product returns 1 (`creation target already exists`) and Apple
   returns 1. Ordinary same-name all-line deletion leaves an empty file on all
   engines; its reverse succeeds on GNU/product and fails on Apple.
7. **`-E` is distinct:** both native binaries remove an emptied target for both
   ordinary and `/dev/null` deletion. GNU reverse cases succeed. Apple reverse
   cases fail; with `-E`, an existing empty input may additionally disappear.
   Product returns 2 (`unsupported option: -E`) in all five explicit `-E` cases.
   Do not inject `-E` into all native calls and thereby hide default differences.
8. **Whitespace `-l`:** in the final capture all engines accept tab/space runs,
   preserve actual context, and insert literal addition whitespace. Exact-match
   and strict-rejection controls pass; removing a required blank run returns 1
   on all three. An earlier product `-l` unsupported gap was fixed concurrently.
9. **Normal/context:** all three diff generators now emit matching normal and
   `-C1` output on the small append/change/delete workload. GNU/Apple patch apply
   and reverse both. Product patch still returns 2 with
   `patch: expected --- file header\n`, retaining old input. Twelve generated
   cross-applications plus two independent literals are 14 visible product
   failures, not 14 distinct missing features.

The 20 product intent failures are those 14 normal/context cases, five `-E`
cases, and `/dev/null` reverse into an already existing empty file. No source
changes, permissive golden rewrites, or expected-failure inversions were made.

## Recommendation for existing suites

Keep original Apple observations immutable and report the unmodified live-native
denominator separately. Prefer pinned GNU references for canonical generation
and GNU-policy acceptance, but retain Apple interoperability tests and explicit
bytes/existence assertions. Separate generator defects, patcher defects,
intent-based roundtrip properties, and selected-policy agreement.

Do not blindly replace every `/usr/bin/patch` call: the displaced asymmetric
`-F0` expected success is not GNU behavior, Apple zero-start output can mislead
GNU too, and implicit `-E` changes semantics. Apply neither the sed dialect
exception nor any blanket GNU/BSD exception to this new evidence. Root should
review exact policy fixtures and hashes after other testers close; no existing
suite or policy file was changed here. Keep unavailable or failing outcomes in
their denominator; a useful oracle is not proof of full compatibility.
