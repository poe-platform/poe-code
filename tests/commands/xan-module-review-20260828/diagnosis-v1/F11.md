The first failure asks for **2 work units with only 1 remaining**, not 15 units
remaining or a stdout quota exhaustion. No stdout sink write occurs. Diagnostic
construction begins but aborts during its first `textSize` part; no diagnostic
output reservation, final buffer, encoded part or stderr sink write is reached.
Its attempted full string is 34 bytes; **emitted diagnostic remains zero**.

For the existing diagnostic algorithm, absent an admission failure, work demand
is `34 size + 34 encode-size + 34 encode-write + 34 copy = 136`, versus **1**
remaining on catch entry (zero after the partial attempt). Existing lifetime
requires peak retained `34 live + 34 final + 22 longest-part = 90`; total output
reservation would be `2 + 34 = 36`. Counterfactual total work would be
`13 + 136 = 149`, **not a proposed cap change**. Increasing maxWork would also
change whether the original failure occurs, so this is not a rerunnable minimum.

No content cell-byte accounting, LF inspection, output text or stdout reservation

are static counter arithmetic, not measured JS allocation, and not an instruction
to release resources early, raise minima, or exempt diagnostics.
