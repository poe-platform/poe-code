## D1 — Choose sibling executor and fixed ERE entry

**Recommend:** new private ere-client/ere-worker/ere-protocol/ere-ledger siblings in the existing regex-execution subsystem. Leave legacy client.ts, worker.ts, protocol.ts, matching.ts and expr/** unchanged, including their byte/reply/error behavior. No widening Descriptor/Request/Reply/RegexErrorCode, RegexExecutionOptions or old request overloads. A separate internal session method cannot dispatch ERE through an old method accidentally.

Alternative: a shared mixed-operation legacy pool saves idle threads/duplicates fewer lifecycle lines, but changes Slot/Pending dispatch, cache separation, queue fairness, disposal, startup messages and every legacy Worker's load graph. It requires a materially broader expr/declaration/load regression window. It is not the smallest additive change.

**Lifetime:** one inert ERE root is registered with the fresh public-exec InvocationScope before activation and associated privately with that exact Budget. At first reached ERE job, open a registered child-session handle and lazily acquire at most one ERE Worker per root; retain/reuse the idle Worker only while that root owns it. Descendant jobs/invoke/pipelines/substitutions share root ledger and serial scheduler, not a cloned ledger or one Worker per conditional. Child close cancels/drains only its jobs; root close seals all admissions and awaits every acquired Worker/owned job/cleanup before public settlement. Independent public exec gets a new root. No root Budget fields or public options added. See accepted shell.ts165-186, runtime.ts957/1391/1985/2488, cleanup.ts, and regex client.ts28/78/264.

**Real costs:** an additional fixed asset graph and some independently reviewed lifecycle code; one ERE Worker per concurrent root can coexist with legacy command Workers (not a process-wide thread bound); serial ERE scheduling reduces per-root parallelism. More internal declarations/package files ship, despite no root/subpath exports. Source-labelled tests require exact compiled adjacent assets; installed and physical-move layouts need new full graph authentication. Existing legacy startup/request/idle/resource defaults may be adopted as explicit private defaults, not read from unrelated command plugin options or represented as an existing Shell regex setting.

New entry uses exact inert WorkerData {operation:"shell-ere",version:1}, explicit empty env and approved static bootstrap/execArgv. Legacy execArgv:[] does not inherit parent loader hooks (client.ts80); it is neither engine-load evidence nor an authority grant. New timers/promises, worker_threads and any validator util edge require importer-specific admission. No old Node/SafeJS/regex loader profile silently approves these assets or flags.

## D2 — Exact finite accounting; one genuine new policy adoption

Engine source defines seven counters. Keep all seven in the usage envelope, not only steps/allocation in the five-field result:

| Counter | Parent reconciliation across jobs |
| --- | --- |
| patternBytes,subjectBytes | Per-input high-water maxima; never subtract maxima as if cumulative spend. |
| work,states,allocationUnits,captureBytes,captureSlots | Cumulative actual usage plus outstanding non-overlapping reservations; never reset on new job/Worker/session/descendant. |

The source-defined limits are P=min(B,65536), S=min(B,1048576), W=min(50000000,32B), states=min(65536,8F), A=min(4000000,8B+128F), captureBytes=B and captureSlots=F. B/F remain existing maxExpansionBytes/maxExpansionFields only as private derivation inputs. Adopt these exact engine formulas only with ROOT's integration ratification; no fabricated ShellLimitError for exceeding them. Original bounds plus lower-only per-resource allowances go to worker-local EreLedger: do not derive new bounds from “remaining B/F,” which would shrink the wrong resources.

**Recommend a separately disclosed parent transport ledger:** cumulative transport storage units T=A and transport traversal units H=W, both shared across the invocation root, with live-owned-reference tracking as well. This avoids silently spending the pure engine's already-defined allowance on previously excluded input ownership. It is a NEW policy adoption, not something f97 already implements or ROOT's earlier engine-cap approval automatically covers. Alternative: charge transport to the same A/W pools; that is a tighter combined logical profile but can refuse cases that fit the pure engine's bounds. Do not switch between these alternatives silently. Separate pools do NOT promise one A-sized/byte/RSS/whole-process budget; engine units and parent units are separately disclosed logical measures.

**Exact proposed parent unit rule (no invented byte threshold):** U(record)=1 container+one unit per admitted own-data field+U of field values; U(array)=1 container+one per entry+U of entries; U(ASCII string)=its byte length; U(number/boolean/null)=0 beyond its containing cell. A retained byte buffer costs its byte length plus one container. Exact schema admits fixed key names only. Count every owned metadata/queue/session cell and every distinct admitted copy/retention boundary, not only payloads. Native Promise/VM frames/structured-clone internals are excluded, so no preallocation/RSS claim. Each complete parent validation/copy traversal charges its actually visited cells/ASCII bytes to H before further work; no shell command/loop/expansion counter is incremented for those bytes. An implementation must census its concrete owner metadata under this rule before claiming conformance.

For the existing proposed request with nine fields, n literal fragments, total ASCII pattern bytes p and subject bytes s, U(request)=47+4n+p+s. The47 is derived from the exact record/array/bounds/allowance cells and fixed operation/profile string lengths, not a guessed overhead size. Pre-admit2U(request) for the owned request and Worker delivery copy before those boundaries; already-performed admission work remains spent if later rejected. Native memory may differ. Fragment count needs no arbitrary new magic cap: the checked inequality2(47+4n+p+s)<=available T bounds even empty-fragment vectors before walking/copying; p<=P,s<=S independently. Reject unsafe arithmetic, not overflow/clamp-upward.

**Remove the earlier proposed512-byte free-form error-message field.** It had no ratified ERE basis. Use a finite semantic failure envelope: version/operation/id/grantId/kind/category/resource/offset/usage; no message/stack/cause. Syntax/unsupported offset is bounded nonnegative safe integer<=pattern allowance (or null when unavailable); profile-limit offset=null and finite resource. Parent formats a bounded fixed category/resource/limit diagnostic through existing budgeted sinks. This intentionally gives less engine detail, not GNU diagnostic-byte equivalence. No arbitrary host/worker exception is converted merely to fit this envelope.

With success envelope/result schema from INTERFACE.md, N=groupCount+1<=33 and M participating spans, U(reply)=38+N+3M<=170 and U(result)=7+N+3M<=139. Finite failure envelope is<=62 units (longest category/resource), so170 covers either reply kind. Pre-reserve2*170+139=479 additional transport units for Worker reply plus parent delivery plus owned result view; settle proven actual U, releasing only unused reserved credit, never spent units. These numbers derive from the fixed schema and source-declared32-group ceiling; they are logical units, not byte allocations. Future schema changes must recompute them. Parent capture strings/array staging remain separately pre-admitted by the existing array owner; engine-created values already consumed engine capture counters even though values are not sent on the wire. No double-charge or refund of those engine counters merely for serializing spans.

**Queue:** one active job per root; waiting jobs own only precharged bounded tickets/input snapshots, not copied full remaining engine budgets. Adopt existing private default maxQueuedRequests64 as a conservative ceiling additionally constrained by available T (no new public option); if ROOT declines that policy adoption, the queue cardinality must be bounded solely by the exact charged ticket cells. Do not claim64 is already a Shell builtin setting. Matcher grant is reserved at dispatch, after earlier validated refunds; outstanding credit is not mistaken for spent credit. Queued requests still must fit transport T and caller cancellation, and cannot wait with uncharged storage.

**Accounting sequence:** reserve before copies/acquisition/post; immediately enroll any returned Worker before fallible handler/timer/publication setup. On complete validated success OR known syntax/unsupported/profile-limit failure, snapshot all seven worker counters, verify <=grant and duplicated result values, commit once, and release only proven unused reserved components. On timeout/crash/malformed/missing reply or post-send abort, consume every unproved reserved cumulative component; no retry/refund from absent or late unvalidated telemetry. Pattern/subject maxima remain known input admissions. A validated reply already committed before a later caller failure is not charged twice. Release live-reference ownership only after actual retirement; consumption is never refunded by cleanup. A termination/cleanup rejection remains owned/unsettled, not clean. Actual caller/control/sink/cleanup reason precedence is preserved with explicit presence/origin, including undefined/falsy rejections. Real public expansion/output Budget failures remain ShellLimitError.

## D3 — Canonical full-cardinality nonmatch

**Recommend:** valid result always has groupCount+1 spans; matched=false uses all null, including group0. Match uses non-null group0, null nonparticipants and explicit {start:k,end:k} empties. This makes the wire's cardinality independent of match success and prevents “missing groups” from looking valid. It does NOT populate BASH_REMATCH on no-match: the runtime still stages the approved empty binding.

Alternative: no-match spans=[] mirrors the pure EreNoMatch type and saves at most33 null cells, but adds a second cardinality rule and offers less structural validation. The recommended adapter obtains groupCount from the actual same-ledger program.groups, canonicalizes the engine's empty no-match captures, and never transports/reconstructs its WeakMap-bound handle. Engine values are omitted from the wire; result.steps=usage.work and allocatedUnits=usage.allocationUnits. This is transport normalization, not a matcher change or proof of POSIX repeated-capture selection.

Reject all falsy non-object replies; proxies/accessors/extras/symbol keys/holes; wrong operation/version/IDs or replay; nonboolean flags; NaN/infinite/fractional/-0/negative counters; groupCount>32; wrong span count; matched/nonmatch contradictions; start>end or end>subject bytes; subgroup outside group0; duplicate counter mismatch; any over-grant usage; resource/offset/category inconsistency. Check complete usage and checked capture-byte/slot sums before parent copies/refunds/publication. Cross-realm finite own DATA is accepted without prototype identity tests. Structured-clone allocation precedes parent validation, so this is not containment of an arbitrary compromised Worker.
