# Independent five-stream public integration verification

Owned by the different integration verifier leaf, never the implementation
author. `frozen/` was committed as fd2926f before this leaf read product source
or author tests. The original eleven manually specified byte fixtures and
bounded controls remain unchanged there. `preexecution-refinement-1.md`
records a helper-only correction made before any product execution.

The executable harnesses require the exact root-owned marker
`/tmp/safe-bash-stream-five-public-review.ready`, actual CLOSED author2919 and
an exact source commit. They must themselves be committed before execution.

```
node tests/integration/stream-five-public/verify.mjs SOURCE_SHA /tmp/safe-bash-stream-five-public-verifier.UNIQUE-packed
node tests/integration/stream-five-public/verify-release.mjs SOURCE_SHA /tmp/safe-bash-stream-five-public-verifier.UNIQUE-release
```

The first archives immutable source, builds only that isolated archive, rejects
package lifecycle hooks, packs offline, copies/extracts the actual tarball into
a consumer outside repository and source snapshot, inventories dependencies and
JS/declaration closure, and executes strict typed and compiled consumers. Darwin
sandbox controls must actually reject source reads and TCP listen/connect;
resolver controls reject source, external package and unpacked worker fallback.
Inspected regex worker_threads imports are allowed, unlike the old-four guard.
F01-F11 execute with MemoryFS; F07/F10 additionally execute with an explicit
RealFileSystem root. C controls measure actual registry/factory65, live streams,
ownership/backpressure/cancellation, quotas, invocation/replacement and partial
publication. Negative type templates are `.ts.txt` so they cannot poison the
repository's ordinary typecheck; only the moved consumer compiles them.

The second archives the exact committed outer release command, authenticates
an isolated detached git database using copied objects, copies installed tooling
without downloads, and runs the unmodified `npm run verify:release:qualified`
with `--source-commit` and three copied native overlays. Missing and wrong pins
must propagate exit78 before product passes. Positive requires 318 canonical
tests/all22 native rows and the original82 stream inputs (164 executions,
124 strict, 40 retained stderr differences). The distinct absolute benchmark
stat and frozen stream references remain read-only. No host pin is modified.
Native qualification uses the canonical unsandboxed permission profile and
reference gid20: sandbox-exec itself strips setid bits during fixture setup.
The independent packed consumer retains its separately proven OS sandbox.
Both failed native attempts and the controls explaining this distinction remain
in `harness-corrections.md` and `evidence/`; none are relabeled as passes.

No new native corpus, source algorithm changes, remote-provider proof,
universal GNU parity, superiority, full-project gate or 72-hour claim is made.
Final measured results and open lifecycle limitations are in `REPORT.md` and
`evidence/final/`; these are scoped checks, not overall release readiness.
