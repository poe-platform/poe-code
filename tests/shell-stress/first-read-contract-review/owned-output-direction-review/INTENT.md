## Contract-required observations

1. Use actual authenticated temporary Shell dispatch, curl, and VFS for the
   workflows specified in each case. Injectable sources, sinks and transports
   instrument real calls; a simulated trace or API-shaped stub is not proof.
   Curl stays an explicit plugin with explicitly allowed loopback networking.
2. A real source read/request must enter exactly once before the independent
   downstream start barrier releases `head -n 0`. Count source `next`, HTTP
   request entry, and body reads separately. No zero-start or demand-before-start
   success. Output closure must be observed before first stdout write; do not
   call the intended operation close from the harness to fake that notification.
3. Borrowed cursor `return`, cancellation and destructive close counts stay
   zero throughout observation, including late read settlement. No ownership
   transfer is inferred from a pending read, iterator shape, or signal argument.
   Record exact bytes at each committed consumer and next owner's boundary.
   Every supplied byte is accounted for once, in order; a discarded late chunk,
   merely untouched stdin, duplicate bytes, or an empty remainder cannot prove
   positive owner/sibling continuation in D01/D02.
4. Only a truthful per-read cooperative lease may retract a pending read. It
   must not cancel the underlying borrowed cursor. Otherwise use the frozen
   opaque fallback: resolve/reject the admitted promise under harness control,
   sequence ownership handback, and retain its bytes or its real committed
   effect. Cancellation cannot revoke an already committed effect. Neither
   branch may claim prompt opaque cleanup or universal nonhanging host behavior.
   Branch selection is fixed from the declaration before implementation access,
   not chosen after a failing run. If both are offered, run both as one case.
5. Parent-owned operations form explicit parent-child edges. Parent termination
   closes descendant admission and drains registered cooperative children,
   including admitted cooperative acquisitions. Child closure cannot abort its
   parent or siblings. Unrelated file/stderr tasks belong outside the stdout
   subtree; writing stderr into that same closed sink is not independent work.
6. Reuse invocation `registerCleanup`, synchronously before acquisition or
   admission, including child resources. The finally path invokes the same
   idempotent cleanup; overlapping close/finally/dispose await shared completion
   and release each owned resource once. Do not build a second lifecycle to
   make a test pass. Registered cooperative work blocks relevant public
   settlement; opaque unregistered host work is not silently enrolled or drained.
7. Preserve reason/error identity and the existing public precedence: observed
   caller abort, otherwise selected execution rejection, otherwise sole cleanup
   rejection or aggregate of multiple cleanup errors, otherwise selected result.
   Internal EPIPE is not caller abort. No generic invented cancellation status;
   exact success/diagnostic/status assertions require declaration binding first.
   Preserve secondary late rejections without unhandled events.
8. Real loopback request/socket closure is observed before harness teardown when
   ownership requires cooperative cleanup. Distinguish candidate-caused closure
   from forced test cleanup. Necessary mixed request/body/header files and
   independent stderr complete exactly. No stage/global cancellation shortcut.
