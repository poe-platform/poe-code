# Frozen execution, admission, and countercontrols

These are **pre-code obligations, not executed results**. `cases.json` is the
literal expectation set and `worker.mjs` its later executable body. `synthetic.json`
freezes exact safety/state procedures; their binding-specific executor must be
versioned and sealed before its first candidate execution. Do not silently edit
these cases to fit the author. An independently demonstrated fixture mistake
requires an additive rationale/version preserving its original result.

## Layout and source/package admission

1. Build only a regular-file selected closure: baseline5137 source/build inputs,
   accepted ca1d WebDAV source and README, accepted464 runtime, then explicitly
   admitted LET runtime delta. `BINDINGS.json` records every selected blob. No
   moving HEAD, dirty overlays, stack work, full-history/AGENTS copies, private
   paths, source fallback, new dependencies, or other author commit contents.
   Provider blobs make composition honest, not a required arithmetic provider.
2. Candidate changes must be runtime.ts-only, adding LET builtin dispatch and
   its private adapter. Parse/evaluator/getopts/cancellation/cleanup/types/exports/
   package/plugin registries remain byte-identical. Exact root authorization
   must release the runtime window first. A changed accepted composition needs
   a separately approved binding; do not transplant an old entire runtime.
3. Freeze input/tool/runtime hashes before builds, capture emitted/runtime and
   declaration inventories, pack with scripts disabled, offline install into
   a fresh regular-file consumer, physically move it, and prove the abandoned
   location absent. Include exact baseline README in a full package claim.
   Compare all common source and package members/modes before/after. Do not
   promote an 845-file documentation-omitting projection to fullpack parity.
4. Run the same 58 literal rows and all 26 synthetic procedures against compiled
   source and moved actual package. Report expanded reason/parameter variants
   separately; 22 families/26 procedures are not counts of executed assertions.
   No third redundant installed behavioral replay is required. Binding/type
   checks do use the actual installed/moved package and no source declarations.
5. Independent authenticated import hook/load receipts must bind actual module
   URLs and hashes, especially runtime/arithmetic/cancellation, in addition to
   the worker's pre/post inventory. The worker alone is not the admission guard.
   Launch under qualified Node22.22.2 or separately admitted Node24, exact binary
   hash, sterile env, exact read fence and no source path access for moved mode.
6. Before behavioral launch, mutated runtime or arithmetic bytes, changed
   manifest digest, missing root module, mismatched source declarations, wrong
   package resolution and original-source import must be rejected by their
   designated guard. A syntax/loader/permission error is not a product mutant
   detection. Same guard admits the intact candidate. Capture each negative.
7. Positive `consumer.mts.fixture` strict NodeNext/ES2023/exact optional/noUnchecked
   compilation against actual package must pass. Negative-limit gives exactly
   one TS2322 at its assigned value; negative-api exactly TS2305 naming the absent
   createLetCommands export. Neutralize each bad declaration in an isolated copy
   to prove the corresponding diagnostic disappears. Missing imports/builds
   never count as valid negative types. These files are data until explicitly
   staged by the later dedicated consumer runner, not canonical standalone .mts.

Execute M0 plus M1–M6 where the candidate contains the specified mechanism;
if a source shape requires a different patch, preseal the exact semantic mutation
and activation predicate before running it. An inapplicable mutant is reported,
not silently treated as killed. All edits are isolated prototypes under owned
scratch; no live product changes. Each mutated module must be rebuilt and loaded
in a fresh child; no expected-result JSON mutation or helper-only substitute.
Source-diff review additionally forbids host eval, new Budget/reset policy,
prefix-restore exception, LET as a sh special builtin, or parser/helper rewrites.

## Boundedness, mutation, and outcome discipline

- Per-child ceiling: 30s wall supervision, 256KiB combined receipt output, no
  more than one child at a time, exact owned PID/group cleanup. A supervision
  failure is a harness/control failure, never a passed LET case. Separate
  build/pack ceilings can be 60s; no large/native/pathological workloads.
- Literal worker limits are explicit; per-row overrides are frozen. Synthetic
  counts are bounded (130 argv,65 recursion names,12 variable-doubling levels,
 64 parenthesis pairs). No maximum-byte BigInt/stack bombs, RSS guarantee,
 hard CPU preemption claim or native async-cancellation analogy.
- Record outcome/failure receipts before assertions terminate a child; await
  dispose and all registered owned cleanup. Never wait on arbitrary opaque
  host promises or assume borrowed stdin cannot be acquired by Shell itself.
- Argument snapshot means existing Shell expansion occurs before LET starts
  (P18), literal invoke is not reparsed, and the implementation does not mutate
  input arrays. Trusted caller arrays remain immutable until settlement. This
  does not invent a sandbox/TOCTOU guarantee for hostile getters or concurrent
  mutation of readonly host arguments.
- Abort instrumentation is limited to isolated children with delegated scheduler
  and state/store observers, restored in finally. It must observe the real
  admission/evaluation checkpoint and retain partial non-prefix writes. Native
  evidence says nothing about these synthetic controls.
- No source/native execution in this freeze. Existing 28 native observations,
  original supervisor syntax failure, and future implementation outcomes remain
  distinct; neither a source scan nor guard check is a LET product pass.
