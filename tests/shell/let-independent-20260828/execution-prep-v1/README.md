## Failure accounting

Each body is supervised to close/reap before ordinary failures are aggregated
and the next case starts. Receipt count, unique IDs, summary totals, settled/
disposed state, terminal code, output ceiling, process group, module loads and
mutant activation are checked independently. **All-PASS stdout with late exit1
or exit7 is rejected.** Missing rows, duplicate rows, malformed summaries,
bootstrap failures, deadlines and surviving children are not compatibility passes
or killed mutants. Build/admission prerequisites can stop execution with explicit
failure and unexecuted bodies; they cannot produce an overall green result.

The S25 raw-child/outer-cleanup distinction follows unchanged
`InvocationScope.close`: it appends callback failures to the shared failure list
instead of throwing them from close. A raw successful child can therefore return0
while root settlement rejects the exact cleanup marker. The executor asserts
both observations rather than assuming every cleanup callback rejects raw invoke.
No frozen procedure or existing cleanup policy was changed. S02 additionally
uses a frozen forwarded argument array to realize the existing no-input-mutation
predicate; it does not promise safety against concurrent hostile host mutation.
